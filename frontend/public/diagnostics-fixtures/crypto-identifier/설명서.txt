crypto_identifier / crypto_identifier.py 사용 설명서
================================================

역할
----
정체불명의(암호화/인코딩된 듯한) 문자열을 넣으면:
1. base64/base64url/hex/base32/base58/ascii85/base85/URL인코딩/HTML엔티티
   (&lt; 등)/유니코드·JS 이스케이프(\uXXXX, \xXX)/ROT13/ROT47 조합을 최대
   3단계까지 자동으로 풀어보고, 사람이 읽을 수 있는 결과가 나오면 전부
   보여줌. base64/base64url/hex/base32 디코드 결과가 printable 텍스트가
   아니어도 gzip/zlib 압축 데이터로 보이면 압축까지 풀어서 재시도함(쿠키·
   세션값이 base64(gzip(...)) 형태로 오는 경우가 흔해서). 추가로 hex로
   보이는 값은 단일 바이트 XOR로 가려졌을 가능성도 전수 브루트포스
   (0x01~0xFF)해서 영어 평문과 가장 비슷한 상위 5개를 보여줌(printable
   조건만으로는 짧은 문자열에서 틀린 키도 다수 통과하길래, 영어 글자
   빈도 기반 점수로 정렬 -- 100% 자동판별은 아니고 참고용).
   "." 2개로 나뉜 3-segment base64url 값은 JWT로 보고 header/payload를
   그 자리에서 JSON으로 바로 보여줌(서명 검증은 안 함, 구조 파싱만).
2. 길이/문자셋/접두사로 해시·crypt 포맷을 추정 (md5/sha1/sha256/sha512,
   NTLM, MySQL 4.1+ PASSWORD(), bcrypt, md5crypt, sha256crypt,
   sha512crypt, phpass, Django PBKDF2, LDAP SSHA 등 — hashid 도구와
   같은 방식의 휴리스틱).
3. 빠른 무솔트 해시(md5/sha1/sha224/sha256/sha384/sha512) + NTLM(순수
   파이썬 MD4 구현 내장, OpenSSL에 md4 없어도 동작) + MySQL 4.1+
   PASSWORD()(SHA1(SHA1(pass)) 이중해시 전용 처리)는 파이썬으로 직접
   워드리스트 대입 크래킹 수행.
4. bcrypt/crypt류처럼 느리거나 GPU가 유리한 포맷은 hashcat/john 실행
   명령어를 만들어서 "출력만" 함 — 오래 걸릴 수 있어 자동 실행은 안 함.
   실행 파일 위치: E:\temp\tools\hashcat\hashcat-7.1.2\hashcat.exe
                  E:\temp\tools\john\john-1.9.0-jumbo-1-win64\run\john.exe

참고: 진짜 "레인보우테이블"(사전연산 해시→평문 매핑 파일)은 다운로드된 게
없음. 대신 hashcat/john + SecLists 워드리스트로 하는 사전대입 공격이
현실적인 대체 수단 (무솔트 빠른 해시엔 오히려 더 실용적).

기본 사용법
----------
python crypto_identifier.py "aGVsbG8gd29ybGQ="
python crypto_identifier.py "5d41402abc4b2a76b9719d911017c592" --crack
python crypto_identifier.py '$2b$12$...'
python crypto_identifier.py --file value.txt

대화형 모드
----------
인자 없이 실행하면(더블클릭 포함) 번호 입력식 메뉴가 뜸 — 필수 값 입력
후 옵션 번호를 골라 값 설정/토글, 0=실행. 목록은 아래 옵션 설명과 항상
동일하게 자동 생성됨. 터미널 특성상 마우스 클릭은 지원 안 됨.

옵션 설명
--------
value (위치인자, --file과 택1)
    분석할 문자열.

--file 경로
    값을 인자 대신 파일에서 읽음.

--crack
    해시로 추정된 값 중 "로컬에서 크랙 가능한" 무솔트 빠른 해시
    (md5/sha1/sha224/sha256/sha384/sha512)에 대해 워드리스트 대입을 실행.
    bcrypt 등 느린 포맷은 이 옵션과 무관하게 항상 hashcat/john 명령만 출력.

--wordlist 경로 또는 짧은이름 (기본: SecLists 10k-most-common.txt)
    대입 크래킹용 단어 목록. 짧은 이름은
    E:\temp\tools\SecLists-master\Passwords\ 아래에서 자동 탐색.

--limit N (기본 500,000)
    --crack 시 시도할 최대 단어 수.

-v, --verbose
    상세 로그.

출력 항목
--------
- [JWT 감지됨]: 값이 JWT 구조(헤더.페이로드.서명)면 header/payload를
  JSON으로 바로 표시(서명 미검증). alg=none이면 경고 표시.
- [Decode chains]: 성공한 디코딩 경로들 (예: base64 -> rot13, 또는
  base64+decompress, xor(key=0x5a) 등)
- [Hash format guesses]: 추정 포맷과 confidence(likely/possible),
  대응하는 hashcat -m 번호 / john --format
- [Local crack: ...]: --crack 사용 시 빠른 해시 결과
- [포맷명: GPU/전용 크래커 권장]: 느린 포맷일 때 복사해서 쓸 수 있는
  실제 hashcat/john 명령어 (해시가 파일 기반인 john은 직접 해시를
  텍스트 파일로 저장 후 경로를 바꿔줘야 함)

주의
----
- MD5와 NTLM은 길이/문자셋이 동일해서 구분 불가 — 두 후보 모두 표시하고
  --crack 시 둘 다 실제로 시도함(예전엔 후보만 두 개 보여주고 크랙은
  MD5로만 돌려서 진짜 NTLM 값은 사전에 답이 있어도 못 찾던 버그가 있었음,
  수정됨). 마찬가지로 '*' + 40자리 hex는 MySQL 구버전 PASSWORD()(이중
  SHA1) 전용으로도 같이 시도함 — 일반 SHA1로만 돌리면 절대 못 찾는 값이라
  별도 처리.
- 해시 포맷 추정은 휴리스틱이라 100% 정확하지 않음(특히 possible 등급).
- 크래킹 대상 해시가 정당하게 접근 권한이 있는 것인지 확인 후 사용.
