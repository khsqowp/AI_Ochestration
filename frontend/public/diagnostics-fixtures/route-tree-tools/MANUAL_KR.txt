경로 트리 분석기 사용설명서
===========================

둘 다 완전 독립 HTML 파일 하나(외부 요청·서버 전송 없음, 전부 브라우저
안에서만 분석) -- 진단 탭 모달에서 바로 쓰거나, 이 파일만 저장해서 폐쇄망
PC에서 그대로 열어도 동일하게 동작한다.

har-endpoint-tree.html (화면·API 관계 트리와 요청 경로 트리)
-------------------------------------------------------------
브라우저 DevTools Network 탭에서 "Preserve log"를 켜고 대상 화면들을
직접 이동·조작한 뒤 내보낸 .har 파일을 넣는다. 파일은 브라우저 안에서만
분석되며 서버로 전송되지 않는다.

"화면·API 관계" 보기:
- HAR 문서 요청과 페이지 참조 정보를 화면 노드로 표시한다.
- 화면 간 Referer가 기록된 경우 상위 화면 아래에 연결한다.
- 페이지 참조 또는 Referer로 확인되는 API 요청을 화면 아래에 붙인다.
- HAR 페이지 참조, Referer 추정, 화면 연결 미확인을 구분한다.
- 연결 근거가 없는 요청은 별도 그룹에 두며 임의로 특정 화면에 붙이지 않는다.
- 화면/API 노드에서 우클릭(또는 키보드 메뉴 키)하면 주소를 복사한다.
- 마우스를 올리면 연결 근거, HTTP 상태, 응답 유형, 파라미터, 호출 횟수를 확인한다.

"요청 경로 트리" 보기:
- 실제 관측된 요청(메서드/경로/파라미터)과 JS 번들에서 추출한 후보 경로를
  도메인·경로 계층으로 표시한다. 후보는 실제 호출과 구분된다.
- 제외 키워드(| 로 구분)를 입력하면 해당 문자열이 포함된 결과를 숨긴다. 추적/광고 도메인(예: youtube, google, kakao) 제거에 쓸 수 있다.

주의:
- HAR에 기록되지 않은 화면 전환은 복원할 수 없다. SPA 내부의 경로 변경도
  HAR 형식/브라우저 내보내기 방식에 따라 누락될 수 있다.
- Referer에 근거한 화면 연결은 추정이다. HAR 페이지 참조가 있어도 화면의
  의미적 상·하위 관계를 완전히 증명하지는 않는다.
- API 판별은 HAR의 리소스 유형, URL, 응답 유형, HTTP 메서드에 의존하므로
  일부 요청은 API가 아니거나 API인데 누락될 수 있다.
- HAR에는 쿠키, 토큰, 개인정보가 포함될 수 있다. 공유 전에 민감값을 제거한다.

js-route-tree.html (JS URL·API 경로 트리)
-------------------------------------------
JS 파일을 업로드하거나 코드를 붙여넣으면 그 안의 URL/라우트/API 경로 문자열을
추출해 트리로 보여준다. fetch/axios 호출, 문자열 리터럴 경로 패턴을 찾는다.
제외 키워드(| 로 구분)를 입력하면 해당 문자열이 포함된 결과를 숨긴다. 추적/광고 도메인(예: youtube, google, kakao) 제거에 쓸 수 있다.

common-path-checklist.html (공통 경로 체크리스트 · Intruder 페이로드 생성기)
-------------------------------------------------------------------------
Git, 기타 VCS, 앱/일반, CI/CD, Spring Boot, CMS, .well-known 등 21개
카테고리(태그) 하나당 체크박스가 하나씩 있다. 체크하면 해당 카테고리에 속한
모든 경로가 한 번에 선택 목록에 추가되고, 해제하면 모두 빠진다. 각 카드의
"경로 목록 보기"에서 실제 경로를 읽기 전용으로 확인할 수 있다. 상단 "전체 해제"는
모든 카테고리 선택을 해제한다. 선택된 경로는 카테고리와 각 경로의 나열 순서대로
하단 미리보기에 모인다. "Intruder용으로 복사" 버튼으로 클립보드에 복사해
Burp Intruder의 Simple list 페이로드나 ffuf/wfuzz 워드리스트로 붙여넣을 수 있다.

주의:
- 이 체크리스트는 실제 스캔 결과가 아니라 여러 프레임워크/서버에서 흔히
  노출되는 경로 모음일 뿐이다. 각 경로가 대상 서버에 실제로 존재하는지,
  존재한다면 접근 가능하거나 취약한지는 이 도구가 전혀 보장하지 않는다.
- 선택한 경로로 실제 요청을 보내는 기능은 없다. 생성된 목록을 가지고 승인된
  범위 내에서 별도의 스캐너/Intruder로 직접 확인해야 한다.
