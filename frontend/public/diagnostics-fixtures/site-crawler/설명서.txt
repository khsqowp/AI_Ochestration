site_depth_crawler / crawler.py 사용 설명서
================================================

역할
----
URL + 깊이(depth)를 입력하면 그 깊이까지 링크를 따라가며 페이지를 수집.
서버에 무리가 가지 않도록 동시 요청 수 제한 + 호스트별 최소 요청 간격을
항상 강제함 (끌 수 없음). 추가로 SecLists 경로 목록을 이용한 디렉터리/
파일 존재 여부 탐색(wordlist probing)도 지원.

기본 사용법
----------
python crawler.py https://example.com --depth 2
python crawler.py https://example.com --wordlist common.txt

대화형(간단) 모드
----------------
인자 없이 실행하면(더블클릭 포함) 한글 질문이 순서대로 뜸 — URL, 쿠키/
헤더(선택), 경로/디렉터리 존재 탐색(워드리스트) 켤지, 깊이, 외부 도메인
허용 여부, 요청 간격/동시요청 수만 물어봄. 경로는 링크를 따라가며 자동
수집되니 따로 안 물어봄. 마지막에 "고급 옵션을 더 조정할까요?"에 y로
답하면 아래 옵션 전체를 번호로 설정/토글하는 메뉴로 이어감(0=실행,
q=취소). 터미널 특성상 마우스 클릭은 지원 안 됨.

--wordlist 선택 UI
-----------------
--wordlist도 더 이상 짧은이름을 맨입으로 타이핑하지 않는다. 번호 메뉴에서
번들 포함 목록(common.txt/raft-large-directories.txt/raft-large-files.txt/
raft-medium-directories.txt/raft-medium-files.txt)이 체크박스로 나오고,
번호나 이름을 ","로 구분해 입력하면 그만큼 선택된다(빈 줄=유지, all=전체,
q=선택 해제). 이어서 번들에 없는 경로(예: burp_history_to_wordlist.py가
만든 paths-wordlist.txt)를 추가로 직접 입력할 수도 있다.

옵션 설명
--------
url (필수, 위치인자)
    시작 URL. http:// 또는 https:// 스킴 필수.

--depth N (기본 1)
    시작 URL로부터 몇 단계까지 링크를 따라갈지. 0이면 시작 페이지만.
    안전상한 10 (초과 시 --force 필요).

--workers N (기본 3, 최대 10)
    동시에 보낼 요청 수. 10 초과 입력해도 자동으로 10으로 캡됨.

--min-interval 초 (기본 0.5)
    같은 호스트에 대한 요청 사이 최소 간격(초). 스레드가 여러 개여도
    이 간격은 항상 지켜짐 (서버 보호의 핵심 장치).

--timeout 초 (기본 10)
    요청 1건당 타임아웃.

--retries N (기본 1)
    타임아웃/네트워크 오류 시 재시도 횟수. HTTP 4xx/5xx 응답은
    재시도 대상이 아님(정상적인 결과로 취급).

--max-pages N (기본 200)
    깊이와 무관하게 전체 요청 수 하드 캡. 폭발적으로 링크가 늘어나는
    사이트에서 안전장치 역할.

--allow-external
    기본은 같은 호스트만 크롤링. 이 옵션을 주면 다른 도메인 링크도 따라감.

--ignore-robots
    robots.txt 규칙 무시. 기본은 robots.txt를 항상 준수함.

--user-agent 문자열
    요청 시 보낼 User-Agent 커스터마이즈.

--cookies "k=v; k2=v2"
    이번 실행 전체(크롤링, --wordlist, --spa-assist, --extra-urls)에
    실어 보낼 Cookie 헤더 (로그인 후에만 보이는 페이지 크롤링용).

--headers "Name: value" (반복 가능)
    이번 실행 전체에 추가할 헤더.

--wordlist 경로 또는 짧은이름 (반복 가능)
    디렉터리/파일 탐색용 경로 목록 파일. 절대/상대 경로를 직접 줘도 되고,
    "common.txt", "raft-large-directories" 처럼 짧은 이름만 주면
    SecLists-master\Discovery\Web-Content\ 안에서 자동으로 찾음. 오프라인
    올인원 패키지엔 common.txt(가벼움) 외에 raft-large/medium-directories,
    raft-large/medium-files(더 깊고 넓음)까지 포함돼있음 -- 상황에 맞게
    골라 쓰거나 여러 개 합쳐 쓰면 됨.
    Burp Suite 히스토리에서 직접 워드리스트를 뽑고 싶으면 같이 제공되는
    burp_history_to_wordlist.py로 export(XML/텍스트)를 변환한 뒤 그
    결과 파일(paths-wordlist.txt)을 여기 경로로 넘기면 됨.
    --wordlist를 여러 번 줘서 여러 목록을 한 번에 합쳐서 쓸 수 있음(합친
    뒤 중복 제거하고 --wordlist-limit 한 번만 적용). 예:
      --wordlist common.txt --wordlist raft-large-directories.txt
    지정 시 기존 크롤링에 "추가로" 루트 경로에 대해 목록의 각 경로를
    probing 함 (404 아닌 결과만 콘솔에 강조 출력).

--wordlist-limit N (기본 200, 안전상한 2000)
    wordlist에서 실제로 시도할 최대 경로 수. SecLists 목록은
    수천~수만 줄이라 무제한 사용 시 서버 부담이 커서 반드시 캡을 둠.
    2000 초과는 --force 필요.

--output console|json (기본 console)
    출력 형식.

--output-file 경로
    JSON 리포트를 파일로 저장 (console 모드에서도 추가로 저장 가능).

--force
    --depth 10 초과, --wordlist-limit 2000 초과 등 안전상한을 넘길 때 필요.

-v, --verbose
    상세 로그 출력.

리포트의 "수집 실패·건너뜀" 섹션
------------------------------
크롤링/워드리스트 탐색이 끝나면 콘솔·JSON 리포트 마지막에 실패·차단·
범위밖 스킵 내역이 별도로 정리돼서 나온다:
  - robots.txt 차단 건수 + URL 목록
  - 타임아웃/네트워크 오류로 재시도 소진된 건수 + URL 목록(오류 내용 포함)
  - 다른 도메인이라 건너뛴 링크 수(--allow-external로 포함 가능)
"경로를 다 모았는데 뭐가 빠졌는지 모르겠다"를 막기 위한 섹션 -- 예전엔
이 정보가 로그에만 스치듯 지나가고 최종 리포트엔 안 남았음.

주의
----
- 서버 부담 방지 장치(동시 요청 캡 + 호스트별 최소 간격)는 옵션으로도
  끌 수 없음. --min-interval 0으로 줘도 코드 자체에서 순차 대기 로직은
  유지됨.
- 실전에서 --wordlist 사용 시 반드시 스캔 대상에 대한 권한이 있는지
  확인할 것 (무단 디렉터리 스캐닝은 문제가 될 수 있음).
