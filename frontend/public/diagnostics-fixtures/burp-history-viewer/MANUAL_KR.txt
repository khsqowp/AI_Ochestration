Burp History 뷰어 (오프라인 버전) 사용 설명서
==========================================

burp-history-viewer.html 파일 하나로 동작한다. 인터넷이 없는 PC에서도 이
파일을 더블클릭(또는 브라우저로 열기)하면 그대로 동작한다. 서버로 아무것도
전송하지 않는다 -- XML은 그 브라우저 탭 안에서만 파싱한다.

역할
----
Burp Suite HTTP history의 요청 목록, 요청·응답 원문, 중복 제거한 URL 경로를
확인한다. 별도 프로그램이나 외부 라이브러리를 설치할 필요가 없다.

사용법
------
1. Burp Suite의 Proxy > HTTP history 탭에서 원하는 항목들을 선택하고
   우클릭 > Save items 로 XML로 저장한다.
2. "파일 불러오기"로 XML을 선택하거나 파일을 업로드 영역에 끌어 놓는다.
3. 총 요청 수, 상태코드별 분포, 고유 경로 수와 HTTP History 테이블을 확인한다.
   URL 검색은 문자열 포함 검색이며 상태 필터와 함께 적용된다. 테이블은
   200개씩 표시한다. "이전"과 "다음"으로 페이지를 이동한다.
4. 행을 클릭하거나 번호 버튼을 누르면 Request와 Response 원문이 나온다.
   Raw는 원문이며 Pretty는 헤더를 유지하고 JSON/XML 바디만 포맷한다.
5. 경로 목록의 "클립보드 복사" 또는 "txt로 다운로드"를 누른다.
   다운로드 파일명은 paths-wordlist.txt이며 한 줄에 경로 하나가 들어간다.

경로 목록
---------
전체 히스토리에서 path 필드를 우선 사용하고 없으면 url에서 경로를 가져온다.
쿼리스트링과 프래그먼트, 맨 앞의 모든 슬래시를 제거한 뒤 중복을 제거하고
정렬한다. 빈 경로와 루트 경로는 제외한다. 테이블 필터는 목록에 영향을 주지
않는다. burp_history_to_wordlist.py의 경로 정규화 형식을 따른다.

주의
----
요청·응답은 선택한 행에서만 디코딩한다. 응답이 없는 항목은 "응답 없음"으로
표시한다. base64 데이터를 UTF-8로 엄격히 검사하며 유효하지 않으면
"바이너리 데이터(N바이트, 표시 안 함)"으로 표시한다. 바이너리 HTTP 메시지는
헤더까지 포함한 해당 메시지 전체를 표시하지 않는다. 손상된 base64는
디코딩 실패로 표시한다. 평문 필드는 XML 파서가 반환한 텍스트를 사용한다.

XSS 페이로드를 포함한 원문도 텍스트로만 표시하며 HTML로 실행하지 않는다.
Pretty는 들여쓰기 확인용이다. JSON/XML 포맷은 공백이나 표현을 바꿀 수 있으므로
정확한 원문 확인에는 Raw를 사용한다. 압축·chunked 바디를 별도로 해제하지 않는다.

XML 전체는 브라우저 메모리에 읽힌다. 페이지 표시는 수천 건의 행 렌더링 부담을
줄이지만 매우 큰 파일은 읽기·XML 파싱에 시간이 걸릴 수 있다. 클립보드는
브라우저의 로컬 파일 또는 iframe 권한에 따라 실패할 수 있다. 실패하면
안내 메시지를 확인하고 txt 다운로드를 사용한다. 새 파일을 열면 기존 목록을
교체하며 새로고침하거나 탭을 닫으면 불러온 기록을 유지하지 않는다.
