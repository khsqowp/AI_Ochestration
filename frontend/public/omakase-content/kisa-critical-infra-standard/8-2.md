# 8-2. 웹 애플리케이션 부가 점검과 가상화 전환부

### 핵심 개념 및 기법

#### 불필요한 HTTP 메소드 악용
- **개요**: PUT, DELETE, TRACE 등의 불필요한 HTTP 메소드의 악용 여부를 점검하여 서버의 무단 접근 및 악의적인 행위(임의 파일 생성, 데이터 삭제 등)를 방지.
- **점검 목적**: 보안 위협으로서 해당 메소드들이 악용될 경우, 조작된 Server Side Script 파일 업로드, 민감 데이터 삭제, 서버 정보 노출 등이 가능하다.

#### TRACE 메소드
- **참고**: XST(Cross-Site Tracing) 공격 기법을 통해 httpOnly 등으로 보호된 세션 및 쿠키를 탈취할 수 있다.

### 취약점

- **불필요한 HTTP 메소드 활성화**: 웹 애플리케이션이 불필요한 메소드로 변조된 요청 패킷 전송 시 해당 메소드를 통해 임의의 행위로부터 악용이 제한되지 않는 경우 취약하다.
- **TRACE 메소드 활성화**: 기본적으로 TRACE 메소드가 활성화되어 있어, XST 공격에 노출될 수 있다.

### 절차

#### 점검 방법
1. **PUT 메소드 사용 시도**: 악성 파일(Server Side Script, 악성 스크립트 등) 생성 시도.
2. **웹쉘(Webshell) 업로드 및 크로스사이트 스크립팅 공격 수행 가능 확인**.
3. **DELETE 메소드 사용 시도**: 서버에 저장된 임의의 데이터 삭제 가능 확인.

#### 조치 방법
- **WebDAV 비활성화**: WebDAV 기능을 비활성화하여 PUT, DELETE 메소드를 제한한다.
- **RESTful API 애플리케이션 상의 PUT, DELETE 메소드 처리**: 기본적으로 취약하게 설계된 메소드가 아니며, POST 메소드를 통해 구현하는 것과 동일하게 핵심 비즈니스 로직에 대한 시큐어 코딩을 구현한다.
- **불필요한 메소드 비활성화**: 잠재적인 취약점의 최소화를 위해 불필요하게 활성화된 메소드는 비활성화한다.

### 수치

- **Session Timeout 설정**: 웹 콘솔 및 사용자 Shell Session Timeout 설정이 600초(10분) 이하로 설정되어 있는 경우가 양호하다.
- **TMOUT 값 예시**:
  - VMware ESXi, vCenter: `UserVars.HostClientSessionTimeout` 설정 확인
  - XenServer, KVM: `$TMOUT` 명령어를 이용하여 사용자 Shell Session Timeout 설정 확인 및 수정
  - Nutanix: Controller VM에 접속하여 User Shell Session Timeout 설정 확인 및 수정

### 소프트웨어별 설정 예시

#### Apache
- **dav 및 dav_fs 모듈 비활성화**:
  ```bash
  sudo a2dismod dav
  sudo a2dismod dav_fs
  ```
- **WebDAV 서비스 비활성화**:
  ```apache
  <Directory "/var/www/html">
  Dav On #On으로 활성화 되어있을 경우 Off 또는 지시어 삭제로 비활성 조치
  Options Indexes FollowSymLinks
  AllowOverride None
  Require all granted
  <LimitExcept GET POST PUT DELETE OPTIONS>
  Order Allow,Deny
  Deny from all
  </LimitExcept>
  </Directory>
  ```
- **TRACE 메소드 비활성화**:
  ```apache
  TraceEnable Off # 파일 내용 하단에 추가
  ```

#### Tomcat
- **WebDAV 서비스 비활성화**:
  ```xml
  <servlet>
  <servlet-name>webdav</servlet-name>
  <servlet-class>org.apache.catalina.servlets.WebdavServlet</servlet-class>
  <init-param>
  <param-name>debug</param-name>
  <param-value>1</param-value>
  </init-param>
  <init-param>
  <param-name>listings</param-name>
  <param-value>false</param-value>
  </init-param>
  <init-param>
  <param-name>readonly</param-name>
  <param-value>true</param-value> // true로 설정하여 쓰기 권한 제거
  </init-param>
  <load-on-startup>1</load-on-startup>
  </servlet>
  ```
- **TRACE 메소드 비활성화**:
  ```xml
  <Connector port="8080" protocol="HTTP/1.1"
  connectionTimeout="20000"
  redirectPort="8443"
  maxParameterCount="1000"
  allowTrace="true" // 설정 값 제거
  />
  ```

#### Nginx
- **WebDAV 서비스 비활성화**:
  ```nginx
  location /dav/ {
  ...
  dav_methods PUT DELETE MKCOL COPY MOVE; #dav_methods 지시어 부분 삭제
  ...
  }
  ```
- **TRACE 메소드 처리**: 기본적으로 TRACE 메소드를 항상 405 응답 코드로 거부하도록 패치되어 있다.

#### IIS 5.0 이하
- **WebDAV 기능 비활성화**:
  ```plaintext
  HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W3SVC\Parameters → 편집 → 값 추가 → 값 이름: DisableWebDAV, 데이터형식: REG_DWORD, 데이터: 1 → IIS 재시작
  ```

#### IIS 6.0 이상
- **TRACE 메소드 비활성화**:
  - 요청 필터링 → HTTP 동사 → 동사 거부 메뉴에 TRACE 메소드 추가.

### 참고

- **XST(Cross-Site Tracing)**: TRACE 메소드를 악용하여 httpOnly 등으로 보호된 세션 및 쿠키를 탈취할 수 있는 공격 기법.
- **WebDAV**: PUT, DELETE 등의 메소드를 통해 임의적인 파일 생성 삭제가 가능하다.

이 청크는 웹 애플리케이션 보안에서 불필요한 HTTP 메소드의 악용을 점검하고 조치하는 방법에 대해 자세히 설명하고 있다. 특히, Apache, Tomcat, Nginx, IIS 등의 설정 파일을 통해 메소드 사용을 제한하거나 비활성화하여 보안 위협을 최소화할 수 있는 방법이 다루어져 있다.

### 계정 관리 정책 설정

#### 비밀번호 복잡성 및 길이
- **비밀번호 복잡성**: 영문 대소문자, 숫자, 특수 문자 조합 사용.
- **비밀번호 길이**: 최소 8자 이상.

#### 변경 주기
- **비밀번호 변경 주기**: 최소 6개월 단위로 변경 권장.

### 점검 내용 및 목적

#### 점검 내용
- 비밀번호 복잡성 및 길이 확인.
- 비밀번호 변경 주기 확인.
- 허용된 IP에서만 관리 콘솔 및 원격 접속 가능 여부 확인.
- 루트 계정으로 가상화 장비가 관리되는지 확인.
- 불필요한 공용 계정 및 퇴사자 계정 존재 여부 확인.
- 사용자 계정별 적절한 권한이 부여된 여부 확인.

#### 점검 목적
- 비인가자의 무단 접근 시도를 예방.
- 시스템 침해 사고의 위험을 줄이고, 관리자 계정이 아닌 일반 계정이 공격자에게 탈취되었을 때 가상화 시스템을 장악하지 못하도록 함.

### 보안 위협

#### 보안 위협
- 무차별 대입 공격 (Brute-force Attack): 특정한 암호를 풀기 위해 가능한 모든 값을 대입하는 것.
- 비인가자의 무단 접근에 노출되어 가상화 장비 침해사고의 위험이 존재함.

### 참고

#### 참고
- **TCP Wrapper**: 호스트 기반의 네트워킹 ACL(Access Control List) 시스템.
- **IPTables**: 리눅스 커널 방화벽이 제공하는 테이블들과 그것을 저장하는 체인, 규칙들을 구성할 수 있게 해주는 서비스.
- **FirewallD**: Linux 운영체제를 위한 방화벽 관리 도구.

### 점검 대상 및 판단 기준

#### 대상
- VMware ESXi, vCenter, XenServer, KVM, Nutanix

#### 양호 조건
- 허용된 IP에서만 관리 콘솔 및 원격 접속이 가능하도록 제한된 경우.
- 별도의 관리자 계정을 생성하여 가상화 장비가 관리된 경우.
- 불필요한 공용 계정 및 퇴사자 계정이 존재하지 않은 경우.
- 계정별 불필요한 권한이 부여되지 않은 경우.

#### 취약 조건
- 허용된 IP에서만 관리 콘솔 및 원격 접속이 가능하도록 제한되지 않은 경우.
- 루트 계정으로 가상화 장비가 관리된 경우.
- 불필요한 공용 계정 및 퇴사자 계정이 존재하는 경우.
- 계정별 불필요한 권한이 부여된 경우.

### 조치 방법

#### 최소 사용 기간
- **최소 사용 기간**: 6개월 이상.

#### 최대 사용 기간
- **최대 사용 기간**: 정의되지 않음.

#### 최근 비밀번호 기억
- **최근 비밀번호 기억**: 정의되지 않음.

### 영향

#### 조치 시 영향
- 일반적인 경우 영향 없음.
- 애플리케이션에서 사용하는 계정의 경우 삭제 시 서비스 가용성에 영향을 줄 수 있음.

### 점검 및 조치 사례

#### SOLARIS
- **/etc/default/passwd 파일 내에 비밀번호 설정값 수정**

#### 권고값 기능 설명
- **HISTORY=**: 최근 사용한 패스워드의 갯수.
- **MINDIFF=**: 이전 패스워드와 다른 최소 문자 수.
- **MINALPHA=**: 패스워드에 필요한 최소 알파벳 문자 수.
- **MINNONALPHA=**: 패스워드에 필요한 최소 비알파벳 문자 수.
- **MINUPPER=**: 패스워드에 필요한 최소 대문자 문자 수.
- **MINLOWER=**: 패스워드에 필요한 최소 소문자 문자 수.
- **MAXREPEATS=**: 패스워드에서 허용되는 연속 문자의 최대 수.
- **MINSPECIAL=**: 패스워드에 필요한 최소 특수 문자 수.
- **MINDIGIT=**: 패스워드에 필요한 최소 숫자 문자 수.
- **NAMECHECK=**: 사용자 이름과 비밀번호가 같은지 확인.
- **MAXDAYS=**: 패스워드의 최대 유효 기간 (일).
- **MINDAYS=**: 패스워드 변경 가능 전의 최소 일수.
- **MAXWEEKS=**: 패스워드의 최대 유효 기간 (주).
- **MINWEEKS=**: 패스워드 변경 가능 전의 최소 주수.
- **WARNWEEKS=**: 패스워드 만료 경고 주수.
- **PASSLENGTH=**: 허용되는 비밀번호 길이.
- **WHITESPACE=**: 공백 문자 사용 여부.

### 계정 관리 정책 설정

#### 개요
로그인 계정의 비밀번호 관리 정책 설정 여부를 점검하고, 이를 통해 계정 탈취 위험을 방지합니다.

#### 점검 내용 및 목적
- **점검 내용**: 로그인 계정에 대한 비밀번호 관리 정책 설정 여부.
- **점검 목적**: 계정 탈취를 방지하기 위해 보안 위협을 줄입니다. 가상화 시스템에 등록된 계정이 유추하기 쉬운 비밀번호로 인한 위험이 존재합니다.

#### 보안 위협
무차별 대입 공격을 통한 계정 탈취로 인해 가상화 시스템 침입 경로가 제공될 수 있습니다.

#### 정책 기준
- 영문, 숫자, 특수문자 2개 조합 시 10자리 이상, 3개 조합 시 8자리 이상.
- 비밀번호 변경 주기: 90일 이하.

### 점검 대상 및 판단 기준

#### 대상
VMware ESXi, vCenter, XenServer, KVM, Nutanix

#### 판단 기준
- **양호**: 로그인 계정 비밀번호 관리 정책이 적용된 경우.
- **취약**: 로그인 계정 비밀번호 관리 정책이 적용되지 않은 경우.

### 조치 방법
로그인 계정 비밀번호를 관리 정책에 맞게 설정합니다. 영향은 일반적으로 없음.

### 점검 및 조치 사례

#### VMware ESXi
1. WEB 콘솔 페이지 접속: `https://<VMware ESXi IP>`
2. 호스트 > 관리 > 시스템 > 고급 설정으로 이동.
3. Security.PasswordQualityControl 설정값 확인.
4. min = N0, N1, N2, N3, N4 중 N3, N4의 값이 8 미만일 경우 [옵션 편집]을 클릭하여 수정.
5. Security.PasswordMaxDays 설정값 확인.
6. 90일 이하로 설정되어 있지 않은 경우 [옵션 편집]을 클릭하여 수정.

#### VMware vCenter
1. vSphere Client 접속 후, 다음 메뉴에 접근하여 확인:
   - (vCenter6.5) "관리" > "Single Sign On" > "구성" > "Policies" > "암호 정책" > 비밀번호 정책 확인.
   - (vCenter8) "관리" > "Single Sign On" > "구성" > "로컬 계정" > "암호 정책" > 비밀번호 정책 확인.
2. 비밀번호 정책 설정 적용.

#### XenServer
1. XenServer 접속 > Local Command Shell 실행.
2. 아래 명령어를 통해 비밀번호 설정 확인:
   - `# cat /etc/login.defs | grep –i "PASS_MAX_DAYS"`
   - `# cat /etc/login.defs | grep –i "PASS_MIN_DAYS"`
   - `# cat /etc/login.defs | grep -i "PASS_MIN_LEN"`
3. 아래 명령어 적용:
   - `# vi /etc/login.defs`
     ```
     PASS_MIN_LEN 8
     PASS_MAX_DAYS 90
     PASS_MIN_DAYS 7
     ```

#### KVM (RHEL 8 이후 버전 기반 리눅스)
1. `/etc/security/faillock.conf` 파일 확인.
2. 비밀번호 정책 설정이 되어 있지 않으면 적용 설정.

### 참고사항
- 영문, 숫자, 특수문자 2개 조합 시 10자리 이상, 3개 조합 시 8자리 이상 설정 권고.
- 비밀번호 최대 사용 기간을 90일(3개월) 이하로 설정할 것을 권고.
- 비밀번호 최소 사용 기간을 7일(1주) 이상으로 설정할 것을 권고.

### NTP 및 시각 동기화 설정

#### 개요
점검 내용: NTP 설정을 통한 시간 동기화 여부 점검  
점검 목적: 분석 수행이 가능하도록 하기 위함  
보안 위협: 초기 대응 불가 위험이 존재함

#### 점검 대상 및 판단 기준
- **대상**: VMware ESXi, vCenter, XenServer, KVM, Nutanix  
- **양호**: NTP 서버와 시간 동기화 설정을 적용한 경우  
- **취약**: NTP 서버와 시간 동기화 설정을 적용하지 않은 경우

#### 조치 방법
NTP 설정 및 시각 동기화 설정

#### 조치 시 영향
일반적 경우 영향 없음

#### 점검 및 조치 사례
- **VMware ESXi**
  - Web 콘솔 페이지 접속: `https://<VMware ESXi IP>`
  - 호스트 > 관리 > 시스템 > 시간 및 날짜로 이동
  - NTP 설정 확인

- **VMware vCenter**
  - vCenter Server 관리 페이지(`https://<주소>:5480/`) 접속 후, "시간" > "시간 동기화" > NTP 설정 여부를 확인

- **KVM**
  - PHC 사용 여부 확인
  - 사용하지 않으면 활성화 적용: `echo ptp_kvm > /etc/modules-load.d/ptp_kvm.conf`
  - `/dev/ptp0` 시계를 chrony 구성에 대한 참조로 추가 설정: `echo "refclock PHC /dev/ptp0 poll 2" >> /etc/chrony.conf`
  - chrony 데몬 다시 시작: `systemctl restart chronyd`

- **XenServer**
  - XenServer 접속 > Network and Management Interface > Network Time (NTP) > Provide NTP Servers Manually > 별도 NTP 서버 지정 설정 적용

- **Nutanix**
  - 웹 콘솔(`https://<Nutanix 웹 콘솔 IP:9440>`)에 접속
  - Settings > NTP Servers 선택하여 NTP 서버가 설정되어 있는지 확인
  - Controller VM에 접속하여 타임존 설정: `ncli cluster set-timezone timezone="Asia/Seoul"`
  - Nutanix 호스트 타임존 설정: `hostssh "date; mv /etc/localtime /etc/localtime.bak; ln -s /usr/share/zoneinfo/Asia/Seoul /etc/localtime; date"`

### ESXi Shell 세션 종료 시간 설정

#### 개요
점검 내용: ESXi Shell(TSM, TSM-SSH)의 Session Timeout(로그인 후 일정 시간 사용하지 않을 경우 세션 종료) 설정의 적정성 여부 점검  
점검 목적: 비인가자에 의한 시스템 무단 사용 방지 목적으로 Session Timeout 설정을 적용하기 위함  
보안 위협: 비인가자에 의한 시스템 무단 사용 위험이 존재함

#### 참고
- 기본값: 0(제한 없음)
- 기본적으로 ESXi Shell은 비활성화(HV-12)하여야하며, 해당 설정은 필요 시 ESXi Shell을 사용할 경우에 대비한 설정

#### 점검 대상 및 판단 기준
- **대상**: VMware ESXi  
- **양호**: Session Timeout 값(ESXiShellInteractiveTimeOut)이 600 이하로 설정된 경우  
- **취약**: Session Timeout 값(ESXiShellInteractiveTimeOut)이 0이거나, 600초과로 설정된 경우

#### 조치 방법
Session Timeout 값(ESXiShellInteractiveTimeOut)이 900 이하 설정

#### 조치 시 영향
일반적 경우 영향 없음

#### 점검 및 조치 사례
- **VMware ESXi**
  - Web 콘솔 페이지 접속: `https://<VMware ESXi IP>`
  - 관리 > 설정 > 시스템 > 고급 설정으로 이동
  - UserVars.ESXiShellInteractiveTimeOut 설정값 확인

### 가상화 장비 시스템 서비스 관리

#### 원격 로그 서버 이용 (HV-14)
**개요**
- **점검 내용**: 원격 로그 서버를 이용한 로그 저장 여부 점검.
- **점검 목적**: 시스템 가용성 저하, 침해에 따른 로그 유실 방지.
- **보안 위협**: 원격 로그 서버 또는 스토리지가 연동 설정되지 않은 경우 시스템 가용성 저하 및 로그 유실 위험이 존재.

**점검 대상 및 판단 기준**
- **대상**: VMware ESXi, vCenter, XenServer, KVM, Nutanix
- **양호**: 원격 로그 서버 또는 스토리지가 연동 설정된 경우.
- **취약**: 원격 로그 서버 또는 스토리지가 연동 설정되지 않은 경우.

**조치 방법**
- **원격 로그 서버 또는 스토리지 연동 설정**

**점검 및 조치 사례**
- **VMware ESXi**
  - Web 콘솔 페이지 접속 (`https://<VMware ESXi IP>`)
  - `호스트 > 관리 > 시스템 > 고급 설정`으로 이동
  - `Syslog.global.logHost` 설정값 확인 및 수정.
  
- **vCenter**
  - Syslog 설정 여부를 확인 후, vCenter Server 관리 페이지(`https://<주소>:5480/`) 접속하여 "Syslog" > "Syslog 설정 여부"를 확인.

- **KVM**
  - 원격 로그 서버 사용 확인 및 `/etc/rsyslog.conf` 파일에서 전송 지시어 확인.
  
- **XenServer**
  - `Remote Log` 서버 사용 유무 확인, `udp514 Port` 확인(`netstat -an | grep "udp"` 또는 `# netstat -an | grep " udp" | egrep "514"`).
  - `Syslog.conf` 파일 수정 (`/etc/sysconfig/syslog` 파일에 `SYSLOGD_OPTIONS="-m 0"`).

- **Nutanix**
  - Controller VM 접속하여 원격 로깅 서버 설정 확인(`ncli rsyslog-config list`).
  - 설정되지 않은 경우, `ncli rsyslog-config add-server name=<alias of log server> ip-address=<원격 로그 서버 IP> port=<원격 로그 서버 포트> network-protocol=tcp relp-enabled=no`.
  - 로그 레벨 설정(`ncli rsyslog-config add-module module-name=syslog_module level=info server-name=<alias of log server>`).

#### 시스템 주요 이벤트 로그 설정 (HV-15)
**개요**
- **점검 내용**: 시스템 주요 이벤트 로그가 설정 여부 점검.
- **점검 목적**: 시스템 문제 발생 시 보안, 성능 등의 이슈 파악.
- **보안 위협**: 로그 기록 정책이 내부 정책에 부합하지 않은 경우 시스템 문제 발생 시 보안, 성능 등의 이슈를 파악할 수 없는 위험이 존재.

**점검 대상 및 판단 기준**
- **대상**: VMware ESXi, vCenter, KVM
- **양호**: 로그 기록 정책이 내부 정책에 부합하게 설정된 경우.
- **취약**: 로그 기록 정책이 내부 정책에 부합하지 않은 경우.

**조치 방법**
- **로그 기록 정책을 내부 정책에 부합하게 설정**

**점검 및 조치 사례**
- **VMware ESXi**
  - Web 콘솔 페이지 접속 (`https://<VMware ESXi IP>`)
  - `호스트 > 관리 > 시스템 > 고급 설정`으로 이동
  - `Config.HostAgent.log.level` 설정값 확인 및 수정.
  
- **vCenter**
  - 로그 설정 레벨 확인 후, vSphere Client 접속하여 "호스트 및 클러스터" > [vCenter 서버] > "구성" > "설정" > "고급 설정" > `config.log.level` 확인.

- **KVM**
  - 호스트에 접속하여 `libvirt` 설정파일을 확인(`$ cat /etc/libvirt/libvirtd.conf`) 및 수정(`$ log_level =`).
  - 변경 사항 적용을 위해 `libvirt` 데몬 재시작 (`$ systemctl restart libvirtd.service`).

### 가상머신 관리

#### 1. 장치 변경 제한 설정
- **개요**: 가상 머신의 장치(네트워크 어댑터, CD-ROM 등) 연결을 끊거나, 설정 변경을 방지하기 위함.
- **점검 내용**: 가상 머신 장치 변경 제한 설정 적용 여부 점검.
- **점검 목적**: 관리자 권한이 없는 사용자(또는 프로세스)에 의한 장치 연결 및 설정 변경 가능성을 방지.
- **보안 위협**: 장치 연결 및 설정 변경이 가능한 위험이 존재함.
- **참고**: 서버보안 솔루션 등에서 해당 기능을 통제할 경우 양호.
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi
  - 양호: 장치 설정 변경 방지 설정이 활성화(true)된 경우
  - 취약: 설정 없거나, 비활성화(false)된 경우
- **조치 방법**: 가상 머신의 장치 설정 변경 방지 활성화 적용.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 가상 시스템 > [가상 머신 선택] > 설정 편집 > VM 옵션 > 고급 > 구성 매개 변수로 이동
  Step 3) isolation.device.edit.disable, isolation.device.connectable.disable 설정값 확인
  Step 4) 매개 변수 값을 각각 TRUE로 설정.
  또는, 각 매개 변수가 존재하지 않을 시, 해당 매개 변수 추가 및 값을 TRUE로 설정
  ```

#### 2. 불필요한 장치 제거
- **개요**: 불필요하게 연결된 외부 장치를 통한 잠재적인 공격 루트로 활용되는 것을 방지하기 위함.
- **점검 내용**: 불필요한 장치(USB, CD/DVD, 플로피 디스크, 병렬 포트, 직렬 포트) 제거 여부 점검.
- **점검 목적**: 외부 장치를 통한 잠재적인 공격 루트로 활용되는 위험을 방지.
- **보안 위협**: 불필요하게 연결된 외부 장치는 잠재적인 공격 루트로 활용될 수 있는 위험이 존재함.
- **참고**: 장치: USB, CD/DVD, 플로피 디스크, 병렬 포트, 직렬 포트.
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi, XenServer
  - 양호: 불필요한 장치가 가상 머신에 연결되지 않은 경우
  - 취약: 연결된 경우
- **조치 방법**: 불필요한 장치 연결 해제 적용.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 가상 시스템 > [가상 머신 선택] > 설정 편집 > 가상 하드웨어로 이동
  Step 3) 장치 연결 상태 확인 및 불필요한 외부 장치 비활성화

  l XenServer
  Step 1) 장치 연결 상태 확인
  1. PCI 장치 목록 확인: lspci
  2. 블록 디바이스 목록 확인: lsblk
  3. 네트워크 인터페이스 확인: ifconfig 또는 ip addr
  4. 가상 머신의 디스크 목록 확인: xe vm-list name-label="<VM_NAME>"
  5. VM에 연결된 디스크 확인: xe vbd-list vm-uuid=<VM_UUID>
  6. 모든 가상 디스크 이미지 목록 확인: xe vdi-list
  7. 네트워크 인터페이스 목록 확인: xe vif-list
  8. USB 장치 확인: lsusb
  9. 디스크 용량 및 사용 현황 확인: df –h
  Step 2) 불필요한 외부 장치 비활성화
  ```

#### 3. 콘솔 클립보드 복사&붙여넣기 기능 비활성화
- **개요**: 가상 머신에 클립보드를 활용한 복사/붙여넣기 기능을 비활성화하여 파일 송·수신 기능을 통한 로그 기록이 저장되도록 하기 위함.
- **점검 내용**: 가상 머신 콘솔 복사 기능 비활성화 여부 점검.
- **점검 목적**: 로그 분석을 통한 침입 탐지가 가능하도록 함.
- **보안 위협**: 파일 송·수신 기록이 로그에 저장되지 않아 로그 분석을 통한 침입 탐지가 불가능한 위험이 존재함.
- **참고**: ESXi 기본 비활성화.
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi
  - 양호: 콘솔 복사 기능이 비활성화 되어 있거나, 복사 제한이 설정된 경우
  - 취약: 활성화되어 있거나, 복사 제한이 설정되지 않은 경우
- **조치 방법**: 가상 머신 콘솔 복사 제한 설정.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 가상 시스템 > [가상 머신 선택] > 설정 편집 > VM 옵션 > 고급 > 구성 매개 변수로 이동
  Step 3) isolation.tools.copy.disable, isolation.tools.paste.disable 및 isolation.tools.setGUIOptions.enable 설정값 확인

---

Step 4) isolation.tools.copy.disable와 isolation.tools.paste.disable 각 변수 값을 TRUE로,
  isolation.tools.setGUIOptions.enable 변수 값을 FALSE로 설정.
  또는, 각 매개 변수가 존재하지 않을 시, 해당 매개 변수 추가 및 값 설정
  ```
