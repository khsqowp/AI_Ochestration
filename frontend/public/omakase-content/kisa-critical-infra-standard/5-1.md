# 5-1. 네트워크 장비 계정·패치·로깅 관리

### SNMP 서비스 확인

**개요**
점검 내용: SNMP 서비스 사용 여부 점검합니다.

**점검 목적**
서비스를 중지하도록 함. 불필요한 SNMP 서비스를 사용할 경우, DoS 공격, 보안 장비 성능 저하, 크래쉬, 리로드 등의 위험이 존재합니다.

**보안 위협**
SNMP 서비스: 네트워크 관리를 위한 프로토콜로 네트워크상의 서버, 프린터, 허브, 스위치, 라우터와 같은 네트워크 장치를 구성하고 정보를 수집하는 데 사용됩니다.
SNMP 서비스를 이용해야 하는 경우 Community String을 유추할 수 없게 설정합니다.

**점검 대상 및 판단 기준**
- **대상**: 방화벽, VPN, IDS, IPS, Anti-DDoS, 웹 방화벽 등
- **양호**: 불필요한 SNMP 서비스를 사용하지 않을 경우
- **취약**: 불필요한 SNMP 서비스를 사용할 경우

**조치 방법**
불필요한 경우 SNMP 서비스 중지합니다.
- 조치 시 영향: 일반적인 경우 영향 없음

**점검 및 조치 사례**
- **Step 1**: 보안 장비의 SNMP 설정 메뉴에서 확인
- **Step 2**: 불필요하다면 SNMP 서비스를 중지하고, 관리를 위해 NMS 솔루션과의 연동이 필요하다면 SNMP 설정

### SNMP Community String 복잡성 설정

**개요**
점검 내용: SNMP Community String이 유추하기 어렵게 설정되어 있는지 점검합니다.

**점검 목적**
SNMP Community String을 유추하기 어려워 네트워크상에서 시스템 정보가 비인가자에게 노출되지 않도록 합니다.

**보안 위협**
SNMP의 Community String을 기본값 또는 유추하기 쉬운 값으로 설정할 경우, 악의적인 사용자가 장비 설정을 쉽게 변경(RW)하여 중요 시스템 정보가 노출될 수 있는 위험이 존재합니다.
※ SNMP 버전: v1, v2, v3 이 존재. v1, v2는 Community String을 평문 전송하지만, v3는 암호화가 설정되어 해시값으로 전송됩니다.

**점검 대상 및 판단 기준**
- **대상**: 방화벽, VPN, IDS, IPS, Anti-DDoS, 웹 방화벽 등
- **양호**: SNMP 서비스를 사용하지 않거나, 유추하기 어려운 Community String을 설정한 경우
- **취약**: Community String을 기본값으로 사용하고 있거나, 유추하기 쉬운 Community String을 설정한 경우

**조치 방법**
유추하기 어려운 Community String을 설정합니다.
- 조치 시 영향: 일반적인 경우 영향 없음

**점검 및 조치 사례**
- **Step 1**: 보안 장비의 SNMP 설정 메뉴에서 Community String 확인
- **Step 2**: 보안 장비는 SNMP 취약성이 존재하므로 누구나 추측하기 어렵고 의미가 없는 문자열, 영문자 혼합으로 변경

### 핵심 개념 및 기법

#### 유해 트래픽 탐지/차단 정책 설정
- **개요**: 네트워크 장비에서 유해 트래픽(Flooding 공격, Scan 공격, 해킹 툴 공격 등)을 탐지/차단하는 정책을 설정하여 네트워크 운영 및 서비스의 장애 발생 가능성을 차단합니다.
- **점검 내용**: 유해 트래픽 탐지/차단 패턴이 적용된 경우와 그렇지 않은 경우를 점검합니다.
- **점검 목적**: 악성코드가 네트워크를 통해 전파되는 위험을 차단하기 위함입니다.

#### 기본 비밀번호 설정
- **개요**: 네트워크 장비 접근 시 기본 비밀번호(기본 관리자 계정도 함께 변경하도록 권고)를 사용하는지 점검합니다.
- **점검 내용**: 기본 비밀번호를 변경하지 않고 사용함으로써 발생할 수 있는 보안 위협을 확인합니다.
- **점검 목적**: 장비 출고 시 설정된 기본 비밀번호를 변경하지 않거나 그대로 사용할 경우, 비인가자가 인터넷을 통해 네트워크 장비에 접근하여 데이터 유출 또는 통신 중단의 위험이 있습니다.

### 취약점

- **유해 트래픽 탐지/차단 정책 미적용**: 유해 트래픽 탐지/차단 패턴이 적용되지 않은 경우, 악성코드가 네트워크를 통해 전파될 우려가 있습니다.
- **기본 비밀번호 사용**: 기본 비밀번호를 변경하지 않거나 설정하지 않은 경우, 비인가자가 인터넷을 통해 네트워크 장비에 접근하여 데이터 유출 또는 통신 중단의 위험이 있습니다.

### 절차

#### 유해 트래픽 탐지/차단 정책 설정 절차
1. **TCP/UDP/ICMP Flooding 공격**
   - 탐지 및 차단 패턴 적용 여부 점검
   - DDoS 차단시스템에 차단 정책 등록 여부 점검
   - 차단 패턴 적용 및 등록

2. **Port Scan 공격**
   - 탐지 및 차단 패턴 적용 여부 점검
   - DDoS 차단시스템에 차단 정책 등록 여부 점검

3. **해킹 툴 공격**
   - 악성코드에 대한 탐지 및 차단 패턴 적용 여부 점검
   - 주요 해킹 툴에 대한 탐지 및 차단 정책 등록

#### 기본 비밀번호 설정 절차 (Cisco IOS)
1. **enable 비밀번호 설정 확인**
   ```bash
   Router> enable
   Router# show running-config
   ```
2. **VTY, 콘솔, 보조(AUX) 포트의 로그인 인증 방식 및 비밀번호 설정 확인**
   ```bash
   login: 라인 비밀번호 인증
   login local: 로컬 사용자 인증
   ```
3. **enable 비밀번호 설정**
   ```bash
   Router# config terminal (단축 명령 conf t)
   Router(config)# enable secret <비밀번호> 또는 Router(config)# enable password <비밀번호>
   Router(config)# end
   ```
4. **가상 터미널(VTY) 비밀번호 설정**
   ```bash
   Router# config terminal
   Router(config)# line vty ?
   <0X4> First Line number
   Router(config)# line vty 0 4
   Router(config-line)# login
   Router(config-line)# password <비밀번호>
   ```
5. **콘솔 비밀번호 설정**
   ```bash
   Router# config terminal
   Router(config)# line console ?
   <0X0> First Line number
   Router(config)# line console 0
   Router(config-line)# login
   Router(config-line)# password <비밀번호>
   ```
6. **보조(AUX) 포트 비밀번호 설정**
   ```bash
   Router# config terminal
   Router(config)# line aux ?
   <0X0> First Line number
   Router(config)# line aux 0
   Router(config-line)# login
   Router(config-line)# password <비밀번호>
   ```

### 참고 정보

- **Flooding 공격**: 악의적으로 한꺼번에 많은 양의 데이터를 보내 상대방의 서비스를 운용할 수 없게 만드는 서비스 거부 공격
- **Scan 공격**: 네트워크, 시스템의 활성화된 포트·서비스·취약점을 식별하기 위한 행위
- **해킹툴 공격**: 공격자가 상용 해킹툴이나, 자제 제작한 해킹툴을 이용해 시스템을 침투·장악하거나 권한을 획득하는 행위

이 청크는 네트워크 장비의 유해 트래픽 탐지/차단 정책 설정과 기본 비밀번호 설정에 대한 내용을 포함하고 있습니다. 각 항목별로 개요, 점검 내용, 목적, 위협, 대상, 판단 기준, 조치 방법, 그리고 수치를 명확히 구분하여 설명하고 있습니다.

### 비밀번호 복잡성 설정

#### 개요
네트워크 장비에 기관 정책에 맞는 계정 비밀번호 복잡성 정책이 적용되어 있는지 점검합니다.

#### 점검 내용
- 비밀번호 복잡성 정책 설정 기능이 장비에 존재하지 않는 경우, 기관 정책에 맞게 계정 비밀번호를 설정하여 사용하는지 확인합니다.
- 비인가자의 네트워크 장비 터미널(콘솔, SSH, https 등) 접근 시도 공격(무차별 대입 공격, 사전 대입 공격 등)에 대한 대비 여부를 확인합니다.

#### 점검 목적
- 계정 생성 후 초기 비밀번호 설정 및 기존 비밀번호 변경 시 비밀번호 복잡성 제약 규칙을 적용받지 않아 취약한 비밀번호(예: qwerty, 12345, pass1234 등)를 설정할 수 있도록 허용되므로, 해당 취약점으로 인해 비인가자의 공격(무차별 대입 공격, 사전 대입 공격 등)에 계정 비밀번호가 유출되는 원인을 제공하여 유출된 비밀번호를 사용하여 비인가자가 네트워크 장비 터미널에 접근할 위험이 존재합니다.

#### 보안 위협
- 무차별 대입 공격(Brute Force Attack): 컴퓨터로 암호를 해독하기 위해 가능한 모든 키를 하나하나 추론해 보는 시도를 말합니다.
- 사전 대입 공격(Dictionary Attack): 사전에 있는 단어를 입력하여 비밀번호를 알아내거나 암호를 해독하는 데 사용되는 컴퓨터 공격 방법입니다.

#### 참고
- 비밀번호 복잡성: 계정 비밀번호 설정 시 영문(대문자, 소문자), 숫자, 특수문자가 혼합된 비밀번호로 설정하는 것을 의미합니다.

#### 점검 대상 및 판단 기준
- **대상**: 공통
- **판단 기준**:
  - 양호: 기관 정책에 맞는 비밀번호 복잡성 정책을 설정하거나, 비밀번호 복잡성 설정 기능이 없는 장비는 기관 정책에 따라 비밀번호를 사용하는 경우
  - 취약: 기관 정책에 맞지 않는 비밀번호를 설정하여 사용하는 경우

#### 조치 방법
- 관리기관의 비밀번호 작성규칙에 맞게 비밀번호 복잡성 정책 및 비밀번호 설정 조치합니다.

#### 조치 시 영향
- 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **공통**
  - Step 1) 장비에 비밀번호 복잡성 정책을 설정하거나 비밀번호 복잡성 설정 기능이 없는 장비는 기관 정책에 따라 비밀번호를 설정하여 사용하는지 확인합니다.
  
- **한국인터넷진흥원**
  - Step 2) 기반시설 관리기관의 비밀번호 작성규칙과 관련 법규를 준수하여 비밀번호 복잡성 정책을 설정하고 안전한 비밀번호를 사용합니다.

- **Cisco IOS**
  - Step 1) 비밀번호 복잡성 관련 설정 확인
    ```
    Router# show running-config
    ```
  - Step 2) 비밀번호의 최소 길이 설정(기존 비밀번호는 영향을 받지 않음)
    ```
    Router# config terminal
    Router(config)# security passwords min-length ?
    <0-16> Minimum length of all user/enable passwords
    Router(config)# security passwords min-length <길이>
    ```

### 계정 관리

#### 1. 사용자 계정 및 기본 비밀번호
- **User / User**: 스위치 상태 정보와 통계 자료를 볼 수 있지만, 설정 변경 불가능.
- **SLB Operator / slboper**: Web 서버들과 다른 인터넷 서비스의 로드를 관리하며, Server Load Balancing 운영 메뉴에서 사용 가능/사용 불가능을 설정할 수 있음.
- **Layer4 Operator / l4oper**: 공유된 인터넷 서비스들에 따른 라인 트래픽을 관리하고, 운영적인 명령어에 접근할 수 있음.
- **Operator / oper**: 모든 스위치 기능을 관리하며, SLB Operator 기능과 포트나 전반적인 스위치를 재설정할 수 있음.
- **SLB Administrator / slbadmin**: 웹 서버들과 다른 인터넷 서비스들의 로드 설정 및 관리 가능하며, Server Load Balancing 메뉴에 매개변수를 설정할 수 있음.
- **Layer4 Administrator / l4admin**: 공유된 인터넷 서비스들에 따른 라인 트래픽을 설정 및 관리하고, Server Load Balancing 메뉴에 모든 매개변수를 설정할 수 있음.
- **Administrator / admin**: User와 administrator 비밀번호를 변경할 수 있으며, Web 스위치의 모든 메뉴, 정보 그리고 설정 명령어들에 사용 가능.

#### 2. 점검 내용 및 목적
- **점검 내용**: 사용자의 접근 레벨이 7단계로 나누어져 있는지 확인.
- **점검 목적**: 각 계정의 역할과 권한을 정확히 이해하고, 필요한 경우 추가적인 권한 설정을 통해 보안을 강화.

#### 3. 보안 위협
- **보안 위협**: 잘못된 접근 레벨 설정으로 인해 중요한 설정 변경이 가능하거나, 불필요한 정보 노출 등의 위험이 있을 수 있음.

#### 1. 대상

#### 2. 판단 기준
- **양호**: 가상 터미널(VTY) 접근을 제한하는 ACL이 설정된 경우.
- **취약**: 가상 터미널(VTY) 접근을 제한하는 ACL이 설정되지 않은 경우.

### 조치 방법

#### 1. 최소 사용 기간
- **최소 사용 기간**: 지정된 IP만 네트워크 장비에 접근할 수 있도록 설정하여 비인가자의 터미널 접근을 차단함.
  
#### 2. 최대 사용 기간
- **최대 사용 기간**: Session Timeout 시간을 10분 이하로 설정하여 터미널 세션이 자동으로 종료되어 관리자의 부재 시 비인가자에게 통제를 받음.

### VTY 접속 시 안전한 프로토콜 사용

#### 개요
네트워크 장비 정책에 암호화 프로토콜(ssh)을 이용한 터미널 접근만 허용하도록 설정되어 있는지 점검합니다. 이를 통해 네트워크 터미널 접근 시 전송되는 데이터의 스니핑 공격으로부터 보호할 수 있습니다.

#### 점검 목적
공격에 대한 대비가 되어 있는지 확인하기 위함입니다. 암호화 프로토콜이 아닌 평문 프로토콜(telnet)을 이용하여 네트워크 장비에 접근할 경우, 네트워크 보안 위협으로 관리자 계정 정보(계정, 비밀번호)가 비인가자에게 유출될 위험이 존재합니다.

#### 보안 위협
스니핑 공격으로 인해 관리자 계정 정보가 유출될 수 있습니다. 스니핑은 네트워크상의 데이터를 도청하는 행위로, 스니퍼(Sniffer)는 "컴퓨터 네트워크상에 흘러 다니는 트래픽을 엿듣는 참조 도청장치"라고 말할 수 있습니다.

#### 점검 대상 및 판단 기준
- **대상**: Cisco, Alteon, Juniper, Piolink 등
- **양호**: 장비 정책에 VTY 접근 시 암호화 프로토콜(ssh) 이용한 접근만 허용하고 있는 경우
- **취약**: 장비 정책에 VTY 접근 시 평문 프로토콜(telnet) 이용한 접근을 허용하고 있는 경우

#### 조치 방법
암호화 프로토콜만 VTY에 접근할 수 있도록 설정합니다.

#### 조치 시 영향
일반적인 경우 영향 없음입니다.

#### 점검 및 조치 사례
- **Cisco IOS**
  - Step 1) SSH 활성화 확인: `Router# show ip ssh`
  - Step 2) Cisco IOS 이미지 확인: `Router# show version`
  - Step 3) SSH 설정:
    ```
    Router# config terminal
    Router(config)# hostname <호스트명>
    Router(config)# ip domain-name <도메인명>
    Router(config)# crypto key generate rsa
    How many bits in the modulus [512]: 2048
    Router(config)# ip ssh time-out <초>
    Router(config)# ip ssh version 2 (SSH 버전 2 사용)
    Router(config)# ip ssh authentication-retries [횟수] <- 재시도 횟수
    Router(config)# line vty 0 4
    Router(config-line)# transport input ssh
    ```
- **Radware Alteon**
  - Step 1) /sys/sshd에서 SSH 활성화 확인
  - Step 2) SSH 설정 방법:
    ```
    # cfg
    # /sys/sshd ena
    # /sys/sshd on
    # apply
    # save
    ```
- **Juniper Junos**
  - Step 1) SSH 버전 확인: `user@host# set ssh`
  - Step 2) SSH 활성화:
    ```
    [edit]
    root# set system services ssh
    [edit]
    root# commit
    ```
  - Step 3) Telnet 비활성화:
    ```
    [edit]
    root# delete system services telnet
    [edit]
    root# commit
    ```
- **Piolink PLOS**
  - Step 1) SSH 버전 확인: `(config)# management-access`
  - Step 2) SSH 활성화:
    ```
    (config-management-access)# ssh status enable
    (config-management-access)# apply
    ```
  - Step 3) Telnet 비활성화:
    ```
    (config-management-access)# telnet status disable
    (config-management-access)# apply
    ```

### 로깅 버퍼 크기 설정

#### 개요
점검 내용: 버퍼 메모리의 크기를 어느 정도로 설정하고 있는지 점검  
점검 목적: 장비 성능을 고려하여 최대 용량에 가깝도록 버퍼 크기를 설정하도록 함  
보안 위협: 버퍼 메모리의 용량을 초과하는 로그가 저장될 경우 로그 정보를 잃게 되어 침해사고 발생 시 침입 보안 위협

#### 참고
- 기본적으로 로그는 파일이 아닌 버퍼 메모리에 저장됨  
- 최대 버퍼 크기는 65,500byte이며 버퍼 용량을 높게 설정하면 패킷 전달이 안 되는 경우가 발생함.  
- 일반적으로 16Kbyte에서 32Kbyte의 크기가 적당하며, 최대 용량이 16Kbyte에 못 미치는 장비의 경우 장비 성능을 고려하여 최대 용량에 가깝게 설정하는 것을 권고함.

#### 점검 대상 및 판단 기준
- **대상**: Cisco, Piolink 등  
- **양호**: 저장되는 로그 데이터보다 버퍼 용량이 큰 경우  
- **취약**: 저장되는 로그 데이터보다 버퍼 용량이 작은 경우

#### 조치 방법
로그에 대한 정보를 확인하여 장비 성능을 고려한 최대 버퍼 크기를 설정  
조치 시 영향: 버퍼 크기가 장비 성능에 비해 큰 경우 라우터의 성능에 영향을 줌.

#### 점검 및 조치 사례
- **Cisco IOS**
  - 버퍼 메모리 설정 확인: `Router> enable`, `Router# show logging`
- **Piolink PLOS**
  - (config)# show logging, (config)#logging buffer <size>, (config)#logging priority <event> <level>

### 로깅 방법

#### Cisco IOS, Juniper Junos
- **콘솔 로깅**: 콘솔 포트에서만 보이므로 이 로그를 보기 위해서는 반드시 콘솔 포트에 연결해야 함.
- **Buffered 로깅**: 로그를 라우터의 RAM에 저장하는데 이 버퍼가 가득 차게 되면 오래된 로그는 자동으로 새로운 로그에 의해 대체됨.
- **Terminal 로깅**: Terminal monitor 명령을 사용하여 로깅을 설정하면 라우터에서 발생하는 로그 메시지를 VTY terminal에 보냄.
- **Syslog**: 시스코 라우터는 라우터의 로그 메시지가 외부의 syslog 서버에 저장되도록 설정할 수 있음.
- **SNMP traps**: SNMP trap이 설정되면 SNMP는 특별한 상황을 외부의 SNMP 서버에 전송하도록 설정할 수 있음.
- **ACL 침입 로깅**: 표준 또는, 확장된 액세스 리스트를 설정할 때 특정한 룰에 매칭하였을 경우 해당 패킷 정보를 로그에 남기도록 설정할 수 있는데, 이는 액세스 리스트 룰의 끝에 로그나 로그 인풋을 추가하면 됨. 로그 인풋은 로그와는 달리 인터페이스 정보도 함께 남기게 되므로 어떤 인터페이스를 통해 로그가 남았는지를 알 수 있음.

### NTP 및 시각 동기화 설정

#### 개요
점검 내용: 네트워크 장비의 NTP 서버 연동 및 시간 동기화 설정 적용 여부 점검  
점검 목적: 시스템 운영 또는 보안 사고 발생으로 인한 로그 분석 과정에서 이벤트 간의 인과 관계 파악에 도움을 주고 로그 자체의 신뢰성을 갖도록 하기 위함

#### 보안 위협
시스템 간 시간 동기화 미흡으로 보안 사고 및 장애 발생 시 로그에 대한 신뢰도 확보가 미흡해짐.

#### 참고
- IOS 12.2 이전 버전을 사용하는 장비에는 접근 통제(ACL) 설정이 되어 있어야 양호

#### 점검 대상 및 판단 기준
- **대상**: Cisco, Alteon, Juniper 등  
- **양호**: NTP 서버를 통한 시스템 간 실시간 시간 동기화가 설정된 경우  
- **취약**: NTP 서버와 연동되어 있지 않아 시스템 간 실시간 시간 동기화 설정이 되어있지 않은 경우

#### 조치 방법
NTP 사용 시 신뢰할 수 있는 서버로 설정  
조치 시 영향: 일반적인 경우 영향 없음.

#### 점검 및 조치 사례
- **Cisco IOS**
  - NTP 서버 설정 확인: `Router# show running-config`
  - Global Configuration 모드에서 ntp server 명령을 실행: `Router# config terminal`, `Router(config)# ntp server <NTP 서버 IP>`
- **Radware Alteon**
  - /sys/ntp에서 NTP 서버 설정 확인, # cfg, # /sys/ntp, # on, # prisrvr [NTP 서버 IP], # intrval [동기화 주기]
- **Juniper Junos**
  - root authentication 설정을 이용하여 [edit system] 레벨에서 NTP 서비스 설정 확인: `user@host> configure`, `[edit]`, `user@host# show`
  - NTP 서버와 네트워크 장비가 부팅될 때 시간 동기화를 위한 NTP 부트 서버를 설정: `user@host> configure`, `[edit]`, `user@host# edit system ntp`, `[edit system ntp]`, `user@host# set server <NTP 서버 IP>`, `user@host# set boot-server <NTP 부트 서버 IP>`
  - 네트워크 장비와 NTP 서버 간 시간 차이가 1000초 이상 다르면 시간 동기화를 하지 않기 때문에 부팅 단계에서 정확한 시간을 확보하도록 부트 서버를 구성.

### Timestamp 로그 설정

#### 개요
점검 내용: 네트워크 장비 설정 중 timestamp를 설정하여 로그 시간을 기록할 수 있게 하였는지 점검  
점검 목적: 네트워크 장비 로그에 시간을 기록하게 설정하여 공격자의 악의적인 행위를 파악하기 위한 로그의 신뢰성을 확보하기 위함

#### 보안 위협
네트워크 장비에 timestamp를 설정하지 않을 경우, 로그에 시간이 기록되지 않아 공격 및 침입시도에 대한 정보를 정확히 분석할 수 없고 로그 기록에 대한 신뢰성을 잃게 됨.

#### 참고
- timestamp: 네트워크 장비 로그 메시지에 관리자가 지정한 형식으로 시간 정보를 남기도록 하는 설정

#### 점검 대상 및 판단 기준
- **대상**: Cisco 등  
- **양호**: timestamp 로그 설정이 되어 있는 경우  
- **취약**: timestamp 로그 설정이 되어 있지 않은 경우

#### 조치 방법
로그에 시간 정보가 기록될 수 있도록 timestamp 로그 설정  
조치 시 영향: 일반적인 경우 영향 없음.

#### 점검 및 조치 사례
- **Cisco IOS**
  - service timestamps 설정 확인: `Router> enable`, `Router# show running-config`
  - timestamp 로그 설정:
    1. 로그 메시지의 타임스탬프를 UTC 시간대로 밀리초 단위까지 표시: `Router# config terminal`, `Router(config)# service timestamps log datetime msec show-timezone`
    2. 로그 메시지의 타임스탬프를 로컬 시간대로 밀리초 단위까지 표시: `Router(config)# clock timezone KST 9`, `Router(config)# service timestamps log datetime msec localtime show-timezone`

### SNMP 서비스 확인

#### 개요
네트워크 장비의 SNMP(Simple Network Management Protocol) 서비스를 사용하지 않는 경우, 비활성화 상태인지 점검한다.

#### 점검 내용 및 목적
- **점검 내용**: 네트워크 장비에서 SNMP 서비스가 활성화되어 있는지 확인하고, 필요 없는 경우에는 비활성화 상태인지 점검한다.
- **점검 목적**: 불필요한 SNMP 서비스를 차단하여 SNMP 서비스의 취약점을 이용한 공격(조작된 MIB 정보를 통한 네트워크 설정 변경, 전송데이터 평문 전송 등)을 차단하기 위함이다.

#### 보안 위협
- **위협**: 불인가자가 SNMP에 무단 접근하여 설정 파일 열람 및 수정이나 정보 수집 및 관리자 권한 획득, DoS(서비스 거부 공격) 등의 다양한 형태의 공격이 가능하다.
  - **SNMP**: TCP/IP 기반 네트워크상에서 정기적으로 여러 정보를 자동으로 수집하여 네트워크 관리를 하기 위한 프로토콜이며, v1, v2, v3 세 가지 버전이 존재하는데, v2까지는 요청, 응답 패킷이 평문으로 전송되기 때문에 스니핑이 가능하지만, v3 이상부터는 HMAC-MD5 또는 HMAC-SHA 알고리즘 기반의 인증을 제공한다.
  - **Community String**: SNMP는 MIB(Management Information Base)라는 정보를 주고받기 위해 인증 과정에서 일종의 비밀번호인 'Community String'을 사용한다.
  - **DoS(Denial of Service)**: 시스템을 악의적으로 공격해 해당 시스템의 자원을 부족하게 하여 원래 의도된 용도로 사용하지 못하게 하는 공격이다.

#### 점검 대상 및 판단 기준
- **대상**: Cisco, Alteon, Passport, Juniper, Piolink 등
- **판단 기준**:
  - **양호**: 사용하지 않는 SNMP 서비스를 비활성화한 경우
  - **취약**: 사용하지 않는 SNMP 서비스를 비활성화하지 않은 경우

#### 조치 방법
장비별 제공하는 최신 취약점 정보를 파악 후 최신 패치 및 업그레이드를 수행한다. SNMP 서비스를 사용하지 않는 경우 비활성화하고, SNMP 서비스를 사용하는 경우 이전 버전보다 보안 수준이 높은 SNMPv3 사용을 권고한다.

#### 조치 시 영향
일반적인 경우 영향 없음이다.

### 점검 및 조치 사례

- **Cisco IOS**
  - Step 1) `Router# show running-config`
  - Step 2) `Router# show snmp`
  - Step 3) `Router# config terminal` → `Router(config)# no snmp-server`

- **Radware Alteon**
  - Step 1) `>> Main# /cfg/dump`
  - Step 2) `>> Main# /cfg/sys/access/snmp`
  - Step 3) `Current SNMP access: disabled`
  - Step 4) `Enter new SNMP access (disabled/read-only/read-write) [d/r/w]:`

- **Passport**
  - Step 1) SNMP 서비스가 불필요하다면 서비스 중지

- **Juniper Junos**
  - Step 1) `user@host# show snmp`
  - Step 2) `user@host> configure` → `user@host# no set snmp community public`

- **Piolink PLOS**
  - Step 1) `switch# show running-config`

### 네트워크 장비 기능 관리

#### TFTP 서비스 차단 (N-21)
- **개요**: 불필요한 TFTP 서비스가 구동되어 있는지 확인하고, 허용된 시스템에서만 TFTP 사용하도록 설정.
- **점검 내용**: TFTP 서비스의 ACL 적용 여부 점검.
- **점검 목적**: 비인가자의 내부 정보 유출 방지와 중요 정보 보호.
- **보안 위협**: TFTP는 인증 없이 사용 가능하여 악성코드 배포 및 중요한 내부 정보 유출 가능.
- **참고**: TFTP는 UDP 기반, 포트 69번을 사용하며, FTP보다 구현하기 쉽지만 보안에 취약.

#### Spoofing 방지 필터링 적용 (N-22)
- **개요**: 스푸핑 방지 필터링(Anti-Spoofing Filtering)을 통해 차단.
- **점검 내용**: 네트워크 경계에서 소스 IP 주소가 명백히 위조된 트래픽을 차단하는지 점검.
- **점검 목적**: IP 스푸핑 기반 DoS 공격으로부터 인프라 보호.
- **보안 위협**: 정상적인 서비스 불가능.
- **참고**: IP Spoofing은 호스트의 원본 주소를 다른 소스 주소로 조작하는 것을 의미.

#### DDoS 공격 방어 설정 또는 DDoS 장비 사용 (N-23)
- **개요**: DDoS 공격 방어 설정을 적용하거나 DDoS 대응 장비를 사용.
- **점검 내용**: DDoS 공격 방어 설정 및 DDoS 대응 장비의 사용 여부 점검.
- **점검 목적**: DDoS 공격으로 인한 피해 최소화.
- **보안 위협**: 네트워크 및 시스템 리소스 속도 저하, 서버 손상 가능.
- **참고**: DDoS는 해커에 의해 감염된 다수의 좀비 PC로부터 트래픽이 특정 서버로 유입되어 서비스 방해.

#### 사용하지 않는 인터페이스 비활성화 (N-24)
- **개요**: 사용하지 않는 인터페이스가 비활성화 상태인지 점검.
- **점검 내용**: 사용하지 않는 인터페이스의 활성화 여부 점검.
- **점검 목적**: 비인가자의 네트워크 접근 차단 및 정보 유출 방지.
- **보안 위협**: 물리적인 내부 접근을 통해 불법적인 네트워크 접근 가능.

#### TCP Keepalive 서비스 설정 (N-25)
- **개요**: TCP Keepalive 서비스를 사용하여 연결 상태 유지.
- **점검 내용**: TCP Keepalive 서비스의 설정 여부 점검.
- **점검 목적**: 유휴 TCP 세션을 무단 접근 및 하이재킹 공격에 취약하지 않도록 유지.
- **보안 위협**: 유휴 연결은 무단 접근 및 하이재킹 공격에 취약.

### ACL, Rate Limiting, TCP Intercept
- **ACL (Access Control List)**: 스푸핑 방지 필터링을 사전 적용하고, DDoS 공격 유형에 따라 임시 차단.
- **Rate Limiting**: 특정 유형의 트래픽에 대역폭과 일정 시간 동안 전송량을 제한하여 다른 서비스에 필요하다는 대역폭을 확보.

---

- **TCP Intercept**: TCP SYN Flooding 공격로부터 서버를 보호하며, Intercept 또는 Watch 모드로 설정.
