# 1-1. Unix 서버 계정 관리와 인증 정책

### 주요 정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드

#### Unix 서버 취약점 분석 및 평가 항목

1. **계정 관리**
   - **항목**: root 계정 원격 접속 제한, 비밀번호 관리 정책 설정, 계정 잠금 임계값 설정 등
   - **점검 내용**: 시스템 정책에 따라 root 계정의 원격 터미널 접속 차단 여부 점검.
   - **점검 목적**: 외부 비인가자의 root 계정 접근을 차단하여 시스템 장악 방지.
   - **보안 위협**: root 계정은 운영체제의 모든 기능을 변경할 수 있어 탈취로 인한 위험이 큼.
   - **참고**: 무차별 대입 공격과 사전 대입 공격 등으로 root 계정 사용 불가 위험 존재.
   - **점검 대상 및 판단 기준**: SOLARIS, LINUX, AIX, HP-UX 등
     - **양호**: 원격 터미널 서비스를 사용하지 않거나, root 직접 접속을 차단한 경우
     - **취약**: 원격 터미널 서비스에서 root 직접 접속이 허용된 경우
   - **조치 방법**: 파일 내용 설정으로 원격 접속 시 root 계정으로 접속할 수 없도록 함.
   - **조치 시 영향**: 일반적으로 영향 없음.

2. **파일 및 디렉토리 관리**
   - **항목**: root 홈, 패스 디렉터리 권한 및 패스 설정, 파일 및 디렉터리 소유자 설정 등
   - **점검 내용**: 파일과 디렉터리의 소유자와 권한 설정 점검.
   - **점검 목적**: 시스템 보안을 위해 적절한 권한 설정 필요.
   - **점검 대상 및 판단 기준**: UNIX 서버

3. **서비스 관리**
   - **항목**: Finger 서비스 비활성화, 공유 서비스에 대한 익명 접근 제한 설정 등
   - **점검 내용**: 불필요한 서비스나 익명 접근을 허용하는 서비스의 상태 점검.
   - **점검 목적**: 시스템 보안 강화를 위해 필요 이상의 서비스 비활성화.

4. **패치 관리**
   - **항목**: 주기적 보안 패치 및 벤더 권고사항 적용
   - **점검 내용**: 시스템 패치의 최신 상태 점검.
   - **점검 목적**: 보안 취약점을 최소화하기 위해 정기적인 패치 적용 필요.

5. **로그 관리**
   - **항목**: NTP 및 시각 동기화 설정, 정책에 따른 시스템 로깅 설정 등
   - **점검 내용**: 시간 동기화와 로그 파일의 소유자 및 권한 설정 점검.
   - **점검 목적**: 시스템 상태를 파악하고 보안 이벤트를 추적하기 위해 적절한 로그 관리 필요.

### 계정 관리

#### 비밀번호 관리 정책 설정
비밀번호 복잡성 및 길이는 영문, 숫자, 특수문자를 포함하여 최소 8자 이상으로 설정되어야 한다. 변경 주기는 최소 1일, 최대 90일로 설정된다.

#### 점검 내용
비밀번호 관리 정책 설정 여부를 점검한다.

#### 점검 목적
사용자의 비밀번호 복잡성과 주기적 변경을 통해 시스템 보안을 강화하기 위함이다.

#### 보안 위협
비밀번호 관련 정책이 설정되지 않을 경우, 무차별 대입 공격, 사전 대입 공격 등에 의해 비밀번호가 노출될 위험이 존재한다.

#### 참고
- 비밀번호 복잡성: 영문, 숫자, 특수문자를 포함하여 최소 8자리 이상

### 점검 대상 및 판단 기준

#### 대상
SOLARIS, LINUX, AIX, HP-UX 등

#### 판단 기준
- 양호: 비밀번호 관리 정책이 설정된 경우
- 취약: 비밀번호 관리 정책이 설정되지 않은 경우

### 조치 방법

#### 최소 사용 기간
1일로 설정된다.

#### 최대 사용 기간
90일로 설정된다.

#### 최근 비밀번호 기억
4회 이상으로 설정된다.

### 영향
비밀번호 변경 시 Web, WAS, DB 연동 구간에서 문제가 발생할 수 있으므로 연동 구간에 미칠 수 있는 영향을 고려하여 적용 필요하다.

### 점검 및 조치 사례

### 부적절한 비밀번호 유형

- 사전에 나오는 단어나 이들의 조합
- 길이가 너무 짧거나 NULL(공백)인 비밀번호
- 키보드 자판의 일련의 나열 (예시 : abcd, qwert 등)
- 사용자 계정 정보에서 유추 가능한 단어들 (예시 : 지역명, 부서명, 계정명, 사용자 이름 이니셜, root, admin 등)

### 비밀번호 관리 방법

1. 영문, 숫자, 특수문자를 조합하여 계정명과 다른 8자 이상의 비밀번호 설정
2. 다음 각 항목의 문자 종류 중 2종류 이상을 조합하여 최소 10자리 이상 또는 3종류 이상을 조합하여 최소 8자리 이상의 길이로 구성
   - 영문 대문자 (26개)
   - 영문 소문자 (26개)
   - 숫자 (10개)
   - 특수문자 (32개)
3. 시스템마다 다른 비밀번호 사용
4. 비밀번호를 기록해 놓는 경우 변형하여 기록

### 계정 잠금 임계값 설정

| 옵션 | 설명 |
| --- | --- |
| RETRIES | 로그인 시도 횟수 |
| LOCK_AFTER_RETRIES | 로그인 시도 횟수와 같거나 초과 되면 잠금 여부 |
| UNLOCK_AFTER | 잠금시간 분(m), 시(h), 일(d), w(주) 단위로 설정 가능 |

#### 점검 대상 및 판단 기준

- 대상: SOLARIS, LINUX, AIX, HP-UX 등
- 양호: 계정 잠금 임계값이 10회 이하의 값으로 설정된 경우
- 취약: 계정 잠금 임계값이 설정되어 있지 않거나, 10회 이하의 값으로 설정되지 않은 경우

#### 조치 방법

- 계정 잠금 임계값을 10회 이하로 설정
- HP-UX: Trusted Mode로 전환 시 파일 시스템 구조가 변경되어 운영 중인 서비스에 문제가 발생할 수 있으므로 충분한 테스트를 거친 후 Trusted Mode로의 전환이 필요함.
- LINUX: /etc/pam.d/system-auth 파일 설정 시 라이브러리(/lib/security/pam_tally.so)가 해당 경로에 존재하는지 확인 필요 (존재하지 않는 파일의 경로로 설정하는 경우 시스템 로그인에 장애가 발생할 수 있음).
- PAM 모듈을 이용하여 설정할 때 해당 순서를 지키지 않을 경우, 로그인 실패 또는 인증 실패 등 예기치 못한 상황이 발생할 수 있으므로 반드시 순서에 맞게 설정해야 함.

#### 점검 및 조치 사례

- SOLARIS
  - [5.9 미만 버전]
    Step 1) /etc/default/login 파일에 RETRIES 값 수정
    `RETRIES=10`
  - [5.9 이상 버전]
    Step 1) /etc/security/policy.conf 파일에 LOCK_AFTER_RETRIES 값 수정

- LINUX (Redhat 계열)
  - Step 1) /etc/pam.d/system-auth 파일에 deny 값 수정
    `auth required /lib/security/pam_tally.so 또는 /lib/security/pam_tally2.so deny=10 unlock_time=120 no_magic_root`
    `account required /lib/security/pam_tally.so 또는 /lib/security/pam_tally2.so no_magic_root reset`

- LINUX (Debian 계열)
  - Step 1) /etc/pam.d/common-auth 파일에 모듈 값 수정
    `auth required /lib/security/pam_tally.so 또는 /lib/security/pam_tally2.so deny=10 unlock_time=120 no_magic_root`
    `account required /lib/security/pam_tally.so 또는 /lib/security/pam_tally2.so no_magic_root reset`

- AIX
  - Step 1) /etc/security/user 파일에 loginretries 값 수정
    `loginretries = 3`

- HP-UX (11.v2 이하 버전)
  - Step 1) /tcb/files/auth/system/default 파일에 u_maxtries 값 수정
    `u_maxtries#3`

- HP-UX (11.v3 이상 버전)
  - Step 1) /etc/default/security 파일에 AUTH_MAXTRIES 값 수정
    `AUTH_MAXTRIES=3`

### U-06 UNIX > 1. 계정 관리
#### 개요
사용자의 `su` 명령 사용을 원천적으로 차단하기 위해 특정 그룹에 속한 사용자만 `su` 명령어를 사용하도록 제한하는 점검과 조치 방법에 대해 설명합니다.

#### 점검 내용
- `su` 명령어 사용을 허용하는 사용자를 지정한 그룹이 설정 여부 점검.
- `su` 관련 그룹만 `su` 명령어 사용 권한이 부여되어 있는지 점검하여 `su` 그룹에 포함되지 않은 일반 사용자들이 `su` 명령어를 사용할 수 있는지 확인합니다.

#### 점검 목적
사용자의 `su` 명령 사용을 원천적으로 차단하여 무분별한 사용자 변경으로 타 사용자 소유의 파일을 변경하거나 root 계정으로 변경하는 경우 관리자 권한을 획득할 수 있는 위험을 줄입니다.

#### 보안 위협
관리자 권한을 획득할 수 있는 위험이 존재합니다.

#### 참고
- 일반 사용자 계정 없이 root 계정만 사용하는 경우 `su` 명령어 사용 제한이 불필요합니다.

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: `su` 명령어를 특정 그룹에 속한 사용자만 사용하도록 제한된 경우
- **취약**: `su` 명령어를 모든 사용자가 사용하도록 설정된 경우

#### 조치 방법
- PAM 모듈 설정 또는 `su` 명령어 허용 그룹 생성 후 `su` 명령어 일반 사용자 권한 제거하도록 설정합니다.

#### 조치 시 영향
그룹에 추가된 계정들은 모든 Session 종료 후 재 로그인 시 `su` 명령어 사용 가능합니다.

#### 점검 및 조치 사례
- **SOLARIS, AIX, HP-UX**
  - `/etc/group` 파일 내 wheel 그룹 (su 명령어 사용 그룹) 및 그룹 내 구성원 존재 여부 확인.
  - `ls –l /usr/bin/su` 입력 후 wheel 그룹이 su 명령어를 사용할 수 있는지 설정 여부 확인.
  - wheel group 생성 (`# groupadd wheel`) 및 `su` 명령 그룹 변경 (`# chgrp wheel /usr/bin/su`), `su` 명령어 권한 변경 (`# chmod 4750 /usr/bin/su`).
  - wheel 그룹에 su 명령 허용 계정 등록 (`# usermod -G wheel <username>`).

- **LINUX**
  - PAM 모듈 이용 중이지 않을 경우:
    - `/etc/group` 파일 내 wheel 그룹 확인.
    - `ls -l /usr/bin/su` 입력 후 su 명령어 그룹과 권한 확인.
    - wheel group 생성 및 `su` 명령 그룹 변경, `su` 명령어 권한 변경, wheel 그룹에 su 명령 허용 계정 등록.
  - PAM 모듈 이용 중인 경우:
    - `/etc/group` 입력 후 wheel 그룹 확인.
    - `/etc/pam.d/su` 파일 내 su 명령어 허용 그룹 확인.
    - `usr/bin/su` 파일 내 su 명령어 그룹과 권한 확인.
    - `/etc/pam.d/su` 파일에 모듈 값 수정 (`auth required pam_wheel.so use_uid` 또는 `auth required pam_wheel.so group=wheel`).

### 사용자 shell 점검

#### 개요
로그인이 불필요한 계정(adm, sys, daemon 등)에 쉘 부여 여부를 점검하여 로그인이 필요하지 않은 계정을 통한 시스템 명령어 실행을 차단하고, 비인가자가 해당 기본 계정으로 시스템에 접근하는 위험을 줄입니다.

#### 점검 내용
로그인이 불필요한 계정에 쉘 부여 여부를 점검합니다.

#### 점검 목적
실행하지 못하게 하기 위함

#### 보안 위협
로그인이 불필요한 계정에 쉘이 부여될 경우, 비인가자가 해당 기본 계정으로 시스템에 접근할 수 있는 위험이 존재합니다.

#### 참고
- **쉘(Shell)**: 대화형 사용자 인터페이스로써, 운영체제(OS) 가장 외곽계층에 존재하여 사용자의 명령어를 이해하고 실행합니다.
- **/bin/false**: 시스템 접근을 항상 실패로 처리해 로그인을 차단하고, 서비스 계정의 직접 접근 차단에 사용됩니다.
- **/sbin/nologin**: 로그인 시 “This account is currently not available” 메시지를 출력하며 접근을 차단하고, FTP와 같은 일부 서비스의 접근은 허용됩니다.

#### 점검 대상 및 판단 기준
##### 대상
SOLARIS, LINUX, AIX, HP-UX 등

##### 판단 기준
- **양호**: 로그인이 필요하지 않은 계정에 /bin/false(/sbin/nologin) 쉘이 부여된 경우
- **취약**: 로그인이 필요하지 않은 계정에 /bin/false(/sbin/nologin) 쉘이 부여되지 않은 경우

#### 조치 방법
로그인이 필요하지 않은 계정에 대해 /bin/false(/sbin/nologin) 쉘 부여 설정합니다.

#### 조치 시 영향
일반적인 경우 영향이 없습니다.

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - Step 1) `/etc/passwd` 파일을 참고하여 로그인이 불필요한 계정에 /bin/false(/sbin/nologin) 쉘 부여 여부 확인
    ```bash
    # cat /etc/passwd | grep –E “^daemon|^bin|^sys|^adm|^listen|^nobody|^nobody4|^noaccess|^diag|^operator|^games|^gopher” | grep -v admin
    ```
  - Step 2) 로그인이 불필요한 계정에 /bin/false 또는 /sbin/nologin 쉘 부여
    ```bash
    # usermod -s /bin/false <계정명>
    # usermod –s /sbin/nologin <계정명>
    ```
- **로그인이 불필요한 계정 목록**
  - daemon, bin, sys, adm, listen, nobody, nobody4, noaccess, diag, operator, games, gopher

### 세션 종료 시간 설정

#### 개요
사용자 쉘에 대한 환경설정 파일에서 Session Timeout 설정 여부를 점검하여 사용자의 고의 또는 실수로 시스템에 계정이 접속된 상태로 방치됨을 차단하고, 유휴 시간 내 비인가자가 시스템에 접근하여 불필요한 정보를 노출할 위험을 줄입니다.

#### 점검 내용
사용자 쉘에 대한 환경설정 파일에서 Session Timeout 설정 여부를 점검합니다.

#### 점검 목적
사용자의 고의 또는 실수로 시스템에 계정이 접속된 상태로 방치됨을 차단하기 위함

#### 보안 위협
Session timeout 값이 설정되지 않을 경우, 유휴 시간 내 비인가자가 시스템에 접근하여 불필요한 정보를 노출할 위험이 존재합니다.

#### 참고
- **Session**: 프로세스들 사이에 통신을 수행하기 위해서 메시지 교환을 통해 서로를 인식한 이후부터 통신을 마칠 때까지의 시간

#### 점검 대상 및 판단 기준
##### 대상
SOLARIS, LINUX, AIX, HP-UX 등

##### 판단 기준
- **양호**: Session Timeout이 600초(10분) 이하로 설정된 경우
- **취약**: Session Timeout이 600초(10분) 이하로 설정되지 않은 경우

#### 조치 방법
600초(10분) 동안 입력이 없는 경우 접속된 Session을 끊도록 설정합니다.

#### 조치 시 영향
모니터링 용도일 경우 세션 타임 설정 시 모니터링 업무가 불가할 수 있으므로 예외 처리 필요합니다.

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - [sh, ksh, bash]
    ```bash
    Step 1) /etc/profile 파일 내 TMOUT 값 설정
    TMOUT=600
    export TMOUT
    ```
  - [csh]
    ```bash
    Step 1) /etc/csh.cshrc 또는 /etc/csh.login 파일 내 autologout 값 설정
    set autologout=10
    ```

### 안전한 비밀번호 암호화 알고리즘 사용

#### 개요
안전한 비밀번호 암호화 알고리즘을 사용 여부를 점검하여 사용자 계정정보를 보호하고, 취약한 비밀번호 암호화 알고리즘을 사용할 경우 노출된 계정에 대해 비인가자가 암호 복호화 공격을 통해 비밀번호를 획득할 위험을 줄입니다.

#### 점검 내용
안전한 비밀번호 암호화 알고리즘을 사용 여부를 점검합니다.

#### 점검 목적
안전한 비밀번호 암호화 알고리즘을 사용하여 사용자 계정정보를 보호하기 위함

#### 보안 위협
취약한 비밀번호 암호화 알고리즘을 사용할 경우, 노출된 계정에 대해 비인가자가 암호 복호화 공격을 통해 비밀번호를 획득할 위험이 존재합니다.

#### 참고
- **비밀번호 암호화 알고리즘 저장 방식**: $1 : MD5 / $2 : Blowfish / $5 : SHA-256 / $6 : SHA-512
- **비밀번호 암호화 알고리즘 변경 필요**: 취약한 비밀번호 암호화 알고리즘을 사용하고 있는 모든 계정 비밀번호 재설정 필요

#### 점검 대상 및 판단 기준
##### 대상
SOLARIS, LINUX, AIX, HP-UX 등

##### 판단 기준
- **양호**: SHA-2 이상의 안전한 비밀번호 암호화 알고리즘을 사용하는 경우
- **취약**: 취약한 비밀번호 암호화 알고리즘을 사용하는 경우

#### 조치 방법
SHA-2 이상의 안전한 비밀번호 암호화 알고리즘 적용 설정합니다.

#### 조치 시 영향
일반적인 경우 영향이 없습니다.

#### 점검 및 조치 사례
- **SOLARIS**
  - Step 1) `/etc/passwd` 파일 내 암호화 필드 값 확인
  - Step 2) `/etc/security/policy.conf` 파일 내 CRYPT_DEFAULT 값 설정
    ```bash
    CRYPT_DEFAULT = 5 또는 6
    ※ CRYPT_DEFAULT = 5: SHA-256 / 6 : SHA-512
    ```
- **LINUX**
  - [Redhat]
    - Step 1) `/etc/shadow(또는 /etc/passwd)` 파일 내 암호화 필드 값 확인
    - Step 2) `/etc/login.defs` 파일 내 ENCRYPT_METHOD 값 설정
      ```bash
      ENCRYPT_METHOD <SHA-2 이상 암호화 알고리즘(SHA-256 또는 SHA-512)>
      ```
  - [Debian]
    - Step 1) `/etc/shadow(또는 /etc/passwd)` 파일 내의 암호화 필드 값 확인
    - Step 2) `/etc/login.defs` 파일 내 ENCRYPT_METHOD 값 설정
      ```bash
      ENCRYPT_METHOD <SHA-2 이상 암호화 알고리즘(SHA-256 또는 SHA-512 또는 yescrypt)>
      ```
    - Step 3) `/etc/pam.d/common-password` 파일 내 안전한 알고리즘 설정
      ```bash
      password[success=2 default=ignore] pam_unix.so <SHA-2 이상 암호화 알고리즘>
      ```
- **AIX**
  - Step 1) `/etc/security/passwd` 파일 내 비밀번호 암호화 알고리즘 확인
    ```bash
    password = {<암호화 알고리즘>}<해시값>
    ```
  - Step 2) 안전한 암호화 알고리즘 설정
    ```bash
    # chsec -f /etc/security/login.cfg –s usw –a pwd_algorithm=<SHA-2 이상 암호화 알고리즘(SHA-256 또는 SHA-512)>
    ※ /etc/security/pwdalg.cfg 파일을 참조하여 OS에서 정의된 암호화 알고리즘 확인 가능
    ```
- **HP-UX**
  - Step 1) `/etc/shadow` 파일 내의 암호화 필드 값 확인
  - Step 2) `/etc/default/security` 파일 내 CRYPT_DEFAULT 값 설정
    ```bash
    CRYPT_DEFAULT = 5 또는 6
    ※ HP-UX 11i v2 이상이며, PHI 및 shadow password를 사용하지 않는 경우 취약
    ※ CRYPT_DEFAULT = 5: SHA-256 / 6 : SHA-512
    ```

### /etc/passwd 파일 소유자 및 권한 설정

#### 개요
/etc/passwd 파일의 권한 적절성 여부를 점검하여, 비인가자의 임의적인 파일 변조를 방지하고 계정을 포함한 사용자 권한 획득 위험을 줄입니다.

#### 점검 내용 및 목적
- **점검 내용**: /etc/passwd 파일 권한 적절성 여부 점검
- **점검 목적**: 관리자만이 파일을 제어할 수 있게 하여 비인가자의 임의적인 파일 변조를 방지합니다.

#### 보안 위협
비인가자가 /etc/passwd 파일의 사용자 정보를 변조하여 Shell 변경, 사용자 추가/제거 등 root 권한 획득 위험이 존재합니다.

#### 참고
- **/etc/passwd**: 사용자의 ID, UID, GID, 홈 디렉터리, 쉘 정보를 담고 있는 파일

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 소유자가 root이고, 권한이 644 이하인 경우
- **취약**: 소유자가 root가 아니거나, 권한이 644 이하가 아닌 경우

#### 조치 방법 및 영향
- **조치 방법**: /etc/passwd 파일 소유자 및 권한 변경 설정
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - Step 1) `ls -l /etc/passwd`로 파일 소유자 및 권한 확인
  - Step 2) `chown root /etc/passwd`, `chmod 644 /etc/passwd`로 파일 소유자 및 권한 변경

### 시스템 시작 스크립트 권한 설정

#### 개요
시스템 시작 스크립트 파일의 권한 적절성을 점검하여, 비인가자의 임의적인 파일 변조를 방지하고 시스템 침입 등 악용할 위험을 줄입니다.

#### 점검 내용 및 목적
- **점검 내용**: 시스템 시작 스크립트 파일 권한 적절성 여부 점검
- **점검 목적**: 관리자만이 파일을 제어할 수 있게 하여 비인가자의 임의적인 파일 변조를 방지합니다.

#### 보안 위협
비인가자가 스크립트의 내용 변경 등을 통해 시스템 침입 등 악용할 위험이 존재합니다.

#### 참고
- **시스템 시작 스크립트**: 운영체제 부팅 시 자동으로 실행되어 시스템 초기화 작업을 수행하고, 필요한 서비스와 데몬을 시작하는 스크립트

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 소유자가 root이고, 일반 사용자의 쓰기 권한이 제거된 경우
- **취약**: 소유자가 root가 아니거나, 일반 사용자의 쓰기 권한이 부여된 경우

#### 조치 방법 및 영향
- **조치 방법**: 시스템 시작 스크립트 파일 소유자 및 권한 변경 설정
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS**
  - Step 1) `ls -al \`readlink -f /etc/rc*.d/ | sed ‘s/$/*/’\``로 파일 소유자 및 권한 확인
  - Step 2) `chown root <파일 이름>`, `chmod o-w <파일 이름>`로 파일 소유자 및 권한 변경

- **LINUX**
  - [init]
    - Step 1) `ls -al \`readlink -f /etc/rc.d/*/* | sed ‘s/$/*/’\``로 파일 소유자 및 권한 확인
  - [systemd]
    - Step 1) `ls -al \`readlink -f /etc/systemd/system/* | sed ‘s/$/*/’\``로 파일 소유자 및 권한 확인
    - Step 2) `chown root /etc/systemd/system/<파일 이름>`, `chmod o-w /etc/systemd/system/<파일 이름>`로 파일 소유자 및 권한 변경

- **AIX**
  - Step 1) `find /etc/rc.d/*/* -type l -exec ls -l {} +`로 파일 소유자 및 권한 확인
  - Step 2) `chown root <파일 이름>`, `chmod o-w <파일 이름>`로 파일 소유자 및 권한 변경

- **HP-UX**
  - Step 1) `find /sbin/rc*.d/ -type l -exec ls -l {} +`로 파일 소유자 및 권한 확인
  - Step 2) `chown root <파일 이름>`, `chmod o-w <파일 이름>`로 파일 소유자 및 권한 변경

### /etc/shadow 파일 소유자 및 권한 설정

#### 개요
/etc/shadow 파일의 권한 적절성을 점검하여, 비인가자의 임의적인 파일 변조를 방지하고 암호화된 해시값을 복호화하여 비밀번호를 탈취할 위험을 줄입니다.

#### 점검 내용 및 목적
- **점검 내용**: /etc/shadow 파일 권한 적절성 여부 점검
- **점검 목적**: 관리자만이 파일을 제어할 수 있게 하여 비인가자의 임의적인 파일 변조를 방지합니다.

#### 보안 위협
/etc/shadow 파일에 저장된 암호화된 해시값을 복호화하여(크래킹) 비밀번호를 탈취할 위험이 존재합니다.

#### 참고
- **/etc/shadow**: 시스템에 등록된 모든 계정의 비밀번호를 암호화된 형태로 저장 및 관리하는 파일

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 소유자가 root이고, 권한이 400 이하인 경우
- **취약**: 소유자가 root가 아니거나, 권한이 400 이하가 아닌 경우

#### 조치 방법 및 영향
- **조치 방법**: /etc/shadow 파일 소유자 및 권한 변경 설정
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, LINUX**
  - Step 1) `chown root /etc/shadow`, `chmod 400 /etc/shadow`로 파일 소유자 및 권한 변경

- **AIX**
  - Step 1) `chown root /etc/security/passwd`, `chmod 400 /etc/security/passwd`로 파일 소유자 및 권한 변경

- **HP-UX**
  - Step 1) `chown root /tcb/files/auth`, `chmod 400 /tcb/files/auth`로 파일 소유자 및 권한 변경

### /etc/hosts 파일 소유자 및 권한 설정

#### 개요
/etc/hosts 파일의 권한 적절성을 점검하여, 비인가자의 임의적인 파일 변조를 방지하고 파밍(Pharming) 공격 등에 악용될 수 있는 위험을 줄입니다.

#### 점검 내용 및 목적
- **점검 내용**: /etc/hosts 파일의 권한 적절성 여부 점검
- **점검 목적**: 관리자만이 파일을 제어할 수 있게 하여 비인가자의 임의적인 파일 변조를 방지합니다.

#### 보안 위협
/etc/hosts 파일에 쓰기 권한이 부여된 경우, 공격자는 /etc/hosts 파일에 악의적인 시스템을 등록하여 파밍(Pharming) 공격 등에 악용될 수 있습니다.

#### 참고
- **/etc/hosts**: IP주소와 호스트 이름을 매핑하는 파일. DNS보다 먼저 참조됩니다.
- **파밍(Pharming)**: 사용자의 DNS 또는 /etc/hosts 파일을 변조함으로써 정상적인 사이트로 오인하여 접속하도록 유도한 뒤 개인정보를 훔치는 새로운 컴퓨터 범죄 수법

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 소유자가 root이고, 권한이 644 이하인 경우
- **취약**: 소유자가 root가 아니거나, 권한이 644 이하가 아닌 경우

#### 조치 방법 및 영향
- **조치 방법**: /etc/hosts 파일 소유자 및 권한 변경 설정
- **영향**: /etc/hosts 파일에 시스템 정보가 설정된 경우 해당 파일을 참조하는 서비스에 영향을 미칠 수 있음

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - Step 1) `chown root /etc/hosts`, `chmod 644 /etc/hosts`로 파일 소유자 및 권한 변경

### /etc/(x)inetd.conf 파일 소유자 및 권한 설정

#### 개요
/etc/(x)inetd.conf 파일의 권한 적절성을 점검하여, 비인가자의 임의적인 파일 변조를 방지하고 등록된 서비스를 변조하거나 악의적인 프로그램(서비스)을 등록할 수 있는 위험을 줄입니다.

#### 점검 내용 및 목적
- **점검 내용**: /etc/(x)inetd.conf 파일 권한 적절성 여부 점검
- **점검 목적**: 관리자만이 파일을 제어할 수 있게 하여 비인가자의 임의적인 파일 변조를 방지합니다.

#### 보안 위협
/etc/(x)inetd.conf 파일에 쓰기 권한이 부여된 경우, 일반 사용자 권한으로 해당 파일에 등록된 서비스를 변조하거나 악의적인 프로그램(서비스)을 등록할 수 있는 위험이 존재합니다.

#### 참고
- **(x)inetd(슈퍼데몬)**: 자주 사용하지 않는 서비스가 상시 실행되어 메모리를 점유하는 것을 방지하기 위해 (x)inetd(슈퍼데몬)에 자주 사용하지 않는 서비스를 등록하여 요청이 있을 시에만 해당 서비스를 실행하고 요청이 끝나면 서비스를 종료하는 역할 수행

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 소유자가 root이고, 권한이 600 이하인 경우
- **취약**: 소유자가 root가 아니거나, 권한이 600 이하가 아닌 경우

#### 조치 방법 및 영향
- **조치 방법**: /etc/(x)inetd.conf 파일 소유자 및 권한 변경 설정
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, AIX, HP-UX**
  - Step 1) `chown root /etc/inetd.conf`, `chmod 600 /etc/inetd.conf`로 파일 소유자 및 권한 변경

- **LINUX**
  - [inetd]

---

- Step 1) `chown root /etc/inetd.conf`, `chmod 600 /etc/inetd.conf`로 파일 소유자 및 권한 변경
  - [xinetd]
    - Step 1) `chown root /etc/xinetd.conf`, `chmod 600 /etc/xinetd.conf`로 파일 소유자 및 권한 변경
    - Step 2) `chown -R root /etc/xinetd.d/`, `chmod -R 600 /etc/xinetd.d/`로 디렉터리 내 모든 파일의 소유자 및 권한 변경

- **systemd**
  - Step 1) `chown root /etc/systemd/system.conf`, `chmod 600 /etc/systemd/system.conf`로 파일 소유자 및 권한 변경
  - Step 2) `chown -R root /etc/systemd/`, `chmod -R 600 /etc/systemd/`로 디렉터리 내 모든 파일의 소유자 및 권한 변경
