# 7-1. DBMS 계정 관리와 접근 통제

#### 조치 방법
- **조치 방법**: 하나의 OS만 설치하여 운영함
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: 인터넷 제어판에서 설정 확인 (`gpedit.msc`)
  - **Step 2**: 설정 변경

### 주기적 보안 패치 적용

#### 개요
- **점검 내용**: 시스템에 관련한 공개된 취약점에 대한 최신 보안패치를 적용하였는지 점검
- **점검 목적**: 침해사고 발생 방지

#### 참고
- **Hot Fix**: 즉시 교정되어야만 하는 주요한 취약점을 패치로 배포하는 프로그램
- **업데이트 (Update)**: 문제를 예방 또는 해결하거나 컴퓨터 작동 방식을 향상시키는 소프트웨어

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: HOT FIX 설치 및 자동 업데이트 설정이 되어 있고 내부적으로 관리 절차를 수립하여 이행한 경우
- **취약**: HOT FIX 설치되어 있지 않거나 내부적으로 관리 절차가 수립되지 않은 경우

#### 조치 방법
- **조치 방법**: Windows Update 사이트에 접속하여 최신 패치 존재 여부 확인 및 패치 적용
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: 인터넷에 연결되는 경우 Windows Update 사이트에 접속하여 최신 패치 존재 여부 확인
  - **Step 2**: HOT FIX, 최신 보안 업데이트 설치 여부 확인 및 설정 변경

### 지원이 종료되지 않은 Windows OS Build 적용

#### 개요
- **점검 내용**: 시스템에 최신 서비스팩이 적용 여부 점검
- **점검 목적**: 공격(익스플로잇)에 대비하여 시스템 취약점을 이용한 공격에 노출되지 않도록 확인

#### 참고
- **서비스 팩 (Service Pack)**: 운영체제 응용프로그램의 기능 추가 및 버그나 보안 취약점을 해결한 패치 파일을 단일 묶음으로 배포하는 패키지
- **익스플로잇 (Exploit)**: 컴퓨터의 소프트웨어나 하드웨어 또는 컴퓨터 관련 전자 제품의 버그, 보안 취약점 등 설계상 결함을 이용해 공격자의 의도된 동작을 수행하도록 만들어진 프로그램

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: 최신 빌드가 적용되어 있고 내부적으로 관리 절차를 수립하여 이행한 경우
- **취약**: 최신 빌드가 적용되어 있지 않거나 내부적으로 관리 절차가 수립되지 않은 경우

#### 조치 방법
- **조치 방법**: Windows Update 사이트에 접속하여 최신 서비스팩 여부 확인 및 적용
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: HOT FIX 패치를 통해 업데이트 (`https://www.microsoft.com/ko-kr/software-download/windows10`, `https://www.microsoft.com/ko-kr/software-download/windows11`)
  - **Step 2**: 네트워크 단절 후 서비스팩 설치 및 업데이트 진행 권장

### Windows 자동 로그인 점검

#### 개요
- **점검 내용**: Windows 자동 로그인이 비활성화 여부 점검
- **점검 목적**: 비인가자의 로그인을 방지하기 위함
- **보안 위협**: 자동 로그인이 활성화되어 있을 때, 비인가자가 별도의 로그인 과정 없이 계정에 접근할 수 있는 위험이 존재

#### 참고
- **Windows 자동 로그인**: 사용자 이름이나 비밀번호를 입력하지 않고 Windows에 로그인할 수 있음.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: Windows 자동 로그인이 비활성화된 경우
- **취약**: Windows 자동 로그인이 활성화된 경우

#### 조치 방법
- **Windows 자동 로그인 비활성화 설정**
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: 레지스트리 값 확인 (`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon > AutoAdminLogon`)
    - **AutoAdminLogon**이 존재하지 않으면 양호.
  - **Step 2**: `AutoAdminLogon` 문자열 값 생성 및 데이터 `0` 입력.

### 바이러스 백신 프로그램 설치 및 주기적 업데이트

#### 개요
- **점검 내용**: 시스템에 백신이 설치되어 있고, 백신이 주기적으로 자동 업데이트되는 설정 여부 점검
- **점검 목적**: 악성코드 감염을 대비하기 위함
- **보안 위협**: 백신이 설치되지 않았거나, 최신 업데이트가 이루어지지 않은 경우 악성코드의 감염으로 인한 시스템 중요 파일이나 폴더의 유출 및 삭제 위험이 존재

#### 참고
- **바이러스(Virus)**: 자신을 복제하려는 명백한 의도를 갖고 만들어진 코드, 호스트 프로그램에 침투하여 컴퓨터 사이에서 확산.
- **웜(Worm)**: 바이러스와 비슷하지만 독자적으로 실행되며 통신망 등을 통해 널리 퍼지는 부정 프로그램.
- **랜섬웨어**: 사용자 파일을 암호화하여 접근을 제한하고 복호화 비용을 요구하는 악성 소프트웨어.
- **스파이웨어**: 사용자의 동의 없이 설치되어 컴퓨터의 정보를 수집하고 전송하는 악성 소프트웨어.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: 백신이 설치되어 있고, 최신 업데이트가 적용된 경우
- **취약**: 백신이 설치되어 있지 않거나, 최신 업데이트가 적용되지 않은 경우

#### 조치 방법
- **바이러스 백신 설치 및 최신 업데이트 적용**
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11 (Windows Defender 사용 예시)**
  - **Step 1**: `시작 > 설정 > 개인 정보 및 보안 > Windows 보안 > 바이러스 및 위협 방지 > 바이러스 및 위협 방지 설정 > 보호 업데이트 > 업데이트 확인`.

### 바이러스 백신 프로그램에서 제공하는 실시간 감시 기능 활성화

#### 개요
- **점검 내용**: 시스템에 설치된 백신 프로그램의 환경 설정에 실시간 감시기능 적용 여부 점검
- **점검 목적**: 악성코드 감염을 실시간으로 점검하고 있는지 확인하기 위함
- **보안 위협**: 실시간 감시기능이 비활성화된 경우, 악성코드에 대해 실시간 감지가 이루어지지 않아 시스템 사용자가 인터넷을 통한 파일 다운로드나 실행 시 악성코드가 감염될 위험이 존재

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: 설치된 백신의 실시간 감시기능이 활성화된 경우
- **취약**: 백신이 설치되어 있지 않거나 실시간 감시기능이 비활성화된 경우

#### 조치 방법
- **바이러스 백신 실시간 감시 기능 설정**
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: `시작 > 모든 앱 > Windows 보안 > 바이러스 및 위협 방지 > 설정 관리 > 실시간 보호 기능 활성화`.

### OS에서 제공하는 침입차단 기능 활성화

#### 개요
- **점검 내용**: 시스템의 방화벽 기능이 활성화 여부 점검
- **점검 목적**: 외부망의 비인가 접근 및 통신을 통제하고 있는지 확인하기 위함
- **보안 위협**: 방화벽 기능이 비활성화되어 있으면, 외부 및 내부의 접근통제가 되지 않아 유해 정보가 유입되거나 시스템 사용자의 파일이나 폴더가 외부로 유출될 위험이 존재

#### 참고
- **방화벽**: 인터넷 또는 외부 네트워크에서 유입되는 트래픽을 통제하는 솔루션으로써 외부의 불법 침입으로부터 내부의 정보 자산을 보호하고 외부로부터 유해 정보 유입을 차단하기 위한 정책과 이를 지원하는 하드웨어와 소프트웨어를 총칭함.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: Windows 방화벽 “사용”으로 설정된 경우 또는 유·무료 기타 방화벽을 사용한 경우
- **취약**: Windows 방화벽 “사용 안 함”으로 설정된 경우 또는 유·무료 기타 방화벽을 사용하지 않은 경우

#### 조치 방법
- **Windows 방화벽 “사용”으로 설정 또는 유·무료 기타 방화벽을 사용**
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: `제어판 > 시스템 및 보안 > Windows Defender 방화벽 > Windows 방화벽 설정 또는 해제`.
  - **Step 2**: `Windows Defender 방화벽 “사용” 설정`.

### 화면보호기 대기 시간 설정 및 재시작 시 암호 보호 설정

#### 개요
- **점검 내용**: 화면보호기 대기 시간 및 화면보호기 재시작 시 비밀번호 설정 여부 점검
- **점검 목적**: 사용자가 일정 시간 동안 아무런 작업을 수행하지 않을 경우, 자동으로 로그오프 되거나 워크스테이션이 잠기도록 하기 위함
- **보안 위협**: 화면보호기가 작동하지 않거나 재시작 시 비밀번호를 설정하지 않는다면, 사용자가 자리를 비운 사이 임의의 사용자가 해당 시스템에 접근하여 중요 정보를 유출하거나, 악의적인 행위를 통해 시스템 운영에 악영향을 미칠 수 있는 위험이 존재

#### 참고
- **악의적인 행위**: 시스템 파일 또는 시스템 폴더 삭제, 응용프로그램 폴더 삭제 등.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호**: 화면보호기 설정(대기 시간 10분 이하) 및 비밀번호로 보호가 설정된 경우
- **취약**: 화면보호기 설정(대기 시간 10분 초과) 및 비밀번호로 보호가 설정되지 않은 경우

#### 조치 방법
- **화면보호기 설정 및 비밀번호 보호 설정**
- **영향**: 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **Windows 10, Windows 11**
  - **Step 1**: `시작 > 설정 > 개인설정 > 잠금화면 > 화면보호기`.

### 이동식 미디어 보안 대책

#### 개요
- **점검 내용**: 이동식 미디어(USB, CD/DVD 등)의 자동 실행 방지 여부를 점검합니다.
- **점검 목적**: 미디어 연결 시 자동 실행을 차단하여 바이러스 감염과 정보 유출 위험을 줄입니다.

#### 보안 위협
- **자동 실행 파일(Autorun.inf)**: 이 파일은 미디어 연결 시 특정 프로그램을 자동으로 실행할 수 있습니다.
- **응용 프로그램**: 사용자에게 피해를 일으킬 수 있는 악성코드들이 `autorun.inf` 파일을 통해 자동 실행되도록 설계되어 있습니다.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호 상태**: 미디어 사용 시 자동 실행되지 않고 내부적으로 관리 절차를 수립하여 이행된 경우.
- **취약 상태**: 미디어 사용 시 자동 실행되거나 내부적으로 관리 절차가 수립되지 않은 경우.

#### 조치 방법
- **미디어 자동 실행 방지 설정**:
  - **로컬 그룹 정책 편집기**:
    ```
    시작 > 파일 탐색기 > 내 PC > 로컬 디스크 (C:) > Windows > System32 > gpedit > 컴퓨터 구성 > 관리 템플릿 > Windows 구성 요소 > 자동 실행 정책
    "자동 실행 끄기" 정책을 "사용 모든 드라이브"로 설정.
    ```
  - **제어판에서 자동 실행 기능 설정**:
    ```
    시작 > 모든 앱 > Windows Tools > 제어판 > 하드웨어 및 소리 > 자동 실행 > “모든 미디어 및 장치에 자동 실행 사용(U)” 체크 해제 > 저장(S).
    ```

#### 조치 시 영향
- **일반적인 경우**: 영향 없음.

### 원격 지원 정책

#### 개요
- **점검 내용**: 원격 지원 기능이 비활성화되어 있는지 점검합니다.
- **점검 목적**: 비인가자에게 원격에서의 접근을 방지하여 시스템 제어 권한이 악용되는 위험을 줄입니다.

#### 보안 위협
- **원격 지원 기능 활성화**: 비인가자가 원격에서의 접근이 허용될 경우, 시스템 제어 권한이 악용될 수 있는 위험이 존재합니다.

#### 점검 대상 및 판단 기준
- **대상**: Windows 10, Windows 11
- **양호 상태**: 원격 지원이 “사용 안 함”으로 설정된 경우.
- **취약 상태**: 원격 지원이 “사용”으로 설정된 경우.

#### 조치 방법
- **원격 지원 서비스 비활성화**:
  ```
  시작 > 파일 탐색기 > 내 PC > 로컬 디스크 (C:) > Windows > System32 > gpedit > 컴퓨터 구성 > 관리 템플릿 > 시스템 > 원격 지원 제공 구성
  “원격 지원 제공”을 “사용 안 함”으로 설정.
  ```

#### 조치 시 영향
- **원격 지원 기능 사용 불가**.

### DBMS 계정 관리

#### 개요
- **점검 내용**: DBMS 기본 계정의 초기 비밀번호 및 권한 정책을 변경하여 사용하는지 점검합니다.
- **점검 목적**: 비인가자의 초기 비밀번호를 획득하여 DB 정보를 유출할 수 있는 위험을 차단하기 위함.

#### 보안 위협
- **기본 계정 초기 비밀번호 및 권한 정책 변경**: 기본 계정의 초기 비밀번호 및 권한 정책을 변경하지 않을 경우, 비인가자가 인터넷 통해 DBMS 기본 계정의 초기 비밀번호를 획득하여 기본 계정에 부여된 권한의 취약점을 이용하여 DB 정보를 유출할 수 있는 위험이 존재합니다.

#### 점검 대상 및 판단 기준
- **대상**: Oracle DB, MSSQL, MySQL, Altibase, Tibero, PostgreSQL, Cubrid 등
- **양호 상태**: 기본 계정의 초기 비밀번호를 변경하거나 잠금설정한 경우.
- **취약 상태**: 기본 계정의 초기 비밀번호를 변경하지 않거나 잠금설정을 하지 않은 경우.

#### 조치 방법
- **기본(관리자) 계정의 초기 비밀번호 및 권한 정책 변경**:
  ```
  SQL> SELECT USERNAME, ACCOUNT_STATUS, PROFILE FROM DBA_USERS;
  SQL> ALTER USER <기본 계정명> IDENTIFIED BY <신규 비밀번호>;
  ```

#### 조치 시 영향
- **불필요한 기본 계정의 사용 제한**.

    - `ALTER ROLE <계정명> NOREPLICATION;`

#### Cubrid

### 계정 관리

#### 비밀번호 관리 정책 설정
- **비밀번호 복잡성 및 길이**
  - SHA-256 이상의 암호화 알고리즘 사용 (Oracle DB, MSSQL, MySQL, Tibero, PostgreSQL 등)
  - 예: OracleDB에서 `SELECT username, password_versions FROM dba_users;`로 확인 가능.
  
- **변경 주기**
  - 최소 사용 기간, 최대 사용 기간 설정
  - 최근 비밀번호 기억

#### 점검 내용
- DBMS 설정 중 일정 횟수의 로그인 실패 시 계정 잠금 정책 설정 (Oracle DB, Altibase, Tibero 등)
  - 예: Oracle DB에서 `ALTER PROFILE LIMIT FAILED_LOGIN_ATTEMPTS XX;`로 설정 가능.

#### 점검 목적
- 데이터의 기밀성 및 무결성을 보장하고, 사용자 인증을 강화.
- 로그인 시도 횟수를 제한하여 비인가자의 자동화된 무차별 대입 공격 방지.

#### 보안 위협
- 오래된 해시 알고리즘 (SHA-1, MD5) 사용 시 공격자에게 비밀번호 유추의 위험이 존재.
- 로그인 시도 횟수를 제한하지 않을 경우 자동화된 방법으로 계정 및 비밀번호를 획득하여 정보가 유출될 위험이 존재.

#### 참고
- 각 DBMS에서 사용하는 암호화 알고리즘 (Oracle 10G: MD5, 11G: SHA-1, 12C: SHA-512, AES)
- MySQL 8.0 이상부터 `caching_sha2_password` 알고리즘이 기본 적용.

### 점검 대상 및 판단 기준
- **대상**
  - Oracle DB, MSSQL, MySQL, Tibero, PostgreSQL 등

- **판단 기준**
  - 해시 알고리즘 SHA-256 이상 사용 여부
  - 로그인 시도 횟수를 제한하는 값 설정 여부

### 조치 방법
- **최소 사용 기간, 최대 사용 기간**
  - Altibase: `ALTER USER 계정명 LIMIT (Property 숫자);`
  - PostgreSQL: `CREATE PROFILE prof LIMIT;`

- **로그인 시도 횟수 제한**
  - Oracle DB: `ALTER PROFILE LIMIT FAILED_LOGIN_ATTEMPTS XX;`
  - Altibase, Tibero: 각각의 Property에 대해 비밀번호 정책 설정.

### 영향
- 일반적인 경우 영향 없음.

### 접근 관리

  - `postgres.conf`와 `pg_hba.conf` 파일 설정 (`listen_addresses`, `TYPE DATABASE USER CIDR-ADDRESS METHOD`).

### PostgreSQL 설정 파일 권한 확인 및 설정

#### 주요 설정 파일 위치
- `postgresql.conf` 파일: `[$datadir]`
- DB 접속 통제 설정 파일: `/postgres/data/pg_hba.conf`, `/postgres/data/pg_ident.conf`
- 로그 디렉토리: `/log_directory/pg_log`

#### 권한 설정
- `postgresql.conf`: 640 이하로 설정 (`# chmod 640 [$datadir]/postgresql.conf`)
- `pg_hba.conf`, `pg_ident.conf`: 640 이하로 설정 (`# chmod 640 ./pg_hba.conf`, `# chmod 640 ./pg_ident.conf`)
- `.psql_history` 파일: 600 이하로 설정 (`$chmod 600 .psql_history`)
- `pg_log`: 640 이하로 설정 (`#chmod 640 [Log 파일]`)

### Oracle DB 리스너 설정 파일 권한 및 변경 방지

#### 개요
- Listener 관련 설정 파일의 접근 권한을 관리자만 가능하게 하고, 파라미터 변경 방지를 위해 옵션 설정.

#### 점검 내용
- Listener 설정 파일 및 파라미터 변경 방지 옵션 설정 여부 확인.

#### 점검 목적
- Trace 파일 및 Listener 로그의 신뢰도 유지.
- 비인가자가 Listener를 이용한 파라미터 변경을 방지하여 trace 파일이나 Listener 로그 파일을 변경할 위험이 없음.

#### 보안 위협
- Listener의 모든 파라미터를 변경할 수 있어 trace 파일이나 Listener 로그 파일이 변경될 위험 존재.
  
#### 점검 대상 및 판단 기준
- 대상: Oracle DB
- 양호: 권한이 관리자로 설정되어 있고, Listener로 파라미터를 변경할 수 없게 옵션이 설정된 경우.
- 취약: 권한이 일반 사용자로 설정되어 있고, Listener로 파라미터를 변경할 수 없게 옵션이 설정되지 않은 경우.

#### 조치 방법
- 주요 파일 및 로그 파일에 대한 권한을 관리자로 제한.

#### 점검 및 조치 사례
- `ls –a` 또는 파일 속성 확인.
- `listener.ora` 파일에서 `ADMIN_RESTRICTIONS_<listener name> = ON` 설정 확인.

#### 개요
- DB 로그인 시 Windows 인증 모드 적절성 점검.

#### 점검 내용
- DB 로그인 시 Windows 인증 모드 적절성 점검.

#### 점검 목적
- 적절한 Windows 인증 모드를 적용하여 복잡성 수준 유지.
  
#### 보안 위협
- 혼합 인증 모드와 sa 계정 활성화 시, 잘 알려진 sa 계정에 대한 공격의 위험이 존재.

#### 참고
- `sa` 계정: DB 서버 관리자 계정.
- Kerberos 보안 프로토콜: 강력한 암호 정책을 적용하여 복잡성 수준 유지.

#### 점검 대상 및 판단 기준
- 대상: MSSQL
- 양호: Windows 인증 모드를 사용하고 sa 계정이 비활성화되어 있는 경우.
- 취약: 혼합 인증 모드를 사용하고, 활성화된 sa 계정에 대한 강력한 암호 정책 설정을 하지 않은 경우.

#### 조치 방법
- Windows 인증 모드 사용.

#### 점검 및 조치 사례
- SQL Server Management Studio에서 서버 속성 > 보안 > 서버 인증 > Windows 인증 모드(W) 활성화.

### Audit Table 접근 권한 제한

#### 개요
- Audit Table의 접근 권한이 관리자 계정으로 제한되어 있는지 점검.
  
#### 점검 내용
- Audit Table 접근 권한이 관리자 계정으로 제한되고 있는지 점검.

#### 점검 목적
- 비인가자가 감사 데이터를 수정, 삭제하는 것을 방지하고, 감사 기록의 무결성과 신뢰성을 보장.
  
#### 보안 위협
- 비인가자가 감사 데이터를 수정, 삭제할 수 있어 원인 분석이 불가능해 재발 방지를 위한 조치를 할 수 없음.

#### 점검 대상 및 판단 기준
- 대상: Oracle DB, Altibase, Tibero 등
- 양호: Audit Table 접근 권한이 관리자 계정으로 설정된 경우.
- 취약: Audit Table 접근 권한이 일반 계정으로 설정된 경우.

#### 조치 방법
- Audit Table 접근 권한을 관리자 계정으로 제한.

#### 점검 및 조치 사례
- Oracle DB, Tibero: `SELECT owner FROM dba_tables WHERE table_name = 'AUD$';`
- Altibase: `SELECT * FROM system_.sys_users_;`, `SELECT * FROM system_.sys_tables_;`

### 응용 프로그램 또는 DBA 계정의 Role 조정

#### 개요
- 응용 프로그램 또는 DBA 계정의 Role이 Public으로 설정되어 있는지 점검.
  
#### 점검 내용
- 응용 프로그램 또는 DBA 계정의 Role이 Public으로 설정되어 있는지 점검.

#### 점검 목적
- 일반 계정으로 응용 프로그램 테이블이나 DBA 테이블의 접근을 차단.
  
#### 보안 위협
- 중요 정보 유출의 위험이 존재.

#### 참고
- Role: 사용자에게 허가할 수 있는 권한들의 집합.

#### 점검 대상 및 판단 기준
- 대상: Oracle DB, Altibase, Tibero, Cubrid 등
- 양호: DBA 계정의 Role이 Public으로 설정되지 않은 경우.
- 취약: DBA 계정의 Role이 Public으로 설정된 경우.

#### 조치 방법
- DBA 계정의 Role 설정에서 Public 그룹 권한 취소.

#### 점검 및 조치 사례
- Oracle DB: `SELECT granted_role FROM dba_role_privs WHERE grantee = 'PUBLIC';`, `REVOKE [Role name] FROM PUBLIC;`
- Altibase: `SELECT * FROM system_.sys_users_;`, `SELECT * FROM system_.sys_grant_object_;`, `SELECT * FROM system_.sys_grant_system_;`

### DBMS 옵션 관리

#### 1. OS_ROLES, REMOTE_OS_AUTHENTICATION, REMOTE_OS_ROLES 설정
- **개요**: Oracle DB에서 OS_ROLES, REMOTE_OS_AUTHENTICATION, REMOTE_OS_ROLES를 FALSE로 설정하는 것이 권장됩니다.
- **점검 내용 및 목적**:
  - 점검 내용: 해당 설정이 FALSE로 적용되어 있는지 확인합니다.
  - 점검 목적: 비인가자들의 데이터베이스 접근을 막고, 데이터베이스 관리자에 의한 사용자 Role 설정이 가능하게 합니다.
- **보안 위협**:
  - OS_ROLES가 TRUE로 설정된 경우, OS 그룹에 의해 GRANT 된 권한이 허락되어 악의적인 사용자가 시스템 권한을 악용할 위험이 존재합니다.
  - REMOTE_OS_ROLES가 TRUE로 설정된 경우, 원격 사용자가 OS의 다른 사용자로 속여 데이터베이스에 접근할 수 있으므로 중요 정보에 대한 무단 접근 및 권한 상승의 위험이 존재합니다.
  - REMOTE_OS_AUTHENT가 TRUE로 설정된 경우, 신뢰하는 원격 호스트에서 인증 절차 없이 데이터베이스에 접속할 수 있으므로 중요 정보의 유출 위험이 존재합니다.
- **참고**:
  - OS_ROLES: OS 그룹에 의한 사용자의 롤 부여를 가능하게 하도록 설정
  - REMOTE_OS_AUTHENT: 원격지의 OS 인증 허용 여부를 설정
  - REMOTE_OS_ROLES: OS가 원격 클라이언트에 대한 롤의 지정이 가능하도록 설정

- **대상**: Oracle DB
- **판단 기준**:

  - 취약: 해당 설정이 TRUE로 설정되지 않은 경우
