# 3-1. 웹 서버(WAS) 설정 보안

#### 참고
- NTFS, FAT 파일 시스템 비교: NTFS는 보안 기능이 더 강화되어 컴퓨터에 액세스 가능한 모든 사용자가 파일을 읽을 수 있음.

#### 점검 대상 및 판단 기준
- **대상**: Windows NT, 2000, 2003, 2008, 2012, 2016, 2019, 2022.
- **양호**: NTFS 파일 시스템을 사용하는 경우.
- **취약**: FAT 파일 시스템을 사용하는 경우.

#### 조치 방법
- FAT 파일 시스템을 NTFS로 변환 설정.

#### 조치 시 영향
- 파일 시스템을 변환할 경우 기존 파일 시스템에 영향을 줄 수 있음.

#### 점검 및 조치 사례
- **Windows NT, 2000, 2003, 2008, 2012, 2016, 2019, 2022**: CMD를 통해 FAT 파일 시스템을 NTFS로 변환.

### 시작 프로그램 목록 분석

#### 개요
- **점검 내용**: 시작 프로그램 목록 내 불필요한 항목 존재 여부 점검.
- **점검 목적**: 악의적인 공격을 차단하기 위함.

#### 보안 위협
- 공격자가 심어놓은 악성 프로그램이나 해킹 도구가 실행되어 시스템에 피해를 줄 위험이 존재함.

#### 점검 대상 및 판단 기준
- **대상**: Windows 2000, 2003, 2008, 2012, 2016, 2019, 2022.
- **양호**: 시작 프로그램 목록을 정기적으로 검사하고 불필요한 서비스를 비활성화한 경우.
- **취약**: 정기적인 검사를 하지 않고 부팅 시 불필요한 서비스도 실행되고 있는 경우.

#### 조치 방법
- 시작 프로그램 목록의 정기적인 검사 실시 및 불필요한 서비스 비활성화 설정.

#### 조치 시 영향
- 일반적으로 영향 없음.

#### 점검 및 조치 사례
- **Windows 2000, 2003, 2008**: msconfig를 통해 시작 프로그램 목록을 확인하고 불필요한 항목을 비활성화.
- **Windows 2012, 2016, 2019, 2022**: 시작 프로그램 편집이 불가능하므로 레지스트리 값을 통해 설정.

### 도메인 컨트롤러-사용자의 시간 동기화

#### 개요
- **점검 내용**: 도메인 컨트롤러와 사용자의 시간 동기화 여부 점검.
- **점검 목적**: Kerberos가 클라이언트 시계의 시간과 서버 시계의 시간 사이에서 허용되는 최대 시간 차이(분)를 결정하는 동시에 두 시계의 동기를 고려하여 재전송 공격을 방지하기 위함.

#### 보안 위협
- Replay Attack 이란 프로토콜 상 메시지를 복사한 후 재전송함으로써 승인된 사용자로 오인하게 만들어 내부 침입 및 정보 유출 위험이 존재함.

#### 점검 대상 및 판단 기준
- **대상**: Windows 2012, 2016, 2019, 2022.
- **양호**: 컴퓨터 시계 동기화 최대 허용 오차값이 5분 이하인 경우.
- **취약**: 최대 허용 오차값이 5분 초과인 경우.

#### 조치 방법
- Kerberos 사용 시 컴퓨터 시계 동기화 최대 허용 오차값을 5분 이하로 설정.

#### 조치 시 영향
- 일반적으로 영향 없음.

#### 점검 및 조치 사례
- **Windows 2012, 2016, 2019, 2022**: 로컬 보안 정책에서 Kerberos 정책을 확인하고 최대 허용 오차값을 5분으로 설정.

### 윈도우 방화벽 설정

#### 개요
- **점검 내용**: 시스템의 방화벽 기능이 활성화되어 있는지 점검.
- **점검 목적**: 프로그램에 대해 통제하고 있는지 확인하기 위함.

#### 보안 위협
- 방화벽 기능이 비활성화되어 있으면, 외부 및 내부의 접근통제가 되지 않아 유해 정보가 유입되거나 시스템 사용자의 파일이나 폴더가 외부로 유출될 위험이 존재함.

#### 참고
- 방화벽: 인터넷 또는 외부 네트워크에서 유입되는 트래픽을 통제하는 솔루션으로써 외부의 불법 침입으로부터 내부의 정보 자산을 보호하고 외부로부터 유해 정보 유입을 차단하기 위한 정책과 이를 지원하는 하드웨어와 소프트웨어를 총칭함.

#### 점검 대상 및 판단 기준
- **대상**: Windows 2000, 2003, 2008, 2012, 2016, 2019, 2022.
- **양호**: Windows 방화벽 "사용"으로 설정된 경우.
- **취약**: "사용 안 함"으로 설정된 경우.

#### 조치 방법
- Windows 방화벽을 "사용"으로 설정.

#### 조치 시 영향
- 일반적으로 영향 없음.

#### 점검 및 조치 사례
- **Windows 2000, 2003, 2008, 2012, 2016, 2019, 2022**: Windows Defender 방화벽 설정을 확인하고 "사용"으로 설정.

### 계정 관리

#### Default 관리자 계정명 변경 (WEB-01)
- **개요**: 웹 서비스 설치 시 기본적으로 설정된 관리자 계정의 변경 후 사용 여부를 점검합니다.
- **점검 내용**: 기본 관리자 계정명과 같은 알려진 계정명을 유추하기 어려운 계정명으로 변경 후 사용하는지 확인합니다.
- **점검 목적**: 공격자에 의한 추측 공격 및 무단 접근 등을 방지하고 보안을 강화하기 위함입니다.
- **보안 위협**: 기본 관리자 계정명을 변경하지 않고 사용할 경우, 공격자에 의한 불법적인 접근, 데이터 유출, 시스템 장애 등의 보안 사고가 발생할 수 있습니다.
  - **기본 계정**: IIS(Administrator), Tomcat(tomcat, admin), JEUS(administrator)
- **점검 대상 및 판단 기준**:
  - **대상**: Tomcat, JEUS
  - **양호**: 관리자 페이지를 사용하지 않거나, 계정명이 기본 계정명으로 설정되어 있지 않은 경우
  - **취약**: 계정명이 기본 계정명으로 설정되어 있거나, 추측하기 쉬운 문자 조합으로 이루어진 계정명을 사용하는 경우
- **조치 방법**: 기본 관리자 계정명을 추측하기 어려운 계정명으로 설정합니다.
- **영향**: 일반적인 경우 영향 없음.
- **점검 및 조치 사례**:
  - **Tomcat**
    - Step 1) 기본 계정명 변경 또는 관리자 페이지 비활성화
      ```bash
      # vi <Tomcat 설치 디렉터리>/conf/server.xml
      예시) <user username="admin" password="XNDJxndn264!@" roles="manager-gui"/>
      ```
    - Step 2) Tomcat 재구동
      ```bash
      # systemctl restart tomcat
      ```
  - **JEUS**
    - Step 1) 기본 관리자 계정의 Name 확인 및 변경
      ```bash
      # ./stopServer –host [도메인명]:[포트 번호]
      # ./startDomainAdminServer –host [도메인명]:[포트 번호]
      ```

#### 취약한 비밀번호 사용 제한 (WEB-02)
- **개요**: 관리자 계정의 취약한 비밀번호 설정 여부를 점검합니다.
- **점검 내용**: 관리자 계정의 비밀번호가 복잡도 기준에 맞게 적용되어 있는지 확인합니다.
- **점검 목적**: 비인가자에 의한 비밀번호 유추 공격 및 관리자 권한 탈취 등을 방지하기 위함입니다.
- **보안 위협**: 관리자 계정의 비밀번호를 취약하게 설정하여 사용하는 경우, 비인가자의 비밀번호 유추 공격으로 관리자 권한 탈취 및 시스템 침입 등의 위험이 존재합니다.
- **점검 대상 및 판단 기준**:
  - **대상**: Tomcat, IIS, JEUS
  - **양호**: 관리자 비밀번호가 암호화되어 있거나, 유추하기 어려운 비밀번호로 설정된 경우
  - **취약**: 관리자 비밀번호가 암호화되어 있지 않거나, 유추하기 쉬운 비밀번호로 설정된 경우
- **조치 방법**: 복잡도 기준에 맞는 추측하기 어려운 비밀번호를 설정합니다.
- **영향**: 일반적인 경우 영향 없음.
- **점검 및 조치 사례**:
  - **Tomcat**
    - Step 1) 복잡도를 만족하는 비밀번호 설정
      ```bash
      # vi <Tomcat 설치 디렉터리>/conf/server.xml
      <user username="admin" password="XNDJxndn264!@" roles="manager-gui"/>
      ```
    - Step 2) Tomcat 재시작
      ```bash
      # systemctl restart tomcat
      ```
  - **JEUS**
    - Step 1) 기본 관리자 계정의 비밀번호 변경
      ```bash
      # ./stopServer –host [도메인명]:[포트 번호]
      # ./startDomainAdminServer –host [도메인명]:[포트 번호]
      ```

#### 비밀번호 파일 권한 관리 (WEB-03)
- **개요**: 비밀번호 파일에 대해 적절한 접근 권한 설정 여부를 점검합니다.
- **점검 내용**: 비밀번호 파일의 접근 권한을 적절하게 설정하여 비인가자가 비밀번호 파일에 무단 접근 및 유출 등을 방지하기 위함입니다.
- **점검 목적**: 비밀번호 파일의 권한을 적절하게 설정하지 않은 경우, 비인가자에게 비밀번호 정보가 노출될 수 있고 웹 서버에 접속하는 등의 침해사고가 발생할 위험이 존재합니다.
- **점검 대상 및 판단 기준**:
  - **대상**: Tomcat, IIS, JEUS
  - **양호**: 비밀번호 파일에 권한이 600 이하로 설정된 경우
  - **취약**: 비밀번호 파일에 권한이 600 초과로 설정된 경우
- **조치 방법**: 비밀번호 파일 권한을 600 이하로 설정합니다.
- **영향**: 일반적인 경우 영향 없음.
- **점검 및 조치 사례**:
  - **Tomcat**
    - Step 1) tomcat-users.xml 파일 권한 변경
      ```bash
      # chmod 600 /<Tomcat 설치 디렉터리>/tomcat-users.xml
      ```
  - **IIS**
    - Step 1) SAM 파일 속성 > 보안 > 편집 > Administrators, SYSTEM을 제외한 계정 및 그룹 권한 제거

### 서비스 관리

#### 웹 서비스 디렉터리 리스팅 방지 설정 (WEB-04)
- **개요**: 디렉터리 리스팅 기능 차단 여부를 점검합니다.
- **점검 내용**: 웹 서버에 대한 디렉터리 리스팅 기능을 차단하여 디렉터리 내의 모든 파일에 대한 접근 및 정보 노출을 차단하기 위함입니다.
- **점검 목적**: 디렉터리 리스팅 기능이 차단되지 않은 경우, 비인가자가 해당 디렉터리 내의 모든 파일의 리스트 확인 및 접근이 가능하고, 웹 서버의 구조 및 백업 파일이나 소스 파일 등 공개되면 안 되는 중요 파일들이 노출될 위험이 존재합니다.
- **점검 대상 및 판단 기준**:
  - **대상**: Apache, Tomcat, Nginx, IIS, JEUS, WebtoB
  - **양호**: 디렉터리 리스팅이 설정되지 않은 경우
  - **취약**: 디렉터리 리스팅이 설정된 경우
- **조치 방법**: 디렉터리 리스팅 기능 차단을 설정합니다.
- **영향**: 일반적인 경우 영향 없음.
- **점검 및 조치 사례**:
  - **Apache**
    - Step 1) httpd.conf 파일 내 모든 디렉터리의 Options 지시자에서 Indexes 옵션 제거
      ```bash
      # vi /<Apache 설치 디렉터리>/httpd.conf(또는 apache.conf)
      <Directory />
      Options Indexes 삭제 (또는 –Indexes 설정)
      </Directory>
      ```
    - Step 2) Apache 재시작
      ```bash
      # systemctl restart apache2
      ```
  - **Tomcat**
    - Step 1) web.xml 파일 내 listings 옵션 비활성화
      ```bash
      # vi /<Tomcat 설치 디렉터리>/web.xml
      <init-param>
      <param-name>listings</param-name>
      <param-value>false</param-value>
      </init-param>
      ```
  - **Nginx**
    - Step 1) nginx.conf 파일 내 autoindex 지시자 off 설정
      ```bash
      # vi /<Nginx 설치 디렉터리>/conf/nginx.conf
      server {
      autoindex off;
      }
      ```
    - Step 2) Nginx 재시작
      ```bash
      # systemctl restart nginx
      ```
  - **IIS**
    - 시작 > Windows 관리 도구 > 인터넷 정보 서비스(IIS) 관리자 > 해당 웹 사이트 > IIS > 디렉터리 검색 선택, 사용”을 “사용 안 함”으로 설정

이 청크는 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드에서 웹 서비스의 계정 관리와 서비스 관리에 대한 내용을 포함하고 있습니다. 각 항목별로 점검 내용, 목적, 대상, 판단 기준, 조치 방법, 그리고 사례를 구체적으로 설명하고 있습니다.

### 주요 정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드

#### 1. 웹 서비스 > 2. 서비스 관리
- **(상) 지정하지 않은 CGI/ISAPI 실행 제한**
  - **개요**: 웹 서비스의 CGI 스크립트를 정해진 디렉터리에서만 실행되도록 설정하여 악의적인 파일 업로드 및 실행을 방지.
  - **점검 내용**: CGI 스크립트가 정해진 디렉터리 내에서만 실행되는지 확인.
  - **점검 목적**: 보안 위협으로부터 시스템의 중요 정보를 보호하고, 침해사고 경로를 줄이기 위함.
  - **보안 위협**: 악의적인 파일을 업로드하여 시스템의 중요 정보가 노출될 수 있음.
  - **참고**: CGI(Common Gateway Interface)는 사용자가 서버로 보낸 데이터를 처리하고 결과를 다시 전달하는 표준 인터페이스 규격.
  - **점검 대상 및 판단 기준**
    - **대상**: Apache, Tomcat, Nginx, IIS, WebtoB
    - **양호**: CGI 스크립트가 실행 가능한 디렉터리를 제한한 경우
    - **취약**: CGI 스크립트가 실행 가능한 디렉터리를 제한하지 않은 경우
  - **조치 방법**: CGI 스크립트를 정해진 디렉터리 내에서만 실행할 수 있도록 설정.
  - **조치 시 영향**: 해당 디렉터리 확인 후 추가적인 파일이 없다면 영향 없음.

- **점검 및 조치 사례**
  - **Apache**
    - `httpd.conf` 또는 `apache.conf`에서 CGI 모듈 비활성화 또는 주석 처리.

  - **Tomcat**

    - Tomcat 재시작.
  - **Nginx**

  - **IIS**

  - **WebtoB**

#### 2. 웹 서비스 > 2. 서비스 관리

- **WEB-12 웹 서비스 > 2. 서비스 관리**

    - **개요**: 웹 서비스 링크(심볼릭 링크, aliases 등) 사용 제한 여부 점검.
    - **점검 내용**: 심볼릭 링크, aliases 등의 링크 사용을 허용하지 않는 경우와 허용하는 경우를 구분하여 점검.
    - **점검 목적**: 검증을 우회한 시스템 파일 접근을 방지하고, 보안상 민감한 내용이 악의적인 사용자에게 노출될 위험을 줄이기 위함.
    - **보안 위협**: 심볼릭 링크를 통해 허용하지 않은 다른 디렉터리에 액세스할 수 있는 위험이 존재.
    - **참고**: 심볼릭 링크는 사용자가 링크 파일을 요청하면, 시스템이 해당 링크에 저장된 대상 경로를 따라가서 실제 원본 데이터를 가져와 전달.
    - **점검 대상 및 판단 기준**:
      - **대상**: Apache, Tomcat, Nginx, IIS, JEUS, WebtoB
      - **양호**: 심볼릭 링크, aliases, 바로가기 등의 링크 사용을 허용하지 않는 경우.
      - **취약**: 심볼릭 링크, aliases, 바로가기 등의 링크 사용을 허용하는 경우.
    - **조치 방법**: 웹 서비스 링크 사용 제한 설정.
    - **조치 시 영향**: 심볼릭 링크를 이용하여 웹페이지가 구성된 경우 해당 서비스가 실행되지 않을 수 있음.

  - **점검 및 조치 사례**:
    - **Apache**: `apache.conf` 파일 내 `Options` 지시자 `FollowSymLinks` 옵션 제거.
      ```markdown
      <Directory />
      Options –FollowSymLinks
      #Options Indexes FollowSymLinks
      </Directory>
      ```
    - **Tomcat**: `server.xml` 파일 내 `Context` 요소 `allowLinking` 옵션 설정.
      ```xml
      <Context allowLiking=“true”>
      <WatchedResource>WEB-INF/web.xml</WatchedResource>
      <WatchedResource>WEB-INF/tomcat-web.xml</WatchedResource>
      <WatchedResource>${catalina.base}/conf/web.xml</WatchedResource>
      </Context>
      ```
    - **Nginx**: `nginx.conf` 파일 내 설정된 모든 디렉터리의 `disable_symlinks on` 설정.
      ```markdown
      location / {
      root html;
      index index.html index.htm;
      disable_symlinks on;
      }
      ```
    - **IIS**: 홈 디렉터리 바로가기 파일 확인 후 제거.
    - **JEUS**: `jeus-web-dd.xml` 파일 내 `alias` 요소 설정 제거.
      ```xml
      <aliasing>
      <alias>
      <alias-name>/images/</alias-name>
      <real-path>/home/web/images/</real-path>
      </alias>
      </aliasing>
      ```
    - **WebtoB**: `http.m` 파일 내 `ALIAS` 절 요소 설정 제거.
      ```markdown
      # cat /[WebtoB 설치 디렉터리]/config/http.m | grep -C 2 ALIAS
      *ALIAS
      alias1 URI = "/cgi-bin/", RealPath = "/home/tmax/webtob/cgi-bin/"
      ```

- **WEB-13 웹 서비스 > 2. 서비스 관리**
  - (상) 웹 서비스 설정 파일 노출 제한
    - **개요**: DB 연결 파일에 대한 접근 권한, 스크립트 매핑 등 웹 서비스에서의 DB 연결 취약점 존재 여부 점검.

### 웹 서비스 헤더 정보 노출 제한

#### 개요
점검 내용: 웹페이지 응답 헤더에서 버전 정보, 사용 중인 OS 등의 서버 정보 노출 여부 점검  
점검 목적: 웹 서버 및 OS 정보가 노출될 경우 공격자에 의해 해당 버전의 알려진 취약점을 이용하여 시스템 구조와 특성 노출 및 해당 취약점을 통한 공격의 위험이 존재함

#### 보안 위협
웹 서버 및 OS 정보가 노출될 경우, 공격자에 의해 해당 버전의 알려진 취약점을 이용하여 시스템 구조와 특성을 파악하고, 이를 통해 해당 취약점을 통한 공격이 가능해짐.

#### 점검 대상 및 판단 기준
- **대상**: Apache, Tomcat, Nginx, IIS, JEUS, Webtob  
- **양호**: HTTP 응답 헤더에서 웹 서버 정보가 노출되지 않는 경우  
- **취약**: HTTP 응답 헤더에서 웹 서버 정보가 노출되는 경우

#### 조치 방법
응답 헤더에 표시되는 정보를 최소한으로 제한하여 설정.

#### 조치 시 영향
일반적인 경우 영향 없음.

#### 점검 및 조치 사례
- **Apache**
  - `httpd.conf` (또는 `apache2.conf`) 파일 내 모든 디렉터리에 `ServerTokens`, `ServerSignature` 옵션 설정.
  ```plaintext
  <Directory/>
  ServerTokens Prod
  ServerSignature Off
  </Directory>
  ```
- **Tomcat**
  - `server.xml` 파일 내 `server` 값을 임의 정보로 변경.
  ```xml
  <Connector port="8080" protocol="HTTP/1.1"
    connectionTimeout="20000"
    redirectPort="8443"
    server="{임의 정보로 변경}"
  />
  ```
- **Nginx**
  - `nginx.conf` 파일 내 `server_tokens` 값을 `"off"`로 설정.
  ```plaintext
  server_tokens off;
  ```
- **IIS**
  - 오류 페이지 설정 편집, "서버 오류 발생 시 다음 반환" 항목을 "사용자 지정 오류 페이지"로 설정.
