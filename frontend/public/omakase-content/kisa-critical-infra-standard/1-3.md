# 1-3. Unix 네트워크 서비스 관리 — 메일·DNS·NFS·Telnet

#### NFS
- **점검 내용**
  - `/etc/exports` 파일에서 `anon` 옵션 확인.
  - HP-UX 11i v3에서는 `/etc/dfs/dfstab` 파일도 함께 확인.

- **조치 방법**
  - `anon` 옵션을 `-1`로 수정 후 NFS 서비스 재시작 (`exportfs –u`, `exportfs –a`).

#### Samba
- **점검 내용**
  - `/usr/lib/smb.conf` 파일에서 `guest ok` 옵션 확인.

- **조치 방법**
  - `guest ok` 옵션을 `no`로 수정 후 서비스 재시작 (`stopsrc –s smbd`, `startsrc -s smbd`).

#### HP-UX 기본 FTP
- **점검 내용**
  - `/etc/passwd` 파일에서 `ftp` 및 `anonymous` 계정 확인.

- **조치 방법**
  - `ftp` 및 `anonymous` 계정 제거 (`userdel ftp`, `userdel anonymous`).

### r 계열 서비스 비활성화

#### 점검 내용
- `r-command` (rsh, rlogin, rexec) 등의 r 계열 서비스가 비활성화 여부 확인.

#### 점검 목적
- 인증 없이 관리자 원격 접속이 가능하여 보안 위협을 방지하기 위함.

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등.
- **판단 기준**:
  - **양호**: 불필요한 r 계열 서비스가 비활성화된 경우.
  - **취약**: 불필요한 r 계열 서비스가 활성화된 경우.

#### 조치 방법
- 불필요한 r 계열 서비스 중지 및 비활성화 설정:
  - `SOLARIS(5.9 이하 버전)`: `/etc/inetd.conf` 파일에서 관련 필드 주석 처리 후 서비스 재시작 (`kill -HUP [inetd PID]`).
  - `SOLARIS(5.10 이상 버전)`: `inetadm` 명령어를 통해 데몬 중지.
  - `LINUX`: `inetd.conf` 또는 `xinetd.d/<파일 이름>` 파일에서 관련 필드 주석 처리 후 서비스 재시작 (`systemctl restart xinetd`).
  - `AIX, HP-UX`: `/etc/inetd.conf` 파일에서 관련 필드 주석 처리 후 변경된 설정 적용 (`refresh –s inetd`, `inetd -c`).

### crontab 및 at 명령어 권한 설정 미흡

#### 점검 내용
- `crontab` 및 `at` 서비스 관련 파일의 권한 적절성 여부 확인.

#### 점검 목적
- 관리자 외에는 서비스를 사용할 수 없도록 설정하고 있는지 점검하기 위함.
- 일반 사용자가 crontab 및 at 서비스를 사용할 수 있을 경우, 고의 또는 실수로 불법적인 예약 파일 실행으로 시스템 피해를 일으킬 수 있는 위험이 존재함.

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등.
- **판단 기준**:
  - **양호**: `crontab` 및 `at` 명령어에 일반 사용자 실행 권한이 제거되어 있으며, `cron` 및 `at` 관련 파일 권한이 `640` 이하인 경우.
  - **취약**: `crontab` 및 `at` 명령어에 일반 사용자 실행 권한이 부여되어 있으며, `cron` 및 `at` 관련 파일 권한이 `640` 이상인 경우.

#### 조치 방법
- `crontab` 및 `at` 명령어 파일 권한을 `750` 이하로 설정.
- `cron` 작업 목록 파일, `cron` 관련 파일 및 `at` 작업 목록 파일 소유자를 `root`로, 파일 권한을 `640`으로 변경.
- `crontab` 및 `at` 명령어는 SUID가 설정되어 있으므로 SUID 설정 제거 필요.

#### 점검 및 조치 사례
- **SOLARIS**: `crontab`, `cron` 작업 목록 파일, `cron` 관련 파일 소유자 및 권한 확인 후 변경.
- **LINUX**: `crontab`, `at` 작업 목록 파일 소유자 및 권한 확인 후 변경.
- **AIX, HP-UX**: `crontab`, `at` 작업 목록 파일 소유자 및 권한 확인 후 변경.

### DoS 공격에 취약한 서비스 비활성화

#### 개요
DoS 공격에 취약한 서비스의 실행 여부를 점검하여 시스템 보안성을 높입니다.

#### 점검 내용
사용하지 않는 DoS 공격에 취약한 서비스(echo, discard, daytime, chargen, ntp, dns, snmp 등)의 활성화 여부를 확인합니다.

#### 점검 목적
시스템의 보안성을 높이기 위함입니다.

#### 보안 위협
해당 서비스가 활성화된 경우, 시스템 정보 유출 및 DoS 공격의 대상이 될 수 있는 위험이 존재합니다.

#### 참고
DoS(Denial of Service attack): 시스템을 악의적으로 공격해 해당 시스템의 자원을 부족하게하여 원래 의도된 용도로 사용하지 못하게 하는 공격입니다.

#### 점검 대상 및 판단 기준

- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: DoS 공격에 취약한 서비스가 비활성화된 경우
- **취약**: DoS 공격에 취약한 서비스가 활성화된 경우

#### 조치 방법
echo, discard, daytime, chargen, ntp, dns, snmp 등의 서비스를 비활성화합니다.

#### 조치 시 영향
일반적인 경우 영향이 없습니다.

#### 점검 및 조치 사례

- **SOLARIS**
  - Step 1) `# inetadm | grep enable | egrep “echo|discard|daytime|chargen”`
  - Step 2) `# inetadm -d <중지하고자 하는 서비스 데몬>`
  
- **LINUX**
  - [inetd]
    - Step 1) `/etc/inetd.conf` 파일 내 서비스 활성화 여부 확인
    - Step 2) `/etc/inetd.conf` 파일 수정(주석 제거)
    - Step 3) `# inetd`
  
  - [xinetd]
    - Step 1) `/etc/xinetd.d/<파일명>` 파일 내 서비스 활성화 여부 확인
    - Step 2) `disable = yes`로 설정
    - Step 3) `# service xinetd restart`
  
  - [systemd]
    - Step 1) `# systemctl list-units --type=service | grep -E “echo|discard|daytime|chargen”`
    - Step 2) `# systemctl stop <서비스명>`
    - Step 3) `# systemctl disable <서비스명>`

- **AIX, HP-UX**
  - Step 1) `/etc/inetd.conf` 파일 내 서비스 활성화 여부 확인
  - Step 2) `/etc/inetd.conf` 파일 수정(주석 처리)
  - Step 3) 설정 적용: AIX(`refresh –s inetd`), HP-UX(`inetd -c`)

#### DoS 공격에 취약한 서비스 예시

| 서비스 (포트) | 설명 |
| --- | --- |
| echo (7) | 클라이언트에서 보내는 메시지를 단순히 재전송하는 서비스 |
| discard (9) | 수신되는 임의 사용자의 데이터를 폐기하는 서비스 |
| daytime (13) | 클라이언트의 질의에 응답하여 아스키 형태로 현재 시간과 날짜를 출력하는 서비스 |
| chargen (19) | 임의 길이의 문자열을 반환하는 서비스 |
| NTP (123) | 네트워크로 연결되어 있는 컴퓨터들끼리 시각을 동기화하는 서비스 |
| DNS (53) | 호스트의 도메인 이름을 호스트의 네트워크 주소로 바꾸거나 그 반대의 변환을 수행하는 서비스 |
| SNMP (161/162) | 네트워크 장비들로부터 필요한 정보를 가져와 장비 상태를 모니터링하거나, 설정값을 변경하는 등의 작업을 하여 네트워크 장비를 관리하는데 사용되는 서비스 |
| SMTP (25) | 인터넷에서 메일을 보내기 위해 사용되는 서비스 |

### 불필요한 NFS 서비스 비활성화

#### 개요
불필요한 NFS(Network File System) 서비스의 사용 여부를 점검하여 침해사고 위험성을 줄입니다.

#### 점검 내용
NFS 서비스가 사용되지 않는 경우 중지합니다.

#### 점검 목적
이용하는 NFS 서비스는 서버의 디스크를 클라이언트와 공유하여 사용할 때 이용한 침해사고 위험이 높으므로 사용하지 않는 경우 중지하기 위함입니다.

#### 보안 위협
NFS 서비스가 적절한 보안 설정이 적용되어 있지 않다면 불필요한 파일 공유로 인한 유출 위험이 존재합니다.

#### 참고
- NFS(Network File System): 원격 컴퓨터의 파일 시스템을 로컬 시스템에 마운트하여 로컬 파일 시스템처럼 사용할 수 있는 프로그램.
- NFS 서비스 사용은 원칙적으로 금지되어 있지만 불가피하게 사용 시 필요한 경우 U-40 항목을 참고하여 통제해야 함.

#### 점검 대상 및 판단 기준

- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 불필요한 NFS 서비스 관련 데몬이 비활성화된 경우
- **취약**: 불필요한 NFS 서비스 관련 데몬이 활성화된 경우

#### 조치 방법
NFS 서비스를 사용하지 않는 경우 서비스 중지 및 비활성화 설정합니다.

#### 조치 시 영향
일반적인 경우 영향이 없습니다.

#### 점검 및 조치 사례

- **SOLARIS**
  - Step 1) `# inetadm | egrep “nfs|statd|lockd”`
  - Step 2) `# inetadm -d <중지하고자 하는 서비스 데몬>`
  
- **LINUX**
  - Step 1) `# systemctl list-units --type=service | grep nfs`
  - Step 2) `# systemctl stop <서비스명>`
  - Step 3) `# systemctl disable <서비스명>`

- **AIX**
  - [process 점검]
    - Step 1) `# ps -ef | grep nfsd`
    - Step 2) `# kill –9 <PID>`
    - Step 3) NFS 시동 스크립트 위치 확인: `# ls -al /etc/rc.d/rc*.d/* | grep nfs`
    - Step 4) NFS 시동 스크립트 이름 변경: `# mv /etc/rc.d/rc2.d/S60nfs /etc/rc.d/rc2.d/_S60nfs`
  
  - [service 점검]
    - Step 1) `# lssrc -a | grep nfs`
    - Step 2) `# stopsrc -g nfs`
    - Step 3) `/etc/inittab` 파일 수정(주석 처리): `# rcnfs:23456789:wait:/etc/rc.nfs > /dev/console`
    - Step 4) 설정 적용: `# init q`

- **HP-UX**
  - Step 1) `# ps -ef | grep -E “nfsd|statd|lockd”`
  - Step 2) `# kill -9 <PID>`
  
  - Step 3) `/etc/rc.config.d/nfsconf` 파일 수정: `NFS_SERVER=0`
  - Step 4) 설정 적용: `# /usr/sbin/nfs.server start`

### NFS 접근 통제

#### 개요
NFS(Network File System)의 접근 통제 설정을 점검하여 인증 절차 없이 비인가자의 접근을 통제합니다.

#### 점검 내용
NFS의 접근 통제 설정 적용 여부를 점검합니다.

#### 점검 목적
접근 권한이 없는 비인가자의 접근을 통제하기 위함입니다.

#### 보안 위협
접근 통제 설정이 적절하지 않을 경우, 인증 절차 없이 비인가자가 디렉터리나 파일의 접근이 가능하며, 해당 공유 시스템에 원격으로 마운트하여 중요 파일을 변조하거나 유출할 위험이 존재합니다.

#### 참고
- NFS 서비스 사용 금지가 원칙이나, 불가피하게 사용 시 NFS v2, v3는 평문으로 전송되는 취약점이 있으므로 암호화되는 v4를 사용하는 것을 권고함.
- NFS 서비스를 사용해야 하는 경우, NFS 설정 파일에 꼭 필요한 디렉터리만 설정하고, 허가된 사용자만 접근할 수 있도록 올바른 접근 통제를 설정해야 함.

#### 점검 대상 및 판단 기준

- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 접근 통제가 설정되어 있으며 NFS 설정 파일 접근 권한이 644 이하인 경우
- **취약**: 접근 통제가 설정되어 있지 않고 NFS 설정 파일 접근 권한이 644를 초과하는 경우

#### 조치 방법
불가피하게 사용 시 접근 통제 설정 및 NFS 설정 파일 접근 권한 644 설정합니다.

#### 조치 시 영향
일반적인 경우 영향이 없습니다.

#### 점검 및 조치 사례

- **SOLARIS**
  - Step 1) `# ls -l /etc/dfs/dfstab`
  - Step 2) `# ls -l /etc/dfs/sharetab`
  - Step 3) `/etc/dfs/dfstab` 파일 내 공유 중인 디렉터리에 접근할 수 있는 사용자 및 부여 권한 확인
  - Step 4) `# chown root /etc/dfs/dfstab`
  - Step 5) `# chmod 644 /etc/dfs/dfstab`
  
- **LINUX**
  - Step 1) `# ls -l /etc/exports`
  - Step 2) `# cat /etc/exports`
  - Step 3) `# chown root /etc/exports`
  - Step 4) `# chmod 644 /etc/exports`
  
- **AIX**
  - Step 1) `# ls -l /etc/exports`
  - Step 2) `# cat /etc/exports`
  - Step 3) `# chown root /etc/exports`
  - Step 4) `# chmod 644 /etc/exports`

- **HP-UX**
  - [/etc/dfs/dfstab]
    - Step 1) `# ls -l /etc/dfs/dfstab`
    - Step 2) `# ls -l /etc/dfs/sharetab`
    - Step 3) `/etc/dfs/dfstab` 파일 내 공유 중인 디렉터리에 접근할 수 있는 사용자 및 부여 권한 확인
    - Step 4) `# chown root /etc/dfs/dfstab`
    - Step 5) `# chmod 644 /etc/dfs/dfstab`
  
  - [/etc/exports]
    - Step 1) `# ls -l /etc/exports`
    - Step 2) `# cat /etc/exports`
    - Step 3) `# chown root /etc/exports`
    - Step 4) `# chmod 644 /etc/exports`

### U-41 UNIX > 3. 서비스 관리 (불필요한 automountd 제거)

#### 개요
- **점검 내용**: automountd 서비스 데몬의 실행 여부 점검.
- **점검 목적**: 로컬 공격자가 RPC를 통해 root 권한을 획득하거나 임의 명령을 실행할 수 있는 위험을 줄이기 위함.
- **보안 위협**: 파일 시스템 마운트 옵션 변경으로 root 권한 획득 가능, 프로세스 권한으로 임의 명령 실행 가능.
- **참고**: automountd는 클라이언트에서 자동으로 서버에 마운트를 시키고 일정 시간 사용하지 않으면 unmount 시켜 주는 기능.

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등.
- **양호**: automountd 서비스가 비활성화된 경우.
- **취약**: automountd 서비스가 활성화된 경우.

#### 조치 방법
- **조치 시 영향**: CD-ROM의 자동 마운트는 이뤄지지 않음 (/etc/auto.*, /etc/auto_* 파일을 확인하여 필요 여부).
- **NFS 및 삼바(Samba) 사용 시**: automountd 사용 여부 확인이 필요.

#### 점검 및 조치 사례
- **SOLARIS**:
  - `#svcs -a | grep autofs`
  - `# svcs -l svc:/system/filesystem/autofs:default`
  - `# svcadm disable <서비스 데몬>`
  - `# pkg uninstall <패키지명>`

- **LINUX**:
  - `# systemctl list-units --type=service | grep -E “automount|autofs”`
  - `# systemctl stop <서비스명>`
  - `# systemctl disable <서비스명>`

- **AIX (process 점검)**:
  - `# ps -ef | grep automountd`
  - `# ps -ef | grep autofs`
  - `# kill -9 <PID>`
  - `# installp –u <패키지명>`

- **AIX (service 점검)**:
  - `# lssrc -a | grep -E “automountd|autofs”`
  - `# stopsrc –s automountd`
  - `# stopsrc -s autofs`
  - `/etc/inittab` 파일 수정 및 설정 적용.

- **HP-UX**:
  - `# ps -ef | grep automountd`
  - `# ps -ef | grep autofs`
  - `# kill -9 <PID>`
  - `/etc/rc.config.d/nfsconf` 파일 수정: `AUTOFS=0`

- **설명**: DoS 공격, 버퍼 오버플로우(Buffer Overflow) 및 DNS 서버 원격 침입 등의 위험이 존재함.

#### 참고 자료
- **설명**: BIND(Berkeley Internet Name Domain): BSD 기반의 유닉스 시스템을 위해 설계된 DNS로 서버와 resolver 라이브러리로 구성되어 있음. 네임 서버는 클라이언트들이 이름 참조 자원들이나 Object들에 접근하여, 네트워크 내의 다른 Object들과 함께 정보를 공유할 수 있게 해주는 네트워크 서비스로 사실상 컴퓨터 네트워크 내의 Object들을 위한 분산 데이터베이스 시스템임.

#### 조치 방법
- **설명**: 패치 적용에 따른 서비스 영향 정도를 정확히 파악하여 주기적인 패치 적용 정책 수립 및 주기적으로 패치 적용 설정.

### DNS ZoneTransfer 설정

#### 점검 내용
- **설명**: Secondary Name Server로만 Zone 정보 전송 제한 여부 점검

#### 점검 목적
- **설명**: DNS Zone Transfer 설정을 통해 비인가자에 대한 무단 접근을 방지하기 위함.

#### 보안 위협
- **설명**: Zone Transfer를 모든 사용자에게 허용할 경우, 비인가자에게 호스트 정보, 시스템 정보 등 중요 정보가 유출될 위험이 존재함.

#### 조치 방법
- **설명**: DNS 서비스 사용 시 DNS Zone Transfer를 허가된 사용자에게만 전송 허용하도록 설정.

### DNS 서비스의 취약한 동적 업데이트 설정 금지

#### 점검 내용
- **설명**: DNS 서비스의 취약한 동적 업데이트 설정 여부 점검

#### 점검 목적
- **설명**: DNS 서버에서 동적 업데이트를 사용할 경우, 악의적인 사용자에 의해 신뢰할 수 없는 데이터가 받아들여질 위험이 존재함.

#### 보안 위협
- **설명**: DNS 동적 업데이트: DNS 정보에 변경 사항이 있을 때마다 DNS 클라이언트 컴퓨터가 자신의 리소스 레코드(zone 파일)를 DNS 서버에 자동으로 업데이트하는 기능으로 영역 레코드 수동 관리 작업을 줄일 수 있음.

#### 조치 방법
- **설명**: 일반적으로 동적 업데이트 기능이 필요 없으나 확인 필요함. DNS 서비스 사용 시 allow-update 설정값 수정 후 DNS 서비스 재시작.

### Telnet 서비스 비활성화

#### 개요
점검 내용: 원격 접속 시 Telnet 프로토콜 사용 여부 점검  
점검 목적: 취약한 Telnet 프로토콜을 비활성화하여 계정 및 중요 정보 유출 방지  
보안 위협: 데이터가 평문으로 전송되어 비인가자가 스니핑을 통해 계정 및 중요 정보를 외부로 유출할 위험이 존재  
참고: 스니핑은 컴퓨터 네트워크상에 흘러 다니는 트래픽을 도청하는 행위

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: 원격 접속 시 Telnet 프로토콜을 비활성화한 경우  
취약: 원격 접속 시 Telnet 프로토콜을 사용하는 경우

#### 조치 방법
Telnet, FTP 등 안전하지 않은 서비스 사용을 중지하고 SSH 설치 및 사용하도록 설정

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS**
  - Telnet 서비스 활성화 여부 확인: `svcs -a | grep telnet`
  - Telnet 서비스 비활성화: `svcadm disable svc:/network/telnet:default`
  - SSH 서비스 실행: `svcadm enable ssh`

- **LINUX**
  - **[inetd]**
    - Telnet 서비스 활성화 여부 확인
    - 해당 옵션이 허용된 경우 설정 제거 (예시: 주석 처리)
    - inetd 서비스 재시작: `service inetd restart`
    - SSH 서비스 실행: `service sshd start`

  - **[xinetd]**
    - Telnet 서비스 활성화 여부 확인
    - /etc/xinetd.d/telnet 파일의 disable 설정값 수정 (`disable = yes`)
    - 설정 적용 및 재시작: `systemctl restart xinetd`
    - SSH 서비스 실행: `systemctl start sshd`

  - **[systemd]**
    - Telnet 서비스 활성화 여부 확인
    - Telnet 서비스 중지 및 비활성화: `systemctl stop telnet.socket`, `systemctl disable telnet.socket`
    - SSH 서비스 실행: `systemctl start sshd`

- **AIX**
  - Telnet 서비스 활성화 여부 확인
  - 해당 옵션이 허용된 경우 설정 제거 (예시: 주석 처리)
  - inetd 설정 적용: `refresh –s inetd`
  - SSH 서비스 실행

- **HP-UX**
  - Telnet 서비스 활성화 여부 확인

---

- 해당 옵션이 허용된 경우 설정 제거
  - inetd 설정 적용: `inetd –c`
  - SSH 서비스 실행: `/sbin/init.d/secsh start`
