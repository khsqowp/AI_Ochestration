# 9-1. 가상화·클라우드 환경 보안

#### 4. 콘솔 드래그 앤 드롭 기능 비활성화
- **개요**: 가상 머신에 대한 드래그 앤 드롭 기능을 비활성화하여 파일 송·수신 기능을 통한 로그 기록이 저장되도록 하기 위함.
- **점검 내용**: 가상 머신 콘솔 드래그 앤 드롭 기능 비활성화 여부 점검.
- **점검 목적**: 로그 분석을 통한 침입 탐지가 가능하도록 함.
- **보안 위협**: 파일 송·수신 기록이 로그에 저장되지 않아 로그 분석을 통한 침입 탐지가 불가능한 위험이 존재함.
- **참고**: ESXi 기본 비활성화.
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi
  - 양호: 콘솔 드래그 앤 드롭 기능이 비활성화되어 있거나, 제한 설정된 경우
  - 취약: 활성화되어 있거나, 제한 설정되지 않은 경우
- **조치 방법**: 가상 머신 콘솔 드래그 앤 드롭 제한 설정.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 가상 시스템 > [가상 머신 선택] > 설정 편집 > VM 옵션 > 고급 > 구성 매개 변수로 이동
  Step 3) isolation.tools.dnd.disable 설정값 확인
  Step 4) 매개 변수 값을 TRUE로 설정.
  또는, 각 매개 변수가 존재하지 않을 시, 해당 매개 변수 추가 및 값을 TRUE로 설정
  ```

### 가상 네트워크 관리

#### 1. 가상스위치 MAC 주소 변경 정책 비활성화
- **개요**: MAC 주소 변경 정책을 거부로 설정하여 악의적인 사용자(또는 악성코드)가 장치 내의 MAC 주소를 변경하는 것을 방지하기 위함.
- **점검 내용**: MAC 주소 변경 정책 비활성화 여부 점검.
- **점검 목적**: 스푸핑 등의 공격을 방지하기 위함.
- **보안 위협**: 악의적인 사용자(또는 악성코드)가 장치 내의 MAC 주소를 변경하여 스푸핑 등의 공격 위험이 존재함.
- **참고**: MAC 주소 변경 정책: 가상 머신 내부에서 MAC 주소를 변경하는 것을 허용하는 정책.
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi
  - 양호: MAC 주소 변경 정책이 거부로 설정된 경우
  - 취약: 허용으로 설정된 경우
- **조치 방법**: 가상 스위치 MAC 주소 변경 정책 거부 설정.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 네트워킹 > 가상 스위치 > [가상 스위치 선택] > 설정 편집 > 보안으로 이동
  Step 3) MAC 주소 변경 정책 설정 확인
  Step 4) 허용으로 설정되어 있을 경우, ‘거부’로 변경 후 해당 설정 저장
  ```

#### 2. 가상스위치 무차별(Promiscuous) 모드 정책 비활성화
- **개요**: 무차별(Promiscuous) 모드를 비활성화하여 네트워크 트래픽 모니터링을 방지하기 위함.
- **점검 내용**: 무차별(Promiscuous) 모드 비활성화 여부 점검.
- **점검 목적**: 비인가자가 해당 가상 스위치를 통해 다른 스위치로 전달되는 네트워크 트래픽을 모니터링 및 내부 정보 유출 위험이 존재함.
- **보안 위협**: 무차별(Promiscuous) 모드: 자신에게 직접 전달되지 않은 모든 네트워크 트래픽 패킷을 수신하는 기능.
- **참고**:
- **점검 대상 및 판단 기준**:
  - 대상: VMware ESXi, XenServer
  - 양호: 무차별 모드 정책 설정이 거부로 설정된 경우
  - 취약: 허용으로 설정된 경우
- **조치 방법**: 가상 스위치 무차별(Promiscuous) 모드 정책 거부 설정.
- **점검 및 조치 사례**:
  ```markdown
  l VMware ESXi
  Step 1) Web 콘솔 페이지 접속 > https://<VMware ESXi IP>
  Step 2) 네트워킹 > 가상 스위치 > [가상 스위치 선택] > 설정 편집 > 보안으로 이동
  Step 3) 무차별 모드 정책 설정 확인
  Step 4) 허용으로 설정되어 있을 경우, ‘거부’로 변경 후 해당 설정 저장

  l XenServer
  Step 1) 가상 스위치 Promiscuous 모드 조회
  Step 2) XenServer CLI 접속 후, 다음 명령어 실행하여 uuid_of_pif/vif 확인
  $ xe pif-list network-name-label=<네트워크 이름>
  $ xe vif-list vm-name-label=<VM 이름>
  Step 3) 다음 명령어 실행하여 promiscuous 값 확인
  $ xe pif-param-list uuid=<uuid_of_pif>
  $ xe vif-param-list uuid=<uuid_of_vif>
  Step 4) 다음 명령어 실행하여 promiscuous 값 설정
  $ xe pif-param-set uuid=<uuid_of_pif> other-config:promiscuous="false"
  $ xe vif-param-set uuid=<uuid_of_vif> other-config:promiscuous="false"
  ```

### 가상스위치 위조전송(Forged Transmits) 모드 정책 비활성화

#### 개요
가상 스위치 위조전송(Forged Transmits) 모드를 비활성화하여 네트워크 스니핑, 데이터 유출 등의 보안 위협을 방지합니다.

#### 점검 내용
- 가상 스위치 위조전송(Forged Transmits) 모드가 비활성화 여부 점검

#### 점검 목적
네트워크 스니핑, 데이터 유출 등을 방지하기 위함입니다.

#### 보안 위협
가상 스위치에 위조전송(Forged Transmits) 모드가 설정되어 있을 경우 네트워크 스니핑, 데이터 유출 등의 보안 위험이 존재합니다.

#### 참고
- 위조 전송(Forged Transmits) 모드: 가상 스위치가 수신하는 모든 트래픽을 연결된 모든 NIC에게 전송하는 기능

#### 점검 대상 및 판단 기준
- **대상**: VMware ESXi
- **양호**: 가상 스위치에 위조 전송(Forged Transmits) 모드 설정이 거부로 설정된 경우
- **취약**: 가상 스위치에 위조 전송(Forged Transmits) 모드 설정이 허용으로 설정된 경우

#### 조치 방법
- 위조 전송(Forged Transmits) 모드를 거부로 설정

#### 조치 시 영향
일반적 경우 영향 없음.

#### 점검 및 조치 사례
- **VMware ESXi**
  - Web 콘솔 페이지 접속: `https://<VMware ESXi IP>`
  - 네트워킹 > 가상 스위치 > [가상 스위치 선택] > 설정 편집 > 보안으로 이동
  - 위조 전송 정책 설정 확인
  - 허용으로 설정되어 있을 경우, ‘거부’로 변경 후 해당 설정 저장

### 주기적 보안 패치 및 벤더 권고사항 적용

#### 개요
가상화 장비 및 관리서버 들에 대해 주기적인 보안 패치와 벤더 권고사항 적용 여부를 확인하여 알려진 취약점을 제거하고 가상화 인프라의 안정성과 가용성을 확보합니다.

#### 점검 내용
- 패치 절차 수립 및 주기적 패치 및 벤더 권고사항 적용 여부

#### 점검 목적
패치 미적용 시 제로데이·원격코드실행 등 취약점이 악용되어 전체 가상화 인프라 침해 발생 가능성을 줄입니다.

#### 보안 위협
패치 미적용 시 다양한 취약점들이 존재하여 전체 가상화 인프라의 안정성이 위협받을 수 있습니다.

#### 참고
- -

#### 점검 대상 및 판단 기준
- **대상**: 공통
  - **양호**: 패치 절차를 수립하여 주기적으로 패치 및 벤더 권고사항을 확인 및 적용하는 경우
  - **취약**: 패치 절차가 수립되어 있지 않거나 주기적으로 패치를 설치하지 않는 경우

#### 조치 방법
- 장비별 제공하는 최신 취약점 정보를 파악 후 최신 패치 및 업그레이드를 수행

#### 조치 시 영향
서비스 영향을 고려하여 벤더사와 협의 후 적용.

#### 점검 및 조치 사례
- **공통**

  - 구분: 보안패치 및 보안권고 정보제공 사이트
    - VMware ESXi, vCenter: `https:/support.broadcom.com/web/ecx/security-advisory`
    - XenServer: `https://xenbits.xen.org/xsa`
    - KVM: 리눅스 배포판(Red Hat, Ubuntu, SUSE 등)의 공식 보안공지를 통해 확인
    - Nutanix: `https://www.nutanix.com/trust/security-advisories`

### 클라우드 취약점 분석 평가 항목

#### 계정 관리
- **사용자 계정 관리 (CA-01)**
  - 점검 내용: 불필요한 클라우드 관리 콘솔 계정 존재 여부 점검
  - 점검 목적: 관리되지 않은 계정에 의한 침입을 방지하기 위함.
  - 보안 위협: 불필요한 계정이 존재할 경우 비인가자의 무단 접근이 가능하며, 사후 추적이 어려울 수 있습니다.
  - 참고: 불필요한 계정 삭제 시 업무 영향도 파악 후 삭제 권고.
  - 대상: 클라우드 플랫폼
    - **양호**: 불필요한 계정이 존재하지 않거나 비활성화된 경우
    - **취약**: 불필요한 계정이 존재하며 활성화 된 경우
  - 조치 방법: 클라우드 관리 콘솔에 등록된 계정 현황 확인 후 불필요한 계정 삭제 또는 비활성화.
  - 조치 시 영향: 일반적인 경우 영향 없음.

- **사용자 정책 관리 (CA-02)**
  - 점검 내용: 사용자 계정에 적절한 권한 부여 여부 점검
  - 점검 목적: 권한의 오남용을 예방하기 위함.
  - 보안 위협: 무단 접근, 데이터 유출, 내부자 위협 등 보안 위험이 존재합니다.
  - 대상: Cloud Platform
    - **양호**: 사용자/그룹의 목적에 맞게 역할/권한이 할당된 경우
    - **취약**: 사용자/그룹을 목적에 맞지 않게 역할/권한이 할당된 경우
  - 조치 방법: 사용자/그룹의 역할/권한을 목적에 맞게 설정.
  - 조치 시 영향: 일반적인 경우 영향 없음.

- **MFA(Multi-Factor Authentication) 설정 (CA-03)**
  - 점검 내용: 2차 인증을 통해 사용자 계정의 보안을 강화 여부 점검
  - 점검 목적: 사용자 계정의 보안을 강화하여 무단 접근을 방지하고, 계정 탈취 및 데이터 유출의 위험을 줄이기 위함.
  - 보안 위협: 다양한 비밀번호 추측 공격에 노출될 가능성이 높으며, 계정 탈취로 인해 중요 데이터 유출 및 로그 변조 등의 시스템 악용이 발생할 위험이 존재합니다.
  - 대상: 클라우드 플랫폼
    - **양호**: 각 계정별 2차 인증이 설정된 경우
    - **취약**: 각 계정별 2차 인증이 설정되지 않은 경우
  - 조치 방법: 인증 번호, OTP 등을 통한 2차 인증 설정.
  - 조치 시 영향: 일반적인 경우 영향 없음.

### 계정 관리

#### 비밀번호 관리 정책 설정
- **비밀번호 복잡성 및 길이**: 영문자, 숫자, 특수문자를 두 개 조합시에는 10자리 이상, 세 개 조합시에는 8자리 이상 사용해야 함.
- **변경 주기**: 무차별 대입 공격을 방지하기 위한 로그인 시도 횟수 제한 설정 적용이 필요함.

#### 점검 내용
- 비밀번호 설정 정책의 복잡성 만족 여부 점검

#### 점검 목적
- 탈취 목적의 공격에 대해 대비하기 위함

#### 보안 위협
- 무차별 대입 공격(Brute-force Attack): 특정한 암호를 풀기 위해 가능한 모든 조합을 시도하여 비밀번호를 찾아내는 공격 방식.
- 사전 공격(Dictionary attack): 사전에 있는 단어를 입력하여 비밀번호를 알아내거나 해독하는 컴퓨터 공격 방식.

#### 참고
- 무차별 대입 공격: 특정한 암호를 풀기 위해 가능한 모든 조합을 시도하여 비밀번호를 찾아내는 공격 방식.
- 사전 공격: 사전에 있는 단어를 입력하여 비밀번호를 알아내거나 해독하는 컴퓨터 공격 방식.

#### 점검 대상 및 판단 기준
- **대상**: 클라우드 플랫폼
- **양호**: 복잡성을 만족하는 비밀번호 정책을 설정하고 로그인 시도 제한을 설정한 경우
- **취약**: 복잡성을 만족하지 않는 비밀번호를 사용하거나 로그인 시도 제한을 설정하지 않은 경우

#### 조치 방법
- 비밀번호 정책을 해당 기관의 보안 정책에 적합하게 설정

#### 조치 시 영향
- 일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS**: `/etc/default/passwd` 파일 내에 비밀번호 설정값 수정.
- **권고값 기능 설명**:
  - `HISTORY=`
  - `MINDIFF=`
  - `MINALPHA=`
  - `MINNONALPHA=`
  - `MINUPPER=`
  - `MINLOWER=`
  - `MAXREPEATS=`
  - `MINSPECIAL=`
  - `MINDIGIT=`
  - `NAMECHECK=`
  - `MAXDAYS=`
  - `MINDAYS=`
  - `MAXWEEKS=`
  - `MINWEEKS=`
  - `WARNWEEKS=`
  - `PASSLENGTH=`
  - `WHITESPACE=`

### CA-11 클라우드 > 4. 운영 관리 (중) 관계형 데이터베이스 암호화 설정
