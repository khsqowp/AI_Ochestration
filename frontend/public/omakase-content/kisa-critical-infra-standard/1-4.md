# 1-4. Unix FTP·SNMP 설정과 패치·로그 관리

### FTP 서비스 정보 노출 제한

#### 개요
점검 내용: FTP 서비스 정보 노출 여부 점검  
점검 목적: FTP 서비스 접속 배너를 통한 불필요한 정보 노출을 방지  
보안 위협: 비인가자가 FTP 접속 시도 시 노출되는 접속 배너 정보를 수집하여 악의적인 공격에 이용할 위험이 존재  
참고: -

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: FTP 접속 배너에 노출되는 정보가 없는 경우  
취약: FTP 접속 배너에 노출되는 정보가 있는 경우

#### 조치 방법
FTP 서비스 사용 시 FTP 설정 파일을 통해 접속 배너 설정 (서비스 이름이나 버전 정보를 노출하지 않는 것을 권고)

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, LINUX**
  - **[vsFTP]**
    - 배너 설정 확인: `cat /etc/vsftpd.conf | grep ftpd_banner`
    - 해당 옵션이 설정되지 않은 경우 주석 제거 및 옵션 설정 (`ftpd_banner=<변경할 배너>`)
    - vsFTP 서비스 재시작: `systemctl restart vsftpd`

  - **[ProFTP]**
    - 배너 설정 확인
    - /etc/proftpd.conf 파일 내 ServerIdent 설정값 변경 (`ServerIdent off` 또는 `ServerIdent on “<변경할 배너>”`)
    - ProFTP 서비스 PID 확인: `ps -ef | grep proftp`
    - ProFTP 서비스 재시작: `kill –1 <PID>`

- **AIX**
  - **[FTP]**
    - 메시지 카탈로그 파일 추출
    - 배너 설정 확인 및 변경
    - ftpd.cat 파일 생성

  - **[vsFTP]**
    - 배너 설정 확인 및 변경
    - vsFTP 서비스 PID 확인 및 재시작

- **HP-UX**
  - FTP 설정 파일 경로 확인
  - ftpaccess 설정 확인
  - 배너 설정 확인 및 변경
  - /etc/inetd.conf 파일 설정값 변경
  - 배너 파일 수정
  - /etc/ftpd/ftpaccess 파일의 suppresshostname, suppressversion, greeting 옵션 설정값 변경

### 암호화되지 않는 FTP 서비스 비활성화

#### 개요
점검 내용: 암호화되지 않은 FTP 서비스 비활성화 여부 점검  
점검 목적: 암호화되지 않은 FTP 서비스를 비활성화하여 계정 및 중요 정보 유출 방지  
보안 위협: 데이터가 평문으로 전송되어 비인가자가 스니핑을 통해 계정 및 중요 정보를 외부로 유출할 위험이 존재  
참고: 기반시설 시스템에서 FTP 서비스의 이용은 원칙적으로 금지하나, 불가피하게 사용 시 SFTP 사용 권고

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: 암호화되지 않은 FTP 서비스가 비활성화된 경우  
취약: 암호화되지 않은 FTP 서비스가 활성화된 경우

#### 조치 방법
암호화되지 않은 FTP 서비스 중지 및 비활성화 설정

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS**
  - **[vsFTP]**
    - FTP 서비스 활성화 여부 확인: `svcs -a | grep vsftpd`
    - FTP 서비스 비활성화: `svcadm disable vsftpd`

  - **[ProFTP]**
    - FTP 서비스 활성화 여부 확인: `svcs -a | grep proftpd`

- **LINUX**
  - **[inetd]**
    - /etc/inetd.conf 파일 내 FTP 서비스 활성화 여부 확인 및 설정값 변경 (주석 처리)
    - inetd 서비스 재시작

  - **[xinetd]**
    - /etc/xinetd.d/ftp 파일 내 FTP 서비스 활성화 여부 확인 및 설정값 변경 (`disable = yes`)
    - 설정 적용 및 재시작

  - **[vsFTP]**
    - FTP 서비스 활성화 여부 확인
    - FTP 서비스 중지 및 비활성화

  - **[ProFTP]**
    - FTP 서비스 활성화 여부 확인
    - FTP 서비스 중지

- **AIX, HP-UX**
  - **[FTP]**
    - /etc/inetd.conf 파일 내 FTP 서비스 활성화 여부 확인 및 설정값 변경 (주석 처리)
    - inetd 설정 적용

  - **[vsFTP]**
    - vsFTP 서비스 활성화 여부 확인
    - vsFTP 서비스 PID 확인 및 중지

  - **[ProFTP]**
    - ProFTP 서비스 활성화 여부 확인
    - ProFTP 서비스 PID 확인 및 중지

### FTP 계정 shell 제한

#### 개요
점검 내용: FTP 기본 계정에 쉘 설정 여부 점검  
점검 목적: FTP 계정의 쉘을 통한 시스템 접근을 차단하기 위함  
보안 위협: FTP 기본 계정에 쉘이 부여될 경우, 비인가자가 해당 기본 계정으로 시스템에 접근할 위험이 존재함  
참고: 등의 보안 조치를 반드시 적용해야 함

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: FTP 계정에 /bin/false(/sbin/nologin) 쉘이 부여된 경우  
취약: FTP 계정에 /bin/false(/sbin/nologin) 쉘이 부여되어 있지 않은 경우

#### 조치 방법
- FTP 서비스 사용 시 FTP 계정에 /bin/false 쉘 부여 설정

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - Step 1) ftp 계정의 일곱 번째 필드에 등록된 로그인 쉘 확인
    ```bash
    # cat /etc/passwd | grep ftp
    예시) ftp:x:134:65534::/srv/ftp:/usr/sbin/nologin
    ```
  - Step 2) ftp 계정 로그인 쉘 변경
    ```bash
    /etc/passwd 파일 직접 수정 : ftp:x:134:65534::/srv/ftp:/bin/false 또는 /sbin/nologin
    usermod 명령어를 사용하여 수정
    # usermod -s /bin/false <계정>
    ```

### FTP 서비스 접근 제어 설정

#### 개요
점검 내용: FTP 서비스에 비인가자의 접근 가능 여부 점검  
점검 목적: 접근 권한이 없는 비인가자의 접근을 통제하기 위함  
보안 위협: 인증 절차 없이 비인가자가 디렉터리나 파일에 접근할 수 있어 중요 파일 변조 및 유출을 시도할 위험이 존재함  
참고: 설정 등의 보안 조치를 반드시 적용해야 함

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: 특정 IP주소 또는 호스트에서만 FTP 서버에 접속할 수 있도록 접근 제어 설정을 적용한 경우  
취약: FTP 서버에 접근 제어 설정을 적용하지 않은 경우

#### 조치 방법
- FTP 서비스 사용 시 접근 제어 설정

#### 조치 시 영향
특정 IP주소 또는 호스트에서만 FTP 접속이 가능함

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - [FTP – ftpusers]
    - Step 1) ftpusers 파일 소유자 및 권한 확인
      ```bash
      # ls -l /etc/ftpusers 또는 # ls -l /etc/ftpd/ftpusers
      ```
    - Step 2) 접근 제한 설정 확인
      ```bash
      # cat /etc/ftpusers 또는 # cat /etc/ftpd/ftpusers
      ```

### Ftpusers 파일 설정

#### 개요
점검 내용: FTP 서비스에 root 계정 접근 제한 설정 여부 점검  
점검 목적: root 계정의 FTP 직접 접속을 제한하여 root 비밀번호 정보 노출을 방지하기 위함  
보안 위협: 관리자 계정 및 중요 정보를 외부로 유출할 위험이 존재함  
참고: 접근 제한 등의 보안 조치를 반드시 적용해야 함

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: root 계정 접속을 차단한 경우  
취약: root 계정 접속을 허용한 경우

#### 조치 방법
- FTP 서비스 사용 시 root 계정으로 직접 접속할 수 없도록 설정

#### 조치 시 영향
애플리케이션에서 root 계정으로 직접 접속하여 FTP를 사용하고 있는 경우 확인 필요

#### 점검 및 조치 사례
- **SOLARIS, LINUX, AIX, HP-UX**
  - [기본 FTP – ftpusers]
    - Step 1) root 계정 접근 제한 설정 확인
      ```bash
      # cat /etc/ftpusers 또는 # cat /etc/ftpd/ftpusers
      ```
    - Step 2) /etc(/ftpd)/ftpusers 파일의 설정값 변경(#root 주석 제거)

### 불필요한 SNMP 서비스 구동 점검

#### 개요
점검 내용: SNMP 서비스 활성화 여부 점검  
점검 목적: 불필요한 SNMP 서비스를 비활성화하여 필요 이상의 정보가 노출되는 것을 방지하기 위함  
보안 위협: 비인가자가 시스템의 중요 정보를 유출하거나 불법적으로 수정할 위험이 존재함  
참고: 기본 Community String 변경, 네트워크 모니터링 등의 보안 조치를 반드시 적용해야 함

#### 점검 대상 및 판단 기준
대상: SOLARIS, LINUX, AIX, HP-UX 등  
양호: SNMP 서비스를 사용하지 않는 경우  
취약: SNMP 서비스를 사용하는 경우

#### 조치 방법
- SNMP 서비스를 사용하지 않는 경우 서비스 중지 및 비활성화 설정

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS(5.9 이하 버전)**
  - Step 1) SNMP 서비스 활성화 여부 및 경로 확인
    ```bash
    # ps -ef | grep snmp
    ```
  - Step 2) 서비스 중지 및 이름 변경
    ```bash
    # /etc/init.d/init.snmpdx stop
    # mv /etc/rc3.d/S76snmpdx /etc/rc3.d/_S76snmpdx
    ```

- **SOLARIS(5.10 이상 버전)**
  - Step 1) SNMP 서비스 활성화 여부 확인
    ```bash
    # svcs -a | grep snmp
    ```
  - Step 2) 불필요한 SNMP 서비스가 활성화 중인 경우 데몬 중지
    ```bash
    # svcadm disable svc:/application/management/snmpd:default
    ```

- **LINUX**
  - Step 1) SNMP 서비스 활성화 여부 확인
    ```bash
    # systemctl list-units --type=service | grep snmpd
    ```
  - Step 2) 불필요한 SNMP 서비스가 활성화(loaded active running)인 경우 서비스 중지 및 비활성화
    ```bash
    # systemctl stop snmpd
    # systemctl disable snmpd
    ```

- **AIX**
  - Step 1) SNMP 서비스 활성화 여부 확인
    ```bash
    # lssrc -a | grep snmp
    ```
  - Step 2) 불필요한 SNMP 서비스가 활성화(active) 중인 경우 서비스 중지
    ```bash
    # stopsrc –s snmpd
    ```

- **HP-UX**
  - Step 1) SNMP 서비스 활성화 여부 확인
    ```bash
    # ps -ef | grep snmp
    ```
  - Step 2) 불필요한 SNMP 서비스가 활성화(active) 중인 경우 서비스 중지
    ```bash
    # /sbin/init.d/snmpd stop
    ```

### SNMP 버전 사용

**개요**
- **점검 내용**: 안전한 SNMP 버전 사용 여부 점검  
- **점검 목적**: 데이터 보호를 위해 안전한 SNMP 버전 사용  
- **보안 위협**: 낮은 버전의 SNMP는 스니핑 위험이 존재

**참고**
- **SNMP(Simple Network Management Protocol)**: TCP/IP 기반 네트워크에서 정보 수집을 위한 프로토콜
  - **버전**: v1, v2, v3
    - **v1, v2**: 평문 전송으로 스니핑 가능
    - **v3 이상**: HMAC-MD5 또는 HMAC-SHA 알고리즘 기반의 인증 제공

**점검 대상 및 판단 기준**
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **판단 기준**:
  - **양호**: SNMP 서비스를 v3 이상으로 사용
  - **취약**: SNMP 서비스를 v2 이하로 사용 또는 사용하지 않음

**조치 방법**
- **SNMP 버전을 v3 이상으로 적용**

**영향**
- **일반적인 경우 영향 없음**

**점검 및 조치 사례**
- **SOLARIS, LINUX, AIX, HP-UX**
  - **Step 1**: SNMP v3 사용 여부 확인
    ```bash
    # snmpwalk -v3 -l authPriv -u <사용자 이름> -a <사용자 인증 프로토콜> -A <사용자 인증 암호> -x <사용자 암호화 프로토콜> -X <사용자 암호화 암호> <SNMP 서버 IP주소>
    ```
  - **Step 2**: 사용하지 않을 경우 snmp v3 사용자 생성
    ```bash
    # net-snmp-create-v3-user -ro -A <사용자 인증 암호> -X <사용자 암호화 암호> -a <사용자 인증 프로토콜> -x <사용자 암호화 프로토콜> <사용자 이름>
    ```
  - **Step 3**: `/etc/snmp/snmpd.conf` 파일 내의 SNMPv3 사용자 추가
  - **Step 4**: SNMPv3 사용자 읽기/쓰기 권한 추가
  - **Step 5**: SNMP 서비스 실행

### SNMP Community String 복잡성 설정

**개요**
- **점검 내용**: SNMP Community String 복잡성 설정 여부 점검  
- **점검 목적**: 비인가자의 비밀번호 추측 공격 대비

**보안 위협**
- **계정 탈취 시 환경설정 파일 열람 및 수정, 각종 정보수집, 관리자 권한 획득 등 다양한 위험이 존재**

**참고**
- **Community String**: SNMP 인증 과정에서 사용하는 비밀번호
  - 기본값: "public", "private"
  - 복잡성 설정 필요

**점검 대상 및 판단 기준**
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **판단 기준**:
  - **양호**: 영문자, 숫자 포함 10자리 이상 또는 영문자, 숫자, 특수문자 포함 8자리 이상
  - **취약**: 기본값 "public", "private" 사용 또는 복잡도 미만

**조치 방법**
- **SNMP Community String을 영문자, 숫자 포함 10자리 이상 또는 영문자, 숫자, 특수문자 포함 8자리 이상으로 설정**

**영향**
- **일반적인 경우 영향 없음**

**점검 및 조치 사례**
- **SOLARIS(9 이하 버전)**: `/etc/snmp/conf/snmpd.conf` 파일 내의 Community String 설정 값 수정
  ```bash
  read-community <변경 값>
  write-community <변경 값>
  ```
- **SOLARIS(10 버전)**: `/etc/snmp/conf/snmpd.conf` 파일 내의 Community String 설정 값 수정 및 출력여부 확인
  ```bash
  # svcs -a | grep snmpdx
  svcadm enable svc:/application/management/snmpdx:default
  ```
- **SOLARIS(11 버전)**: `/etc/net-snmp/snmp/snmpd.conf` 파일 내의 Community String 설정 값 수정 및 설정 적용 및 SNMP 서비스 재시작
  ```bash
  # svcadm refresh net-snmp
  ```
- **LINUX**
  - **Redhat 계열**: `/etc/snmp/snmpd.conf` 파일 내의 Community String 설정 값 수정 및 설정 적용 및 SNMP 서비스 재시작
    ```bash
    # systemctl restart snmpd
    ```
  - **Debian 계열**: 동일하게 처리

- **AIX, HP-UX**: 각 운영체제에 맞는 파일에서 Community String 설정값 수정 및 서비스 중지 및 실행 또는 재시작

### SNMP Access Control 설정

**개요**
- **점검 내용**: SNMP 접근 제어 설정 여부 점검  
- **점검 목적**: 비인가자의 접근 차단

**보안 위협**
- **비인가자들의 네트워크 정보 유출, 시스템 변경 및 DoS 공격 등의 위험이 존재**

**점검 대상 및 판단 기준**
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **판단 기준**:
  - **양호**: SNMP 서비스에 접근 제어 설정이 되어 있는 경우
  - **취약**: SNMP 서비스에 접근 제어 설정이 되어 있지 않은 경우

**조치 방법**
- **SNMP 서비스 사용 시 접근 제어 설정**

**영향**
- **일반적인 경우 영향 없음**

**점검 및 조치 사례**
- **SOLARIS, LINUX, AIX, HP-UX**: 각 운영체제에 맞는 파일에서 SNMP 접근 제어 설정 및 설정 적용 및 서비스 재시작

### 로그인 시 경고 메시지 설정

**개요**
- **점검 내용**: 서버 및 서비스에 로그온 시 불필요한 정보 차단 및 경고 메시지 출력 여부  
- **점검 목적**: 비인가자들에게 서버에 대한 불필요한 정보를 제공하지 않고, 서버 접속 시 관계자만 접속해야 한다는 경각심을 심어 주기 위함

**보안 위협**
- **로그온 시 기본 설정값이 노출되어 서비스의 취약점을 이용하여 공격을 시도할 위험이 존재**

**점검 대상 및 판단 기준**
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **판단 기준**:
  - **양호**: 서버 및 Telnet, FTP, SMTP, DNS 서비스에 로그온 시 경고 메시지가 설정된 경우
  - **취약**: 서버 및 Telnet, FTP, SMTP, DNS 서비스에 로그온 시 경고 메시지가 설정되어 있지 않은 경우

**조치 방법**
- **Telnet, FTP, SMTP, DNS 서비스를 사용하는 경우 설정 파일을 통해 로그온 시 경고 메시지 설정**

**영향**
- **일반적인 경우 영향 없음**

**점검 및 조치 사례**
- **SOLARIS, LINUX, AIX, HP-UX**: 각 운영체제에 맞는 파일에서 로그온 시 경고 메시지를 입력하고 설정 적용 및 서비스 재시작

### Unix 서버 로그온 경고 메시지 설정

#### ProFTP
1. **파일 경로 확인 및 수정**
   - `/etc/proftpd/proftpd.conf` 파일 내에 `welcome.msg` 파일 경로 확인 및 수정.
   ```markdown
   DisplayLogin <welcome.msg 파일 경로>
   ```
2. **메시지 수정**
   - `<welcome.msg 파일 경로>` 파일 내에 설정된 FTP 서버 로그온 경고 메시지를 수정.
3. **설정 적용 및 재시작**
   ```bash
   # svcadm refresh proftpd
   ```

#### Linux 서버

##### /etc/motd, /etc/issue 파일
1. **경고 메시지 수정**
   - `/etc/motd`, `/etc/issue` 파일 내에 경고 메시지를 수정.

##### Telnet
1. **로그온 경고 메시지 수정**
   - `/etc/issue.net` 파일 내에 로그온 경고 메시지를 수정.

##### SSH
1. **배너 설정 확인 및 수정**
   - `/etc/ssh/sshd_config` 파일 내에 배너 경고 메시지 파일 경로 확인 및 수정.
   ```markdown
   Banner /etc/issue.net <경고 메시지가 작성된 파일 경로>
   ```
2. **메시지 수정**
   - `<SSH 배너 설정 파일 경로>` 파일 내에 경고 메시지를 수정 (일반적으로 `/etc/issue` 또는 `/etc/issue.net` 파일 사용).
3. **설정 적용 및 재시작**
   ```bash
   # systemctl restart sshd
   ```

##### Sendmail
1. **SMTP 서버 로그온 시 경고 메시지 수정**
   - `/etc/mail/sendmail.cf` 파일 내에 설정된 SMTP 서버 로그온 시 경고 메시지를 수정.
   ```markdown
   SmtpGreetingMessage=<경고 메시지>
   ```
2. **설정 적용 및 재시작**
   ```bash
   # systemctl restart sendmail
   ```

##### Postfix
1. **SMTP 서버 로그온 시 경고 메시지 수정**
   - `/etc/postfix/main.cf` 파일 내에 설정된 SMTP 서버 로그온 시 경고 메시지를 수정.
   ```markdown
   smtpd_banner = <경고 메시지>
   ```
2. **설정 적용 및 재시작**
   ```bash
   # systemctl restart postfix
   ```

#### Exim
1. **SMTP 서버 로그온 시 경고 메시지 수정**
   - `/exim/exim.conf` 또는 `/exim4/exim4.conf` 파일 내에 설정된 SMTP 서버 로그온 시 경고 메시지를 수정.
2. **메시지 수정**
   - `smtp_banner = <경고 메시지>`
3. **설정 적용 및 재시작**
   ```bash
   # systemctl restart exim
   ```

#### vsFTP
1. **FTP 서버 로그온 시 경고 메시지 수정**
   - `/etc/vsftpd.conf` 또는 `/etc/vsftpd/vsftpd.conf` 파일 내에 설정된 FTP 서버 로그온 시 경고 메시지를 수정.
   ```markdown
   ftpd_banner=<경고 메시지>
   ```
2. **설정 적용 및 재시작**
   ```bash
   # systemctl restart vsftpd
   ```

#### DNS
1. **경고 메시지 수정**
   - `/etc/named.conf` 또는 `/etc/bind/named.conf.options` 파일 내에 설정된 경고 메시지를 수정.
   ```markdown
   version <경고 메시지>;
   ```
2. **설정 적용 및 재시작**
   ```bash
   # systemctl restart named
   ```

### sudo 명령어 접근 관리

#### 개요
- `/etc/sudoers` 파일 권한 적절성 여부 점검.
- 비인가자가 관리자 권한을 남용하여 시스템 손상, 악성 코드 실행, 민감한 데이터 유출 등의 보안 위협 방지.

#### 점검 내용
- `/etc/sudoers` 파일 소유자가 root이고, 파일 권한이 640인 경우가 양호.
- 그렇지 않은 경우 취약.

#### 조치 방법
- `/etc/sudoers` 파일 소유자 및 권한을 변경.
```bash
# chown root /etc/sudoers
# chmod 640 /etc/sudoer
```

#### 개요
- 시스템에서 최신 패치가 적용 여부 점검.
- 시스템 안정성 및 보안성을 확보하기 위함.

#### 점검 내용
- 패치 적용 정책을 수립하여 주기적으로 패치 관리를 하고 있으며, 패치 관련 내용을 확인하고 적용하였을 경우가 양호.
- 그렇지 않은 경우 취약.

#### 조치 방법
- O/S 관리자, 서비스 개발자가 패치 적용에 따른 서비스 영향 정도를 파악하여 주기적인 패치 적용 정책을 수립하여 적용해야 함.

### NTP 및 시각 동기화 설정

#### 개요
NTP (Network Time Protocol) 및 시각 동기화 설정 여부를 점검합니다. 시간 동기화는 인증 및 감사 목적을 위한 필수적입니다.

#### 점검 내용
- NTP 및 시각 동기화 설정 여부 점검

#### 점검 목적
- 시간 동기화가 없으면 보안 사고 및 장애 발생 시 로그에 대한 신뢰도 확보 미흡 위험이 있습니다.

#### 보안 위협
존재함

#### 참고
없음

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: NTP 및 시각 동기화 설정이 기준에 따라 적용된 경우
- **취약**: NTP 및 시각 동기화 설정이 기준에 따라 적용되어 있지 않은 경우

#### 조치 방법
NTP 설정 및 동기화 주기를 설정합니다.

#### 조치 시 영향
일반적인 경우 영향 없음

#### 점검 및 조치 사례
- **SOLARIS, AIX, HP-UX**
  - 동기화된 NTP 서버 확인: `# ntpq -pn`
  - /etc/ntp.conf 파일 내의 NTP 설정값 수정: `server <NTP 서버>`
  - NTP 서비스 재시작
- **LINUX**
  - NTP 서비스 활성화 여부 확인: `# systemctl list-units --type=service | grep ntp`
  - 동기화된 NTP 서버 확인: `# ntpq -pn`

### 정책에 따른 시스템 로깅 설정

#### 개요
내부 정책에 따른 시스템 로깅 설정 여부를 점검합니다. 보안 사고 발생 시 원인 파악 및 각종 침해 사실 확인을 위해 필요합니다.

#### 점검 내용
- 내부 정책에 따른 시스템 로깅 설정 여부 점검

#### 점검 목적
로깅 설정이 되어 있지 않을 경우, 원인 규명이 어려우며 법적 대응을 위한 충분한 증거로 사용할 수 없는 위험이 존재합니다.

#### 보안 위협
없음

#### 참고
감사 설정이 너무 높으면 보안 로그에 불필요한 항목이 많이 기록되어 중요한 항목과 혼동할 수 있으며 시스템 성능에도 심각한 영향을 줄 수 있으므로 법적 요구 사항과 조직의 정책에 따라 필요한 로그를 남기도록 설정해야 합니다.

#### 점검 대상 및 판단 기준
- **대상**: SOLARIS, LINUX, AIX, HP-UX 등
- **양호**: 로그 기록 정책이 보안 정책에 따라 설정되어 있으며, 로그를 남기고 있는 경우
- **취약**: 로그 기록 정책 미수립 또는 정책에 따라 설정되어 있지 않거나, 로그를 남기고 있지 않은 경우

#### 조치 방법
로그 기록 정책을 수립하고, 정책에 따라 (r)syslog.conf 파일을 설정합니다.

#### 조치 시 영향
시스템 성능과 로그 저장에 따른 서버 용량 부족 문제가 발생할 수 있으므로 시스템 운영 환경과 특성을 고려하여 적용해야 합니다.

#### 점검 및 조치 사례
- **SOLARIS**
  - /etc/syslog.conf 파일 내에 설정된 로그 기록 정책 수정
  - 설정 적용 및 재시작
- **LINUX**
  - /etc/rsyslog.conf 또는 /etc/rsyslog.d/default.conf 파일 내에 설정된 로그 기록 정책 수정
  - 설정 적용 및 재시작
