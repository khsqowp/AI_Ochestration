# 4-1. 보안장비(방화벽·IDS) 운영 관리

### 웹 서비스 WebDAV 비활성화

#### 개요
점검 내용: 웹 서비스 WebDAV 비활성화 여부 점검  
점검 목적: WebDAV에서 발견되는 다수의 인증 우회 취약점을 제거하고자 함.

#### 보안 위협
WebDAV가 활성화되어 있는 경우, 웹 서비스에 악의적으로 작성된 요청을 이용하여 인증을 우회함으로써 비밀번호로 보호된 WebDAV의 자원에 접근 (디렉터리 열람, 파일 다운로드 등)이 가능하며, WebDAV에 의해 호출된 일부 구성요소에 매개 변수를 정확하게 점검하지 않는 결함이 존재하여 버퍼 오버런이 발생할 위험이 존재함.

#### 점검 대상 및 판단 기준
- **대상**: Apache, Nginx, IIS, WebtoB  
- **양호**: WebDAV 서비스를 비활성화하고 있는 경우  
- **취약**: WebDAV 서비스를 활성화하고 있는 경우

#### 조치 방법
WebDAV 서비스 비활성화 설정.

#### 조치 시 영향
일반적인 경우 영향 없음.

#### 점검 및 조치 사례
- **Apache**
  - `httpd.conf` 파일 내 모든 디렉터리에서 WebDAV 설정 확인 및 비활성화 또는 주석 처리.
  ```plaintext
  <Directory "/path/to/directory">
    Dav Off
  </Directory>
  ```
- **Nginx**
  - `nginx.conf` 파일 내 모든 디렉터리에서 WebDAV 설정 확인 및 주석 처리 또는 제거.
  ```plaintext
  location /webdav {
    root /path/to/webdav;
    dav_methods PUT DELETE MKCOL COPY MOVE;
    dav_access user:rw group:rw all:r;
    create_full_put_path on;
  }
  ```
- **IIS**
  - WebDAV 금지 설정 확인 및 제거.
  - `ISAPI 및 CGI 제한` 선택, WebDAV 항목 선택 > `확장 경로 실행 허용(A)` 체크 해제.

### 웹 서비스 SSI(Server Side Includes) 사용 제한

#### 개요
점검 내용: 웹 서비스 SSI 사용 제한 설정 여부 점검  
점검 목적: 웹 서비스 내 SSI 사용을 제한하여 불법적인 데이터 접근을 차단하여 웹 서버의 보안을 강화하기 위함.

#### 보안 위협
웹 서비스 내 SSI 사용을 제한하지 않을 경우, 공격자가 SSI 기능을 이용하여 시스템 명령 실행 및 중요 파일 탈취 등 공격이 가능하며, 이를 통해 서버 시스템 침해, 데이터 유출 등이 발생할 위험이 존재함.

#### 점검 대상 및 판단 기준
- **대상**: Apache, Tomcat, Nginx, IIS, WebtoB  
- **양호**: 웹 서비스 SSI 사용 설정이 비활성화되어 있는 경우  
- **취약**: 웹 서비스 SSI 사용 설정이 활성화되어 있는 경우

#### 조치 방법
웹 서비스 내 불필요한 SSI 사용 제한 설정.

#### 조치 시 영향
일반적인 경우 영향 없음.

#### 점검 및 조치 사례
- **Apache**
  - `Options` 지시자 `Includes` 옵션 확인 및 제거.
  ```plaintext
  <Directory />
    Options
  </Directory>
  ```
- **Tomcat**
  - `web.xml` 파일 내 SSI 서블릿 또는 필터 사용 설정 확인 및 삭제 또는 주석 처리.
  ```xml
  <servlet-mapping>
    <servlet-name>SSIServlet</servlet-name>
    <url-pattern>*.shtml</url-pattern>
  </servlet-mapping>
  ```
- **Nginx**
  - `nginx.conf` 파일 내 SSI 옵션 사용 여부 확인 및 설정.
  ```plaintext
  location / {
    ssi off;
  }
  ```

이 청크에서 다룬 내용은 웹 서비스의 헤더 정보 노출, 가상 디렉토리 삭제, WebDAV 비활성화, 그리고 SSI 사용 제한 등에 대한 점검 및 조치 방법을 포함하고 있습니다. 각 항목별로 개요, 보안 위협, 점검 대상 및 판단 기준, 조치 방법, 그리고 조치 시 영향 등을 상세히 설명하며, 다양한 웹 서버와 애플리케이션에 대한 구체적인 사례를 제공하고 있습니다.

### SSL/TLS 활성화

#### 개요
서버와 클라이언트 간 통신 시 데이터 암호화 전송 여부를 점검합니다. SSL/TLS가 활성화되어 있지 않을 경우, 데이터는 암호화되지 않아 공격자가 중간에서 데이터를 가로채거나 도청할 수 있으며, 평문으로 전송되어 중간에서 변경될 우려가 있어 데이터의 정확성이 훼손될 위험이 존재합니다.

#### 점검 목적
인증 암호화 접속을 통해 스니핑을 통한 정보 유출의 위험을 방지하기 위함입니다. SSL/TLS 설정이 비활성화되어 있는 경우, 간단한 도청(스니핑)을 통해 정보가 탈취 및 도용될 위험이 존재합니다.

#### 보안 위협
- **SSL/TLS 비활성화**: 데이터는 암호화되지 않아 공격자가 중간에서 데이터를 가로채거나 도청할 수 있으며, 평문으로 전송되어 중간에서 변경될 우려가 있어 데이터의 정확성이 훼손될 위험이 존재합니다.
- **스니핑**: 스니퍼(Sniffer)는 "컴퓨터 네트워크상에 흘러 다니는 트래픽을 엿듣는 도청장치"라고 말할 수 있으며, "스니핑"이란 이러한 스니퍼를 이용하여 네트워크상의 데이터를 도청하는 행위를 말합니다.

#### 참고
- **SSL(Secure Socket Layer)**: 인터넷상에서 정보를 암호화하여 송/수신하는 프로토콜입니다. 현재 인터넷에서 널리 쓰이고 있는 www, FTP 등의 데이터를 암호화하여, 프라이버시에 관한 정보나 신용카드 번호, 기업 비밀 등을 안전하게 송/수신할 수 있습니다.

#### 점검 대상 및 판단 기준
- **대상**: Apache, Nginx, IIS, WebtoB
- **양호**: SSL/TLS 설정이 활성화되어 있는 경우
- **취약**: SSL/TLS 설정이 비활성화되어 있는 경우

#### 조치 방법
웹 서비스 내 SSL/TLS 활성화 설정입니다.

#### 조치 시 영향
일반적인 경우 영향 없음입니다.

#### 점검 및 조치 사례
- **Apache**
  - **Step 1**: SSL 모듈 활성화 확인
    ```bash
    # apache2ctl –M | grep ssl
    ssl_module (shared)
    ```
  - **Step 2**: SSL 가상 호스트 설정에 SSL 인증서 설정 추가
    ```apache
    <VirtualHost *:443>
        SSLEngine on
        SSLCertificateFile /path/to/your_domain_name.crt
        SSLCertificateKeyFile /path/to/your_domain_name.key
    </VirtualHost>
    ```
  - **Step 3**: SSL 가상 호스트 활성화
    ```bash
    # a2ensite default-ssl
    ```
  - **Step 4**: Apache 재구동
    ```bash
    # systemctl restart apache2
    ```

- **Nginx**
  - **Step 1**: SSL 인증서 파일 및 개인키 파일 준비
  - **Step 2**: nginx.conf 파일 내 SSL/TLS 설정
    ```nginx
    server {
        listen 80;
        server_name example.com;
        location / {
            return 301 https://$host$request_uri;
        }
    }

    server {
        listen 443 ssl;
        server_name example.com;
        ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_prefer_server_ciphers on;
        ssl_ciphers 'SSL_CIPHERS';
    }
    ```
  - **Step 3**: Nginx 재구동
    ```bash
    # systemctl restart nginx
    ```

- **IIS**
  - **Step 1**: SSL 인증서 바인딩 설정
  - **Step 2**: SSL 인증서 가져오기
  - **Step 3**: SSL 인증서 설치
  - **Step 4**: 추가된 인증서 확인
  - **Step 5**: 인증서 등록
    ```bash
    # C:\Windows\System32\mmc.exe > 파일 > 스냅인 추가/제거 > 인증서 > 추가 > 이 스냅인이 항상 관리할 인증서 대상 ‘컴퓨터 계정’ > 로컬 컴퓨터 > 확인
    ```
  - **Step 6**: IIS 서버 재구동

- **WebtoB**
  - **Step 1**: http.m 파일 내 SSLFlag, SSLName 설정 확인
    ```bash
    # vi /[WebtoB 설치 디렉터리]/config/http.m
    *VHOST
    vhost1 ...
    ERRORDOCUMENT = "400,401,403,404,405,406,503",
    SSLFLAG = Y,
    SSLNAME = "ssl_nxcore",
    LOGGING = "acc_https",
    ```
  - **Step 2**: http.m 파일 내 인증서 설정 파일 확인
    ```bash
    # vi /[WebtoB 설치 디렉터리]/config/http.m
    *SSL
    ssl_nxcore CertificateFile = "/sw/webtob5/ssl/2023/cert.crt",
    CertificateKeyFile = "/sw/webtob5/ssl/2023/privkey.key",
    CertificateChainFile = "/sw/webtob5/ssl/2023/chain.crt",
    CACertificateFile = "/sw/webtob5/ssl/2023/rootca.crt",
    PassPhraseDialog = "file:/sw/webtob5/ssl/passwd",
    Protocols = "-SSLv2, -SSLv3, -TLSv1, -TLSv1.1, TLSv1.2, TLSv1.3",
    RequiredCiphers = "HIGH:!RSA:!SHA1"
    ```
  - **Step 3**: CA 인증서 및 개인키를 생성해 WebtoB 설정 파일에 설정

### 1. 웹 서비스 설정 및 보안점검

#### 1.1 에러 페이지 일원화
- **설정 파일 수정**:
  ```bash
  # vi /[WebtoB 설치 디렉터리]/config/http.m
  *ERRORDOCUMENT
  503 status = 503,
  url = "/503.html"
  ```
- **에러 메시지 내용 확인 및 수정**:
  ```bash
  # vi /[WebtoB 설치 디렉터리]/docs/503.html
  HTTP Error 503 - Service unavailable
  ```
  →
  ```html
  죄송합니다. 요청하신 페이지를 찾을 수 없습니다.
  ```
- **설정 파일 컴파일 및 재구동**:
  ```bash
  # wscfl -I http.m
  # wsdown
  # wsboot
  ```

#### 1.2 LDAP 알고리즘 적절한 구성
- **점검 내용**: LDAP 연결 시 취약한 알고리즘 사용 제한 설정 여부 점검.
- **점검 목적**: 스니핑 등의 공격에 대비하기 위함.
- **보안 위협**: 취약한 다이제스트 알고리즘을 사용하는 경우 인증 정보 노출 위험이 존재.
- **대상**: Tomcat
- **판단 기준**:
  - 양호: 안전한 비밀번호 다이제스트 알고리즘 사용.
  - 취약: 안전한 비밀번호 다이제스트 알고리즘 미사용.
- **조치 방법**: SHA-256 이상의 알고리즘을 사용하도록 설정.
  ```bash
  # grep 'digest=' /[Tomcat 설치 디렉터리]/conf/server.xml
  digest="SSHA"
  ```
  →
  ```xml
  digest="SHA-256"
  ```

#### 1.3 별도의 업로드 경로 사용 및 권한 설정
- **점검 내용**: 웹 서비스 제공 시 이용되는 파일 전송의 업로드 경로를 별도의 디렉터리 사용 및 적절한 권한 설정 여부 점검.
- **점검 목적**: 루트 디렉터리 내 악의적인 파일 업로드 및 실행을 방지하기 위함.
- **보안 위협**: 일반 사용자의 접근 권한이 부여된 경우, 시스템 침투 등의 가능성이 있음.
- **대상**: Apache, Tomcat, Nginx, IIS, JEUS, WebtoB
- **판단 기준**:
  - 양호: 별도의 업로드 경로 사용 및 일반 사용자의 접근 권한 미부여.
  - 취약: 별도의 업로드 경로 미사용 또는 일반 사용자 접근 권한 부여.
- **조치 방법**: 별도의 업로드 경로 생성 및 권한 설정 제한.
  ```bash
  # mkdir [웹서비스 디렉터리 외 경로]
  # chmod 750 /[디렉터리 경로]
  # chown [유저]:[그룹] /[디렉터리 경로]
  ```

#### 1.4 주기적 보안 패치 및 벤더 권고사항 적용
- **점검 내용**: 최신 보안 패치 적용 여부 점검.
- **점검 목적**: 보안성 및 시스템 안정성을 확보하기 위함.
- **보안 위협**: 알려진 취약점을 이용한 공격 또는 새로운 공격에 대한 침해사고 발생 위험이 존재.
- **대상**: Apache, Tomcat, Nginx, IIS, JEUS, WebtoB
- **판단 기준**:
  - 양호: 최신 보안 패치가 적용되어 있으며, 패치 적용 정책 수립.
  - 취약: 최신 보안 패치 미적용 또는 패치 적용 정책 미수립.
- **조치 방법**: 패치 적용에 따른 서비스 영향을 파악하여 주기적인 패치 적용 정책 수립 및 적용.
  ```bash
  # /[웹 서버 설치 디렉터리]/[웹 서버] –v
  ```

#### 1.5 로그 디렉터리 및 파일 권한 설정
- **점검 내용**: 비인가자의 로그 디렉터리 및 파일의 접근을 차단하기 위한 권한 적절성 여부 점검.
- **점검 목적**: 정보유출, 로그 파일 훼손 및 변조를 방지하기 위함.
- **보안 위협**: 일반 사용자에 의한 정보 유출 또는 로그 조작 등의 공격 위험이 존재.
- **대상**: Apache, Tomcat, Nginx, IIS, JEUS, WebtoB
- **판단 기준**:
  - 양호: 로그 디렉터리 및 파일에 일반 사용자의 접근 권한이 없는 경우.
  - 취약: 로그 디렉터리 및 파일에 일반 사용자 접근 권한이 있는 경우.
- **조치 방법**: 로그 디렉터리 및 파일에 일반 사용자 접근 권한 제거 설정.
  ```bash
  # chmod o-rwx /[로그 파일 경로]
  ```

### 계정 관리

#### 기본 개념 및 기법
- **기본 계정 변경**: 보안 장비의 기본 관리자 계정을 변경하여 비인가자가 기본 계정을 통한 접근을 방지하는 방법.
- **비밀번호 관리 정책 설정**: 비밀번호 복잡성, 길이, 사용 및 최대 기간 등에 대한 정책을 적용하여 무차별 대입 공격과 사전 대입 공격을 방어한다.
- **계정별 권한 설정**: 각 계정의 용도에 따라 적절한 권한을 부여하여 권한 없는 사용자의 설정 변경으로 인한 시스템 침입 경로를 줄인다.
- **계정 관리**: 사용하지 않는 계정을 제거 또는 관리하여 공격을 차단한다.

#### 취약점
- **기본 계정 사용**: 기본 관리자 계정이 변경되지 않은 경우, 비인가자가 기본 계정을 통한 접근을 통해 보안 장비 설정값을 변경하거나 시스템 침입 경로를 제공할 수 있다.
- **비밀번호 정책 미적용**: 비밀번호 관리 정책에 맞지 않는 비밀번호 사용 시, 무차별 대입 공격이나 사전 대입 공격으로 인해 계정 비밀번호가 유출될 위험이 있다.
- **불필요한 권한**: 업무에 불필요한 권한이 부여된 경우, 권한 없는 사용자의 의도하지 않은 설정 변경으로 인한 시스템 침입 경로를 제공할 수 있다.
- **사용하지 않는 계정**: 사용하지 않는 계정이 관리되지 않으면, 비인가자가 공격을 통해 불필요한 계정 탈취의 위험이 존재한다.

#### 절차
1. **기본 계정 변경**
   - Web을 통한 접속 후 기본 계정과 비밀번호 입력하여 접속 확인.
   - 보안 장비에서 제공하는 계정 메뉴에서 기본 계정 변경.
   - 기본 계정 변경이 불가능할 경우, 기본 비밀번호 변경으로 보완 필요.

2. **비밀번호 관리 정책 설정**
   - Web을 통한 접속 후 기본 계정과 비밀번호 입력하여 접속 확인.
   - 비밀번호 메뉴에서 비밀번호 변경.
   - 복잡성 및 최소 길이: 특수문자, 숫자, 영 소문자 포함 8자리 이상, 최소 사용기간(1일) 설정.

3. **계정별 권한 설정**
   - 보안 장비에서 제공하는 계정 메뉴에서 계정별 권한 확인.
   - 기존 계정의 권한 검토 및 불필요한 권한 삭제.
   - 단일 계정을 여러 사용자가 공유 시, 사용자별 계정 생성 및 권한 차등 부여.

4. **계정 관리**
   - 보안 장비에서 제공하는 계정 메뉴에서 계정 및 담당자 확인.
   - 사용하지 않는 계정 삭제.
   - 공용 계정 사용 시, 사용자별 계정 생성 및 시스템 접근 이력을 관리하여 책임 추적성 확보.

- **최소 사용기간**: 1일

### 보안 장비 로그 관리

#### 개요
로그 관리는 보안 장비의 중요한 부분으로, 적절한 로그 보관 및 설정을 통해 보안 장비 침해사고 원인 분석에 필요한 정보를 안전하게 유지할 수 있습니다.

#### 점검 내용
- **로그 보관 정책**: 로그가 3개월 이상 보관되는지 확인합니다.
- **보안 장비 설정 파일 백업**: 설정 파일이 백업되어 있는지 점검합니다.
- **원격 로그 서버 사용**: 로그를 원격 로그 서버에 별도로 보관하는지 확인합니다.
- **NTP 및 시각 동기화 설정**: NTP와 시간 동기화가 설정되어 있는지 점검합니다.

#### 점검 목적
- **로그 보관 정책**: 로그 검토나 사고 원인 분석에 필요한 정보를 유지하기 위함입니다.
- **보안 장비 설정 파일 백업**: 장애 발생 시 즉시 복구할 수 있도록 대비합니다.
- **원격 로그 서버 사용**: 로그 삭제 및 변조에 대비하여 사고 원인 분석이 용이하도록 합니다.
- **NTP 및 시각 동기화 설정**: 이벤트 간의 인과 관계 파악과 로그 신뢰성을 높이기 위함입니다.

#### 보안 위협
- **로그 보관 정책**: 로그가 충분히 보관되지 않을 경우, 사고 원인 분석이 어려워집니다.
- **보안 장비 설정 파일 백업**: 백업되지 않은 설정 파일로 인해 복구가 어렵습니다.
- **원격 로그 서버 사용**: 원격 로그 서버가 구축되어 있지 않거나 설정되지 않을 경우, 사고 원인 분석이 어려워집니다.
- **NTP 및 시각 동기화 설정**: 시간 동기화 미흡으로 인해 로그 신뢰도가 떨어질 수 있습니다.

#### 참고
- **로그 보관 기간**: 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제45조 제2항에 따른 과학기술정보통신부 고시에 따릅니다.
- **NTP(Network Time Protocol)**: 네트워크를 통해 컴퓨터 시스템 간의 시간을 정확하게 유지하기 위한 프로토콜입니다.

#### 점검 대상 및 판단 기준
- **대상**: 방화벽, VPN, IDS, IPS, Anti-DDoS, 웹 방화벽 등
- **판단 기준**:
  - 로그 보관 정책: 설정된 경우 양호, 그렇지 않으면 취약.
  - 설정 파일 백업: 별도의 파일로 보관된 경우 양호, 그렇지 않으면 취약.
  - 원격 로그 서버 사용: 구축되어 있고 설정된 경우 양호, 그렇지 않으면 취약.
  - NTP 및 시각 동기화 설정: 설정된 경우 양호, 그렇지 않으면 취약.

#### 조치 방법
- **로그 보관 정책**: 로그를 정기적으로 분석 및 검토합니다.
- **보안 장비 설정 파일 백업**: 정책을 별도의 파일로 보관합니다.
- **원격 로그 서버 사용**: 원격 로그 서버에 저장될 로그를 기관 정책에 맞게 설정합니다.
- **NTP 및 시각 동기화 설정**: 시간 설정에서 NTP 및 시간 동기화 설정을 확인합니다.

#### 조치 시 영향
- 모든 조치는 일반적으로 영향 없음입니다.

#### 점검 및 조치 사례
- **로그 보관 정책**: 로그 날짜와 저장기간을 확인하고 필요하다면 변경합니다.
- **보안 장비 설정 파일 백업**: 정책을 별도의 파일로 보관합니다.
- **원격 로그 서버 사용**: syslog 설정 및 원격 로그 서버 설정을 확인합니다.
- **NTP 및 시각 동기화 설정**: NTP 프로토콜 연동과 NTP 서버 연동을 확인합니다.

#### 점검 목적
- **정책 관리**: 보안 장비의 고가용성을 유지하고 네트워크 보안 체계를 강화하기 위함입니다.

- **미사용 및 중복된 정책**: 관리자가 인지하지 못한 정책으로 인해 네트워크 보안 체계가 약화될 수 있습니다.

#### 참고
- **발생할 수 있는 보안 위협**: 비인가자의 네트워크 접근 및 내부 정보 유출, 악성코드 삽입 등

#### 점검 대상 및 판단 기준
- **대상**: 방화벽, VPN, IDS, IPS, Anti-DDoS, 웹 방화벽 등
- **판단 기준**:
  - 정책에 대한 주기적인 검사로 미사용 및 중복된 정책을 확인하고 제거된 경우 양호, 그렇지 않으면 취약.

#### 조치 방법
- **정책 관리**: 정책에 대한 주기적인 검사로 미사용 및 중복된 정책을 확인하여 제거합니다.

#### 조치 시 영향
- 모든 조치는 일반적으로 영향 없음입니다.

#### 점검 및 조치 사례
- **정책 관리**: 정책에 대한 주기적인 검사와 미사용 및 중복된 정책의 제거를 통해 보안 장비 관리자의 업무 편의성 및 효율성을 높이고, 네트워크 보안 체계를 강화합니다.

### NAT 설정

#### 개요
NAT(Network Address Translation)는 외부 공개 필요성이 없는 정보시스템을 보호하기 위해 사용됩니다. NAT 설정을 통해 내부 사설 IP를 공인 IP로 변환하여 정보 유출, 시스템 파괴 등의 위험을 줄일 수 있습니다.

#### 점검 내용
- **NAT 설정 여부**: 외부 공개 필요성이 없는 서버, 단말기 등에 대해 NAT 설정이 적용되어 있는지 확인합니다.

#### 점검 목적
- **네트워크 보호**: 비인가자가 내부 시스템을 공격하기 위해서는 내부 사설 IP를 알아야 하므로 NAT 설정을 통해 네트워크를 보호할 수 있습니다.

#### 보안 위협
- **NAT 설정 미흡**: 공인 IP를 통해 시스템에 접근이 가능하여 정보 유출, 시스템 파괴, 악성코드 전파 등의 불법적 행위가 발생할 위험이 존재합니다.

#### 참고
- **NAT 사용 목적**:
  - 인터넷의 공인 IP주소 절약
  - 공공망과 연결되는 사용자들의 고유한 사설망을 침입자들로부터 보호

#### 점검 대상 및 판단 기준
- **대상**: 방화벽, VPN 등
- **판단 기준**:
  - 외부 공개 필요성이 없는 서버, 단말기 등에 대해 NAT 설정이 적용된 경우 양호, 그렇지 않으면 취약.

#### 조치 방법
- **NAT 설정**: 외부 공개 필요성이 없는 정보시스템에 대해 NAT 설정을 적용합니다.

#### 조치 시 영향
- 모든 조치는 일반적으로 영향 없음입니다.

#### 점검 및 조치 사례
- **NAT 설정**: 공인 IP 확인 사이트(포털 등)에 접속하여 사용 중인 단말의 IP를 확인하고, 필요하다면 NAT 설정을 적용합니다.

### DMZ 설정

**개요**
점검 내용: 내부 네트워크와 외부 서비스 네트워크(DMZ)를 구분하고 있는지, 외부 네트워크로 서비스를 제공하는 호스트에서 내부 네트워크로의 접근이 통제되고 있는지를 확인합니다.

**점검 목적**
DMZ 설정을 통해 내부 네트워크와 외부 서비스 네트워크를 구분하여, 외부 보안 위협 네트워크를 통해서 서비스를 제공받는 악의적인 사용자가 DMZ 내 호스트를 통해 내부 네트워크로 불법적 연결을 시도할 위험이 줄어듭니다.

**참고**
DMZ: 조직의 내부 네트워크와 외부 네트워크 사이에 위치하는 네트워크 망으로, DMZ 내 컴퓨터는 외부 네트워크에만 연결할 수 있도록 하고, 내부 네트워크로는 연결할 수 없도록 구성됩니다.

**점검 대상 및 판단 기준**
- **대상**: 방화벽, VPN 등
- **양호**: DMZ를 구성하여 내부 네트워크를 보호하는 경우
- **취약**: DMZ를 구성하지 않고 사설망에서 외부 공개 서비스를 제공하는 경우

**조치 방법**
- 물리적(망 분리)으로 내부 네트워크와 외부 서비스 네트워크가 분리되어 있으면 해당 없음
- 조치 시 영향: 일반적인 경우 영향 없음

**점검 및 조치 사례**
- **Step 1**: 네트워크 구성도 또는 방화벽 설정 확인
- **Step 2**: 방화벽의 옵션 설정 (삼각 방화벽 설정, 차단된 서브넷 방화벽(screened-subnet firewall))

### 최소한의 서비스만 제공

**개요**
점검 내용: 보안 장비에서 필요한 서비스만 제공하고 있는지 점검합니다.

**점검 목적**
보안 장비 정책을 검토하여 사용하지 않는 IP와 포트를 제거하여 네트워크 및 시스템 운영의 보안성을 유지하기 위함입니다.

**보안 위협**
최소한의 서비스만 제공하지 않을 경우, 비인가자의 침입 또는 악성 소프트웨어 전달 등의 보안 위험이 발생할 수 있습니다.

**참고**
방화벽 기본 정책: 방화벽은 기본적으로 All Deny 설정을 적용하며 허용할 IP와 포트만 추가함으로써 관리 포인트를 최소화합니다.

**점검 대상 및 판단 기준**
- **대상**: 방화벽, VPN, 웹 방화벽 등
- **양호**: All Deny 설정 및 보안 장비에 최소 서비스만 허용하는 경우
- **취약**: All Deny 미설정 또는 보안 장비에 불필요한 서비스를 허용하는 경우

**조치 방법**
보안 장비에 최소 서비스만 허용하도록 설정합니다.
- 조치 시 영향: 허용되지 않은 접속은 모두 차단됨

**점검 및 조치 사례**
- **Step 1**: 방화벽에서 허용되지 않은 포트 접속 확인
- **Step 2**: 방화벽 기본 정책인 all deny에 최소 서비스만 허용 확인 (허용된 IP와 서비스 포트만 오픈, 모든 IP 및 서비스 허용 금지)

### 이상징후 탐지 모니터링 수행

**개요**
점검 내용: 보안 장비에 이상징후 탐지 모니터링을 수행하고 있는지를 점검합니다.

**점검 목적**
이상징후가 탐지되는 경우 사고 예방 및 신속한 조치를 이행하기 위함입니다.

**보안 위협**
이상징후 탐지 모니터링을 수행하지 않을 경우, 보안 사고를 미리 방지할 수 없는 위험이 존재합니다.

**참고**
- 보안 사고 미연 방지 및 IT 컴플라이언스 준수
- 예시: 휴일 또는 업무 시간 이외에 비정상적인 패턴으로 중요 문서 또는 고객 정보 DB에 접근한다면 정보 유출 징후가 있다고 판단 가능

**점검 대상 및 판단 기준**
- **대상**: 방화벽, VPN, IDS, IPS, Anti-DDoS, 웹 방화벽 등
- **양호**: 이상징후 탐지 모니터링을 수행하고 있는 경우
- **취약**: 이상징후 탐지 모니터링을 수행하지 않은 경우

**조치 방법**
이상징후 탐지 시 담당자/관리자가 즉시 확인할 수 있도록 모니터링 수행합니다.
- 조치 시 영향: 일반적인 경우 영향 없음

**점검 및 조치 사례**
- **Step 1**: 보안 장비의 이상징후 탐지 모니터링 기능(알람, 이메일, SMS 등)이 설정되어 담당자가 즉시 인지할 방안이 있는지를 점검
- **Step 2**: 장비 자체 기능 대신 Syslog를 통해 모니터링 시스템으로 전송하는 경우, 해당 시스템의 모니터링 기능 설정 여부를 점검
- **Step 3**: 보안 장비 이상징후에 대해 실시간 모니터링 실시

- **취약**: 보안 장비 가용성을 정기적으로 모니터링 및 검토하지 않을 경우
