# 1-1. XSS / CSRF 공격 가능성

> 공격자가 웹 애플리케이션을 통해 다른 사용자에게 악성코드를 전달하거나,  
> 사용자 의도와 무관한 요청을 서버에 전송시키는 취약점 군.

---

## 1. XSS (Cross-Site Scripting)

### 근본적인 원인
사용자 입력값(URL, 폼 필드, 쿠키, 헤더 등)을 출력할 때 HTML 인코딩·이스케이프 없이 그대로 렌더링하면, 브라우저가 입력값을 HTML/JavaScript로 해석하여 실행함.

| 유형 | 설명 |
|------|------|
| Reflected XSS | URL 파라미터의 악성 스크립트가 즉시 응답에 반사되어 실행 |
| Stored XSS | 게시판·댓글 등에 저장된 악성 스크립트가 다른 사용자 조회 시 실행 |
| DOM-based XSS | 서버와 무관하게 브라우저의 DOM 생성 과정에서 스크립트 실행 |

XML에서 CDATA를 사용해 파싱되지 말아야 할 특수문자를 삽입한 뒤 악성코드를 전송하는 방식도 포함됨.

### 2차 피해 시나리오
- 쿠키/세션 탈취 → 계정 도용
- 악성코드 유포 사이트로 리다이렉트
- 키로거 삽입으로 사용자 입력 정보 수집
- CSRF 공격의 전단계로 활용 (스크립트로 위조 요청 자동 실행)
- 관리자 계정 탈취 시 전체 서비스 장악

### 해결 및 대응방안

**① 출력 시 HTML 인코딩 (가장 중요)**

출력 위치에 따라 인코딩 방식을 달리 적용해야 함:

| 출력 위치 | 인코딩 방식 |
|----------|------------|
| HTML 본문 | HTML Entity 인코딩 |
| HTML 속성값 | HTML 속성 인코딩 (따옴표 포함) |
| JavaScript 변수 | JavaScript 이스케이프 |
| URL 파라미터 | URL 인코딩 |

특수문자 → HTML Entity 변환표 (가이드라인 [표] 2 기준):

| From | To (문자표현) |
|------|-------------|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#39;` |
| `(` | `&#40;` |
| `)` | `&#41;` |
| `#` | `&#35;` |

```java
// Java/JSP: 출력 시 인코딩
public String clearXSS(String str) {
    str = str.replaceAll("<", "&lt;");
    str = str.replaceAll(">", "&gt;");
    str = str.replaceAll("\0", " ");
    return str;
}

// Spring: Thymeleaf는 기본적으로 자동 이스케이프
// th:text 사용 → 안전 / th:utext 사용 → 검증 필수
```

**② 입력 시 XSS 키워드 필터링**

가이드라인 [표] 3에 따라 아래 키워드를 대소문자 구분 없이 필터링:

```
<script>, javascript, vbscript, eval, expression, iframe, frame,
object, embed, applet, style, link, meta, base, bgsound, onXXX 이벤트 핸들러 전체
(onclick, onload, onerror, onmouseover 등 150개 이상)
```

```java
// JSP: 키워드 필터링 예시
public String xssFilter(String str) {
    String filstr = "<script>,javascript,eval,iframe,onload,...";
    filstr = filstr.replaceAll(" ", "");
    String[] st = filstr.split(",");
    for (int x = 0; x < st.length; x++) {
        str = str.replaceAll("(?i)" + st[x], "_" + st[x] + "_");
    }
    return str;
}
```

**③ AntiSamy 라이브러리 활용 (Java)**

태그 사용이 불가피한 경우 허용 태그·속성만 정의하고 나머지 제거:

```java
// web.xml 필터 등록
// <filter>
//   <filter-name>AntiXssFilter</filter-name>
//   <filter-class>test.antisamy.AntiXssFilter</filter-class>
// </filter>

// AntiXssFilter.java
import org.owasp.validator.html.*;

Policy policy = Policy.getInstance("antisamy-1.5.8.xml");
AntiSamy as = new AntiSamy(policy);
CleanResults cr = as.scan(userInput, AntiSamy.DOM);
return cr.getCleanHTML();
```

antisamy.xml 정책 예시:
```xml
<!-- 위험 태그 제거 -->
<tag name="script" action="remove"/>
<tag name="iframe" action="remove"/>
<tag name="style" action="remove"/>

<!-- 허용 태그 검증 -->
<tag name="p" action="validate">
    <attribute name="align"/>
</tag>
<tag name="b" action="validate"/>
```

**④ HttpOnly 쿠키 설정 (쿠키 탈취 차단)**

```java
// Java (web.xml)
<session-config>
  <cookie-config>
    <http-only>true</http-only>
    <secure>true</secure>
  </cookie-config>
</session-config>

// Spring Boot (application.properties)
server.servlet.session.cookie.http-only=true
server.servlet.session.cookie.secure=true
```

**⑤ Content Security Policy (CSP) 헤더 설정**

```java
// Spring: 응답 헤더에 CSP 추가
response.setHeader("Content-Security-Policy",
    "default-src 'self'; script-src 'self'; object-src 'none'");
```

### 보완방안
- HTML 메타 캐릭터 제거가 어려운 경우 **화이트리스트 방식** (`[A-Za-z0-9]`만 허용) 적용
- Positive 필터링 모드 우선 적용 후, 불가피한 경우만 Negative(블랙리스트) 병행
- 패스워드 필드는 특수문자 필터링 적용 여부를 별도 검토 (정책 충돌 가능)
- AntiSamy 필수 파일(antisamy.jar, xercesImpl.jar 등) 최신 버전 유지

## 2. CSRF (Cross-Site Request Forgery)

### 근본적인 원인
서버가 요청의 출처를 검증하지 않아, 공격자가 피해자 브라우저를 통해 인증된 상태로 의도하지 않은 요청을 전송할 수 있음.  
XSS로 삽입된 스크립트, 악성 이메일 링크, 이미지 태그 등이 트리거가 됨.

### 2차 피해 시나리오
- 로그인된 사용자의 계정 정보 변경 (이메일, 비밀번호)
- 관리자 계정으로 사용자 추가·삭제
- 금융 서비스에서 이체 요청 위조
- 게시판 글 자동 작성·삭제

### 해결 및 대응방안

**① CSRF 토큰 적용 (가장 중요)**

```java
// Spring Security (가장 권장)
// application 설정만으로 자동 적용 — 별도 코드 불필요
@Configuration
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.csrf().csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse());
        // REST API의 경우에만 disable 고려 (Stateless 구조)
    }
}

// 폼에 토큰 삽입 (Thymeleaf 자동 처리)
<form method="post" th:action="@{/submit}">
    <!-- Thymeleaf가 자동으로 _csrf 히든 필드 삽입 -->
</form>
```

**② SameSite 쿠키 속성 설정**

```java
// Spring Boot
server.servlet.session.cookie.same-site=strict

// 또는 수동 설정
ResponseCookie cookie = ResponseCookie.from("JSESSIONID", value)
    .sameSite("Strict")
    .httpOnly(true)
    .secure(true)
    .build();
response.addHeader(HttpHeaders.SET_COOKIE, cookie.toString());
```

**③ Referer / Origin 헤더 검증**

```java
// 요청의 Origin이 허용된 도메인인지 검증
String origin = request.getHeader("Origin");
if (origin != null && !origin.equals("https://example.com")) {
    response.sendError(403, "CSRF 차단");
    return;
}
```

### 보완방안
- 중요 작업(비밀번호 변경, 결제 등)은 재인증 요구
- GET 요청으로 상태 변경 작업 처리 금지 (GET은 조회 전용)
- AJAX 요청 시 커스텀 헤더(`X-Requested-With`) 포함 여부 서버에서 검증

---

## 공통 대응 원칙

| 원칙 | XSS | CSRF |
|------|-----|------|
| 입력 검증 | 키워드·특수문자 필터링 | 토큰·Origin 검증 |
| 출력 인코딩 | HTML Entity 인코딩 필수 | - |
| 쿠키 보안 | HttpOnly (스크립트 접근 차단) | SameSite (크로스사이트 전송 차단) |
| 프레임워크 활용 | AntiSamy, Thymeleaf 자동 이스케이프 | Spring Security CSRF 필터 |
