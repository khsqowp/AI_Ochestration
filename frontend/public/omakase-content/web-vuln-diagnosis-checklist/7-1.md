# 7-1. Client Request Method

> PUT, DELETE 등 불필요한 HTTP 메소드가 활성화되어 있을 때,  
> 공격자가 악성 파일 업로드, 중요 파일 삭제, 웹 사이트 변조를 수행할 수 있는 취약점.

---

## 근본적인 원인

- 웹 서버 기본 설정에 PUT, DELETE, TRACE, MOVE, COPY 등이 활성화
- WebDAV 서비스가 불필요하게 활성화되어 PUT/DELETE 허용
- TRACE 메소드 활성화 → 쿠키 등 헤더 정보 반사 노출(XST, Cross-Site Tracing)
- 서비스 운영에 필요한 GET, POST, HEAD, OPTIONS 이외의 메소드를 제한하지 않음

---

## 2차 피해 시나리오

- PUT으로 악성 스크립트(웹쉘) 웹 서버에 직접 업로드
- DELETE로 중요 파일 삭제 → 서비스 중단
- TRACE로 HttpOnly 쿠키를 포함한 요청 헤더 반사 → XST 공격으로 세션 탈취

---

## 해결 및 대응방안

### ① Apache: LimitExcept로 불필요한 메소드 차단

```apache
# httpd.conf: GET, POST 외 모든 메소드 거부
<Directory /home>
    AllowOverride FileInfo AuthConfig Limit
    Options MultiViews FollowSymLinks IncludesNoExec
    <LimitExcept GET POST>
        Order allow,deny
        Deny from all
    </LimitExcept>
</Directory>

# TRACE 메소드 별도 비활성화 (기본값: 허용)
TraceEnable Off
```

```apache
# WebDAV 모듈 비활성화 (PUT, DELETE 등 차단)
# httpd.conf에서 DAV 관련 모듈 주석 처리 또는
<Directory "/usr/local/apache/htdocs">
    Dav Off
    <LimitExcept GET OPTIONS>
        Require user admin
    </LimitExcept>
</Directory>
```

### ② Tomcat web.xml: 불필요한 메소드 접근 거부

```xml
<!-- web.xml -->
<security-constraint>
  <display-name>HTTP Method Restriction</display-name>
  <web-resource-collection>
    <web-resource-name>Protected Area</web-resource-name>
    <url-pattern>/*</url-pattern>
    <!-- 이 메소드들에 대한 접근을 role 없이 차단 -->
    <http-method>DELETE</http-method>
    <http-method>TRACE</http-method>
    <http-method>PUT</http-method>
    <http-method>PATCH</http-method>
    <http-method>MOVE</http-method>
    <http-method>COPY</http-method>
    <http-method>MKCOL</http-method>
  </web-resource-collection>
  <auth-constraint>
    <role-name></role-name>  <!-- 빈 role → 아무도 접근 불가 -->
  </auth-constraint>
</security-constraint>
```

### ③ Spring Security: 특정 메소드 차단

```java
@Configuration
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
            .antMatchers(HttpMethod.DELETE, "/**").denyAll()
            .antMatchers(HttpMethod.PUT,    "/**").denyAll()
            .antMatchers(HttpMethod.TRACE,  "/**").denyAll()
            .antMatchers(HttpMethod.OPTIONS,"/**").denyAll()
            .anyRequest().authenticated();
    }
}
```

### ④ IIS 5.x/6.x: WebDAV 비활성화

```
IIS 5.x: 레지스트리 경로 설정
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\W3svc\Parameters
값: DisableWebDAV = 1 (DWORD)
→ 반드시 시스템 재시작 필요

IIS 6.x: 컴퓨터 관리 → 서비스 및 응용프로그램 → IIS → 웹 서비스 확장
→ WebDAV 금지

IIS 7.x/8.x/10.x: IIS 관리자 → ISAPI 및 CGI 제한 → WebDAV 제거 또는 비활성화
```

### ⑤ Nginx: 허용 메소드 명시

```nginx
server {
    location / {
        # GET, POST, HEAD만 허용
        limit_except GET POST HEAD {
            deny all;
        }
    }
}
```

### ⑥ WebToB: 불필요한 메소드 제거 후 재기동

```
# http.m
*NODE
webmain WEBTOBDIR = "/usr/local/webtob",
    ...
    Method = "-PUT, -DELETE, -MOVE, -TRACE"
```

### ⑦ iPlanet: obj.conf에서 메소드별 오류 처리

```apache
# obj.conf: TRACE, PUT, DELETE, MOVE, MKDIR, RMDIR → 501 오류 반환
<Client method="TRACE">
  AuthTrans fn="set-variable" remove-headers="transfer-encoding"
  set-headers="content-length: -1" error="501"
</Client>
<Client method="PUT">
  AuthTrans fn="set-variable" remove-headers="transfer-encoding"
  set-headers="content-length: -1" error="501"
</Client>
<Client method="DELETE">
  AuthTrans fn="set-variable" remove-headers="transfer-encoding"
  set-headers="content-length: -1" error="501"
</Client>

# TRACE: obj.conf의 해당 줄 주석 처리
# Service method="TRACE" fn="service-trace"
```

## 보완방안

- REST API에서 DELETE가 필요한 경우 해당 경로에만 제한적으로 허용 (전체 경로 허용 금지)
- 메소드 차단 후 서비스 영향도 확인 필수 — 특히 OPTIONS가 필요한 CORS 환경 고려
