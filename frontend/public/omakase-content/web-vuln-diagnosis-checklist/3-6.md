# 3-6. 백업 파일 및 테스트 파일 존재 여부

> 개발·운영 중 생성된 백업 파일, 테스트 파일, 디폴트 페이지가 웹 루트에 방치되어  
> 공격자가 이를 발견하고 서버 정보·소스코드·개인정보를 획득하거나 2차 공격에 활용하는 취약점.

---

## 근본적인 원인

- 개발·운영 과정에서 생성한 백업 파일(`.bak`, `.old`, `.zip`, `~` 등)을 웹 서버에서 미삭제
- `test.php`, `test.jsp`, `debug.asp` 등 테스트 파일을 운영 서버에 방치
- 웹 서버·에디터 초기 설치 시 생성되는 디폴트 페이지·샘플 페이지 미제거
- FCKeditor, CKEditor 등 에디터의 샘플 페이지가 그대로 노출

---

## 2차 피해 시나리오

- 백업 파일(`.zip`, `.tar.gz`, `.sql`)로 소스코드·DB 덤프 다운로드 → DB 접속정보, 비밀키 탈취
- FCKeditor 샘플 페이지를 통한 디렉터리 탐색 → 파일 목록·서버 구조 파악
- 에디터 디폴트 업로드 기능으로 악성코드 업로드
- 테스트 파일에 남겨진 하드코딩된 계정·API 키 노출

---

## 해결 및 대응방안

### ① 불필요한 파일 전수 점검 및 제거

점검 대상 파일 유형:
- 백업 파일: `*.bak`, `*.old`, `*.orig`, `*.tmp`, `*~`, `*.zip`, `*.tar.gz`, `*.sql`
- 테스트 파일: `test.*`, `debug.*`, `sample.*`, `demo.*`
- 디폴트 페이지: `index.bak`, `phpinfo.php`, `info.php`, `test.html`
- 에디터 샘플: `editor/samples/`, `fckeditor/`, `ckeditor/samples/`

```powershell
# 웹 루트에서 백업·테스트 파일 탐지 (점검 용도)
Get-ChildItem -Recurse -Include "*.bak","*.old","*test*","*backup*","*.tmp","*.zip","*.sql" `
    | Select-Object FullName
```

```bash
# Linux 서버 점검
find /var/www/html -name "*.bak" -o -name "*.old" -o -name "*.zip" \
     -o -name "test*" -o -name "*backup*" | sort
```

### ② 디폴트 페이지 제거 정책

```
- 초기 서비스 설치 시 디폴트로 설치된 콘텐츠·서비스 비활성화(Disable)
- 기본 패스워드 변경, 경로 변경 등 접근 제한 설정
- 디폴트 디렉터리(/htdocs, /cgi-bin 등) 삭제 또는 변경
- 디폴트 페이지(Manual, Sample 등) 삭제 또는 변경
```

### ③ 에디터 샘플·디폴트 파일 제거 또는 접근 차단

```apache
# Apache: 에디터 샘플 경로 접근 차단
<LocationMatch "/(fckeditor|ckeditor)/samples">
    Require all denied
</LocationMatch>
```

```java
// Spring Security: 에디터 샘플 경로 차단
.antMatchers("/fckeditor/samples/**", "/ckeditor/samples/**")
    .denyAll()
```

### ④ 운영 서버 배포 파이프라인에서 불필요 파일 자동 제외

```yaml
# .gitignore에 백업·테스트 파일 추가
*.bak
*.old
*.tmp
test_*.jsp
debug_*.php
/backup/
/temp/

# CI/CD 배포 스크립트에서 제외
rsync -av --exclude="*.bak" --exclude="*.old" --exclude="test*" src/ server:/var/www/html/
```

### ⑤ 웹 서버에서 백업 파일 확장자 다운로드 차단

```apache
# Apache: 백업 파일 확장자 직접 접근 차단
<FilesMatch "\.(bak|old|orig|tmp|zip|sql|tar\.gz)$">
    Require all denied
</FilesMatch>
```

```nginx
# Nginx: 백업 파일 차단
location ~* \.(bak|old|orig|tmp|zip|sql)$ {
    deny all;
    return 404;
}
```

---

## 보완방안

- 운영 환경 배포 전 체크리스트에 "백업·테스트 파일 제거" 항목 필수 포함
- 파일 접근 로그 정기 검토 (`.bak`, `.zip` 등 비정상 확장자 접근 탐지)
- 웹 루트 디렉터리 구조를 주기적으로 감사하여 신규 불필요 파일 탐지
