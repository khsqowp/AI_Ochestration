# 3-5. 검색엔진 정보 노출 가능성

> 검색 엔진 크롤러가 웹 서비스의 민감한 정보(시스템 정보, 개인정보, 내부 경로 등)를  
> 수집하여 인덱싱함으로써 해킹에 필요한 정보를 외부에 노출하는 취약점.

---

## 근본적인 원인

- robots.txt 미작성 또는 설정 미흡 → 크롤러가 전체 사이트 인덱싱
- 관리자 페이지·내부 API·개인정보 페이지에 대한 크롤링 차단 없음
- HTML meta 태그의 noindex 설정 미적용
- 개인정보·민감 데이터가 포함된 페이지가 검색 엔진에 이미 캐싱됨

---

## 2차 피해 시나리오

- Google Dorks(site:, filetype:, inurl: 등)로 내부 경로·백업 파일 발견
- 검색 결과에 개인정보(이름, 이메일, 전화번호) 노출
- 관리자 페이지 URL, 에러 페이지 구조, 기술 스택 정보 노출 → 공격 사전 정보 수집

---

## 해결 및 대응방안

### ① robots.txt 작성 및 올바른 위치에 배치

robots.txt는 반드시 사이트 **최상위 주소**에 위치해야 함. 서브 디렉터리에 위치하면 효력 없음.

```
위치: www.service.com/robots.txt  (O)
     www.service.com/sub/robots.txt  (X — 효력 없음)
```

**가이드라인 안전 설정 예:**

```
# 네이버봇: 전체 차단
User-agent: NaverBot
Disallow: /

# 그 외 검색엔진: 민감 경로만 차단
User-agent: *
Disallow: /WEB-INF/
Disallow: /adminPage/
Disallow: /api/
Disallow: /backup/
Disallow: /temp/
Disallow: /private/
```

**주요 robots.txt 설정 패턴 (가이드라인 [표] 13 기준):**

| robots.txt 설정 | 의도 |
|----------------|------|
| `User-agent: *` + `Disallow: /` | 모든 검색엔진에 전체 노출 방지 |
| `User-agent: *` + `Disallow:` (빈 값) | 모든 검색엔진에 전체 노출 허용 |
| `User-agent: *` + `Disallow: /cgi-bin/` 등 특정 경로 | 해당 경로만 차단 |
| `User-agent: kkkkkk` + `Disallow: /` | 특정 검색엔진만 거부 |
| `User-agent: *` + `Disallow: /` + `Allow: /information` | 전체 차단 후 특정 경로만 허용 |

> **주의**: 관리자 인터페이스 보호를 위해 robots.txt의 Disallow에 관리자 경로를 입력하는 것은 금지. 오히려 공격자에게 경로를 알려주게 됨.

### ② HTML meta 태그로 특정 페이지 크롤링 차단

```html
<!-- HTML <head> 태그 내 삽입 -->
<meta name="robots" content="noindex, nofollow">
```

- `noindex`: 해당 페이지를 검색 결과에 포함하지 않음
- `nofollow`: 해당 페이지의 링크를 추적하지 않음

### ③ 인증이 필요한 페이지 크롤러 접근 차단

```java
// 인증되지 않은 요청은 로그인 페이지로 리다이렉트 → 크롤러가 내용 수집 불가
@GetMapping("/mypage")
public String myPage(HttpSession session) {
    if (session.getAttribute("userId") == null) {
        return "redirect:/login";
    }
    return "mypage";
}
```

### ④ 이미 노출된 개인정보 삭제 요청

검색 엔진에 이미 캐싱된 경우:
1. **원(原)페이지 먼저 삭제** → 원페이지 삭제 없이는 검색결과 지속 노출
2. **Google 웹마스터 도구**로 캐시 페이지 삭제 요청 (자동: 약 1주, 고객센터 경유: 약 2~3주)
3. **Bing**: Microsoft 콘텐츠 제거 요청 절차 이용

---

## 보완방안

- 전체 사이트를 검색엔진에서 차단하는 경우, 일반 포털 검색에서도 사이트가 검색되지 않을 수 있으므로 **비공개 페이지·인증 후 접근 경로에만 제한적으로 Disallow 설정**
- 개발·스테이징 환경 전체에 `Disallow: /` 적용하여 민감 정보 노출 방지
- 검색엔진 크롤링 차단은 보안의 유일한 수단이 아님 — 민감 페이지는 인증·인가로 근본 보호 적용
