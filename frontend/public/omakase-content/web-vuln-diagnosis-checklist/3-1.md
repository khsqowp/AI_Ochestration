# 3-1. 패스워드 정책 유무 및 반영 여부

> 패스워드 생성/재생성 시 안전한 규칙이 적용되지 않아 제3자 또는 공격자가 쉽게 추측하거나  
> 무차별 대입공격(Brute Force)으로 짧은 시간 내에 패스워드를 획득할 수 있는 취약점.

---

## 근본적인 원인

- ID/패스워드 인증 기반에서 패스워드 생성 기준이 없거나 미흡한 경우
- SMS, E-Mail 인증 등 OTP 기반 인증에서 길이·유지 시간·실패 횟수 기준이 없는 경우
- 패스워드 정책 검증이 클라이언트(JavaScript)에서만 이루어지고 서버에서는 미검증

---

## 2차 피해 시나리오

- 짧은 패스워드·단순 패턴 → Brute Force, Dictionary Attack으로 단시간 내 계정 탈취
- 관리자 계정 탈취 → 서비스 전체 장악, 고객 데이터 대량 유출
- 초기 기본 패스워드 미변경 → 공격자가 기본값(admin/admin 등)으로 바로 접속

---

## 해결 및 대응방안

### ① 패스워드 생성 규칙 (가이드라인 기준)

**사용자:**
- 영대문자·영소문자·숫자·특수문자 4종 중 **2종 이상 조합 + 8자리 이상** 또는 **10자리 이상** (숫자만 구성 시 취약)
- 동일문자 반복, 키보드 연속 문자(qwerty, 1234 등) 금지
- 생일, 전화번호, 아이디와 유사한 패스워드 금지
- 사전에 등재된 단어, 널리 알려진 이름·기업명 포함 금지
- 유효기간: **60일 이내 1회 이상 변경** 권고

**관리자:**
- 위 사용자 규칙과 동일하게 적용
- 시스템 초기 기본 패스워드 사용 금지
- 유효기간: **반기별(6개월) 1회 이상 변경**

### ② 패스워드 정책 검증은 반드시 서버 측에서 수행

```java
// 서버 측 패스워드 정책 검증 (Java)
public boolean validatePassword(String password) {
    // 최소 8자리 이상
    if (password == null || password.length() < 8) return false;

    // 2종 이상 조합 (영대문자, 영소문자, 숫자, 특수문자)
    boolean hasUpper   = password.matches(".*[A-Z].*");
    boolean hasLower   = password.matches(".*[a-z].*");
    boolean hasDigit   = password.matches(".*[0-9].*");
    boolean hasSpecial = password.matches(".*[!@#$%^&*()_+\\-=\\[\\]{}|;':\",./<>?].*");

    int count = (hasUpper ? 1 : 0) + (hasLower ? 1 : 0)
              + (hasDigit ? 1 : 0) + (hasSpecial ? 1 : 0);

    return count >= 2;
}
```

### ③ 패스워드 만료 기간 관리

```java
// 로그인 시 패스워드 유효기간 초과 여부 확인
LocalDate lastChanged = userDao.getPasswordChangedDate(userId);
long daysSinceChange  = ChronoUnit.DAYS.between(lastChanged, LocalDate.now());
long maxDays          = isAdmin(userId) ? 180 : 60;  // 관리자 180일, 사용자 60일

if (daysSinceChange >= maxDays) {
    // 패스워드 변경 페이지로 이동
    response.sendRedirect("/account/change-password?reason=expired");
    return;
}
```

### ④ 패스워드 저장: 해시값으로 DB 저장

```java
// BCrypt 해시 저장 (Spring Security)
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hashed = encoder.encode(rawPassword);
userDao.updatePassword(userId, hashed);

// 검증
boolean matches = encoder.matches(inputPassword, storedHash);
```

### ⑤ OTP 기반 인증 시 추가 정책

```java
// SMS/Email OTP 정책
final int OTP_LENGTH      = 6;      // OTP 길이 최소 6자리
final int OTP_EXPIRY_MIN  = 3;      // 유효 시간 3분 이내
final int OTP_MAX_ATTEMPT = 5;      // 최대 시도 횟수

// OTP 생성 시 유효기간 설정
LocalDateTime expiresAt = LocalDateTime.now().plusMinutes(OTP_EXPIRY_MIN);
otpDao.save(new OtpRecord(userId, otp, expiresAt, OTP_MAX_ATTEMPT));
```

### ⑥ 최근 패스워드 재사용 방지

```java
// 최근 사용 패스워드 1회(사용자) 이상 재사용 금지
List<String> recentHashes = userDao.getRecentPasswordHashes(userId, 3);
for (String oldHash : recentHashes) {
    if (encoder.matches(newPassword, oldHash)) {
        throw new BusinessException("최근 사용한 패스워드는 재사용할 수 없습니다.");
    }
}
```

## 보완방안

- 패스워드 변경 팝업/페이지를 강제 노출하여 유효기간 초과 시 즉시 변경 유도
- 최초 로그인(초기 비밀번호) 시 반드시 변경하도록 강제
- 특수문자 포함 패스워드를 DB에 해시로 저장 (평문 저장 절대 금지)
- 취약한 해시 알고리즘(MD5, SHA-1) 대신 BCrypt, Argon2, PBKDF2 사용
