# 4-4. 비인증 상태로 중요 page 접근 가능성

> 로그인 확인 모듈이 누락된 페이지가 존재할 때, 공격자가 로그인 없이  
> 해당 페이지 URL을 직접 입력하여 접근하는 취약점.

---

## 근본적인 원인

- 프로세스가 여러 페이지/모듈로 구성될 때 특정 페이지에 인증 확인 코드 누락
- 로그인 확인을 각 페이지 단위로 개별 구현하다 보니 일부에서 빠짐
- 관리자 페이지 또는 게시판 페이지에 세션 검증 없이 직접 URL 접근 가능

---

## 2차 피해 시나리오

- 비로그인 상태로 개인정보·게시물 열람
- 관리자 기능(사용자 삭제, 권한 변경 등) 비인증 접근
- 결제·주문 관련 페이지에 비인증 접근으로 데이터 열람·조작

---

## 해결 및 대응방안

### ① 공통 인증 모듈 사용 (가이드라인 핵심 권고)

하나의 프로세스가 여러 페이지/모듈로 이루어진 경우 공통 모듈을 사용하여 누락 방지.

```java
// Spring Security: 전역 설정으로 누락 원천 차단
@Configuration
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
            .antMatchers("/login", "/public/**", "/css/**", "/js/**").permitAll()
            .anyRequest().authenticated()  // 명시되지 않은 모든 경로: 인증 필수
            .and()
            .formLogin().loginPage("/login").defaultSuccessUrl("/main")
            .and()
            .logout().invalidateHttpSession(true).deleteCookies("JSESSIONID");
    }
}
```

```java
// 또는 서블릿 필터로 공통 인증 처리
@WebFilter("/*")
public class AuthFilter implements Filter {
    private static final List<String> PUBLIC_PATHS = List.of("/login", "/public", "/css", "/js");

    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest request = (HttpServletRequest) req;
        String uri = request.getRequestURI();

        boolean isPublic = PUBLIC_PATHS.stream().anyMatch(uri::startsWith);
        if (!isPublic && request.getSession().getAttribute("userId") == null) {
            ((HttpServletResponse) res).sendRedirect("/login");
            return;
        }
        chain.doFilter(req, res);
    }
}
```

### ② 개별 페이지 인증 확인 (공통 모듈 미도입 시 차선책)

```java
// 각 페이지 진입 시 세션 검증
@GetMapping("/board/detail")
public String boardDetail(HttpSession session, Model model) {
    if (session.getAttribute("userId") == null) {
        return "redirect:/login?returnUrl=/board/detail";
    }
    // 이하 로직
    return "board/detail";
}
```

### ③ 페이지 단위가 아닌 트랜잭션 단위로 인증 검증

```java
// 최종 데이터 처리(저장·삭제) 시점에도 인증 재검증
@PostMapping("/order/complete")
public ResponseEntity<?> completeOrder(HttpSession session, @RequestBody OrderDto dto) {
    // 화면 접근 통제와 별개로, API 레벨에서도 독립적으로 검증
    if (session.getAttribute("userId") == null) {
        return ResponseEntity.status(401).build();
    }
    // 주문 처리
    orderService.complete(dto);
    return ResponseEntity.ok().build();
}
```

## 보완방안

- 가이드라인 참조: 샘플 소스는 4-1(쿠키 조작 가능성)의 샘플 소스 동일 적용
- Spring Boot 프로젝트: `@PreAuthorize`, `@Secured` 어노테이션을 서비스·컨트롤러에 적용하여 선언적 보안
- 인증 우회 취약점 점검: Burp Suite의 Authorization 탭 또는 접근제어 체크리스트로 페이지별 전수 점검
