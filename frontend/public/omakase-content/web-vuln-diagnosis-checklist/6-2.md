# 6-2. 일괄적인 오류 처리 페이지 존재 여부

> 로그인 실패 시 계정 존재 여부를 구별할 수 있는 메시지나 오류 코드를 반환하면,  
> 공격자가 유효한 계정 정보를 파악하여 Brute Force Attack에 활용할 수 있는 취약점.

---

## 근본적인 원인

- "해당 아이디가 존재하지 않습니다"와 "패스워드가 틀립니다"를 별도의 메시지로 출력
- 계정 존재 여부에 따라 서로 다른 HTTP 응답 코드나 오류 코드 반환
- 오류 메시지 간 통일성이 없어 공격자가 유효한 계정 ID를 식별 가능

---

## 2차 피해 시나리오

- 오류 메시지 차이로 유효 계정 ID 목록 수집 → Brute Force로 패스워드 공격
- 유효 계정 목록을 다른 서비스의 Credential Stuffing 공격에 활용

---

## 해결 및 대응방안

### ① 계정 ID와 패스워드 오류를 동일한 메시지로 통일

가이드라인 예: 계정이 없어도, 패스워드가 틀려도 동일한 메시지와 오류 코드 반환.

```
계정이 존재하지 않을 경우:
  메시지: "계정이 존재하지 않거나, 계정 또는 패스워드가 틀립니다."
  오류코드: "errCd: 10001"

패스워드가 틀린 경우:
  메시지: "계정이 존재하지 않거나, 계정 또는 패스워드가 틀립니다."
  오류코드: "errCd: 10001"
```

```csharp
// ASP.NET: 계정 존재 여부를 구별하지 않는 통일 오류 처리
public string requestLogin(string userID, string userPass) {
    string message = "";

    // ID와 PW를 동시에 확인 → 결과에 관계없이 동일한 메시지
    bool bChecked = DBManager.checkUser(userID, userPass);

    if (bChecked) {
        processLogin(userID);  // 로그인 성공
    } else {
        // ID가 없든, PW가 틀리든 동일한 메시지
        message = "계정이 존재하지 않거나, 패스워드가 잘못되었습니다.";
    }

    return message;
}
```

```java
// Java/Spring: 통일 오류 메시지
@PostMapping("/login")
public String login(String userId, String password, Model model) {
    User user = userDao.findById(userId);

    // 계정 없음, 패스워드 불일치 모두 동일한 분기
    if (user == null || !passwordEncoder.matches(password, user.getPassword())) {
        model.addAttribute("error", "아이디 또는 패스워드가 올바르지 않습니다.");
        return "login";
    }

    // 로그인 성공 처리
    return "redirect:/main";
}
```

### ② 응답 시간도 일정하게 유지 (타이밍 공격 방지)

```java
// 계정이 없어도 패스워드 검증과 동일한 시간이 걸리도록 처리
// → 타이밍 차이로 계정 존재 여부를 추측하는 것을 방지
public String login(String userId, String password) {
    User user = userDao.findById(userId);

    // 계정이 없어도 passwordEncoder.matches()를 호출하여 처리 시간 균일화
    String hashToCheck = (user != null) ? user.getPassword() : DUMMY_HASH;
    boolean matches = passwordEncoder.matches(password, hashToCheck);

    if (user == null || !matches) {
        return "error";
    }
    return "success";
}
// DUMMY_HASH: 미리 생성해 둔 BCrypt 해시값 (실제 계정과 무관)
```

## 보완방안

- 비밀번호 찾기 기능에서도 "가입된 이메일입니다"/"없는 이메일입니다" 구분 금지 → 동일 메시지 사용
- 계정 잠금 알림도 동일하게 — 잠긴 계정임을 별도로 알리면 계정 존재 확인 가능 → 통일 메시지 사용
- 6-1 항목(오류 페이지 설정)과 연계하여 HTTP 응답 코드도 인증 실패는 항상 동일하게 반환
