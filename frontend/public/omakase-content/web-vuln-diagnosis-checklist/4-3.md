# 4-3. 접근제어 우회 가능성 확인

> 인증·권한 제어를 클라이언트 측 스크립트(JavaScript 등)로만 처리하거나,  
> 민감 페이지에 no-cache를 설정하지 않아 로그아웃 후에도 뒤로 가기로 내용을 열람할 수 있는 취약점.

---

## 근본적인 원인

- 인증 실패 시 `<script>location.href='/login.jsp';</script>`로 클라이언트 측 리다이렉트만 처리
  → JavaScript 비활성화 또는 개발자 도구로 삭제하면 정상 페이지 내용이 그대로 노출
- 로그인 확인 모듈이 특정 페이지에 누락되어 직접 URL 입력 시 접근 가능
- 회원정보·결제 페이지 등에 no-cache 설정 미적용 → 로그아웃 후 브라우저 캐시로 이전 페이지 열람

---

## 2차 피해 시나리오

- 로그인 없이 회원 전용 페이지·관리자 기능 직접 접근
- 로그아웃 후 타인의 컴퓨터에서 뒤로 가기로 민감 정보 열람
- 인증 페이지를 거치지 않고 직접 URL 호출로 권한 우회

---

## 해결 및 대응방안

### ① 인증·권한 처리를 반드시 Server Side에서 수행

```java
// 취약: JavaScript로만 리다이렉트 처리 → 스크립트 비활성화 시 우회 가능
// <script>location.href='/login.jsp';</script>

// 안전: 서버 측에서 세션 검증 후 서버 리다이렉트
@GetMapping("/mypage")
public String myPage(HttpSession session) {
    if (session.getAttribute("userId") == null) {
        return "redirect:/login";  // 서버 측 302 리다이렉트
    }
    return "mypage";
}
```

### ② 세션 + 권한 이중 검증 (ASP.NET)

```csharp
// 세션 인증 + 사용자 그룹 권한 검증
public ActionResult openUserInfo() {
    if (Session["UserID"] == null || string.IsNullOrEmpty(Session["UserID"].ToString())) {
        return Redirect("/Error?message=Need Login");
    }

    string userID = Session["UserID"].ToString();
    string group  = GetUserGroup(userID);  // DB에서 사용자 그룹 조회

    if (string.IsNullOrEmpty(group)) {
        return Redirect("/Error?message=Need Login");
    }

    if (!CheckPermission(group, pageCode)) {
        return Redirect("/Error?message=Need Permission");
    }

    return View();
}
```

### ③ Spring Security: 공통 인증 필터로 누락 방지

```java
// 개별 페이지마다 세션 확인 코드를 넣는 대신 공통 필터 사용
@Configuration
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
            .antMatchers("/public/**", "/login", "/css/**").permitAll()
            .antMatchers("/admin/**").hasRole("ADMIN")
            .anyRequest().authenticated()  // 나머지 모든 경로: 로그인 필수
            .and()
            .formLogin().loginPage("/login")
            .and()
            .logout().invalidateHttpSession(true);
    }
}
```

### ④ no-cache 설정으로 브라우저 캐싱 차단

회원정보 열람·수정, 결제, 핸드폰 인증 등 민감 페이지에 적용:

```java
// JSP no-cache 설정
response.setHeader("Cache-Control", "no-cache, no-store");
response.setHeader("Pragma", "no-cache");
response.setDateHeader("Expires", -1);
```

```csharp
// ASP.NET no-cache 설정
Response.Cache.AppendCacheExtension("no-store");
Response.AppendHeader("Pragma", "no-cache");
Response.AppendHeader("Expires", -1.ToString());
```

```php
// PHP no-cache 설정
header('Cache-Control: no-cache, no-store');
header('Pragma: no-cache');
header('Expires: -1');
// 또는 php.ini: session.cache_limiter = nocache
```

```html
<!-- HTML meta 태그 (HTTP/1.1) -->
<META http-equiv="Cache-Control" content="No-Cache, No-Store"/>

<!-- HTTP/1.0 호환 -->
<META http-equiv="Expires" content="-1">
<META http-equiv="Pragma" content="no-cache">
```

```
헤더 설정 (Chrome, Edge, Firefox, IE, Opera, Safari 모두 호환):
Cache-Control: no-cache, no-store, must-revalidate
Pragma: no-cache
Expires: -1
```

### ⑤ 공통 인증 모듈 사용으로 누락 방지

```java
// 서블릿 필터로 인증 공통 처리 → 개별 페이지에서 누락 불가
@WebFilter("/*")
public class AuthFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest  request  = (HttpServletRequest) req;
        HttpServletResponse response = (HttpServletResponse) res;

        String uri = request.getRequestURI();
        boolean isPublic = uri.startsWith("/public") || uri.contains("/login")
                        || uri.contains("/css")  || uri.contains("/js");

        if (!isPublic && request.getSession().getAttribute("userId") == null) {
            response.sendRedirect("/login");
            return;
        }
        chain.doFilter(req, res);
    }
}
```

## 보완방안

- 실명인증 처리 시 전송 데이터와 인증 후 데이터를 서버에서 비교하여 조작 여부 검증
- 관리자 기능 URL은 `@PreAuthorize("hasRole('ADMIN')")` 어노테이션으로 선언적 보안 적용
- 서비스·운영 영향도 확인 후 no-cache 적용 범위 결정 (정적 자원은 캐싱 허용 가능)
