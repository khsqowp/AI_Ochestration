# 3-2. 인증 실패 횟수 제한

> 인증 시도 실패 횟수 제한이 없을 때, 공격자가 무한 반복으로 Brute Force Attack 또는  
> Dictionary Attack을 수행하여 계정을 탈취할 수 있는 취약점.

---

## 근본적인 원인

- ID/패스워드 로그인, SMS·Email OTP 인증 등에서 실패 횟수를 카운트하거나 제한하지 않음
- 사용자 정보 수정 페이지 등에서 재확인 패스워드 입력 시에도 동일하게 횟수 제한 미적용
- 금융 서비스에서 멀티 디바이스 동시 로그인 허용 → 로그인 사용자 추적 불가

---

## 2차 피해 시나리오

- Brute Force Attack으로 짧은 패스워드 계정 무한 시도 → 탈취
- Dictionary Attack으로 일반적인 패스워드 목록 대입 → 계정 탈취
- 계정 잠금 없이 타인 계정으로 정보 변경·결제 시도
- 금융 서비스: 멀티 디바이스 동시 로그인으로 실제 사용자 인지 불가 → 사기 거래

---

## 해결 및 대응방안

### ① 로그인 실패 횟수 DB 카운트 + 계정 잠금

가이드라인 권고: 로그인 5회 실패 시 계정 잠금, SMS 입력 3분 이내 설정

```java
// 로그인 실패 처리 (Java + Spring)
@PostMapping("/login")
public String login(String userId, String password, HttpSession session) {
    User user = userDao.findById(userId);
    if (user == null) {
        // 계정 존재 여부 노출 방지: 동일한 에러 메시지 사용
        return "redirect:/login?error=invalid";
    }

    // 계정 잠금 여부 확인
    if (user.getLoginFailCount() >= 5) {
        return "redirect:/login?error=locked";
    }

    if (!passwordEncoder.matches(password, user.getPassword())) {
        // 실패 횟수 증가
        userDao.incrementLoginFailCount(userId);
        return "redirect:/login?error=invalid";
    }

    // 로그인 성공 → 실패 횟수 초기화
    userDao.resetLoginFailCount(userId);
    session.setAttribute("userId", userId);
    return "redirect:/main";
}
```

### ② DB 스키마: 실패 횟수 및 잠금 시간 필드 추가

```sql
ALTER TABLE users
  ADD COLUMN login_fail_count  INT         DEFAULT 0,
  ADD COLUMN locked_at         DATETIME    DEFAULT NULL,
  ADD COLUMN lock_expire_at    DATETIME    DEFAULT NULL;
```

### ③ 일정 시간 후 자동 잠금 해제 (또는 관리자 수동 해제)

```java
// 잠금 만료 확인: 30분 후 자동 해제
public boolean isAccountLocked(User user) {
    if (user.getLockExpireAt() == null) return false;
    if (LocalDateTime.now().isAfter(user.getLockExpireAt())) {
        // 잠금 해제 처리
        userDao.resetLoginFailCount(user.getId());
        return false;
    }
    return true;
}

// 계정 잠금 처리
public void lockAccount(String userId) {
    LocalDateTime expireAt = LocalDateTime.now().plusMinutes(30);  // 30분 후 해제
    userDao.lockUser(userId, LocalDateTime.now(), expireAt);
}
```

### ④ 사용자 정보 수정 시 재인증에도 동일한 실패 횟수 제한 적용

```java
// 정보 변경 시 패스워드 재확인 페이지에도 동일 로직 적용
@PostMapping("/account/verify-password")
public String verifyPassword(String password, HttpSession session) {
    String userId = (String) session.getAttribute("userId");
    User user = userDao.findById(userId);

    if (user.getLoginFailCount() >= 5) {
        return "redirect:/account/verify-password?error=locked";
    }
    if (!passwordEncoder.matches(password, user.getPassword())) {
        userDao.incrementLoginFailCount(userId);
        return "redirect:/account/verify-password?error=invalid";
    }

    userDao.resetLoginFailCount(userId);
    session.setAttribute("passwordVerified", true);
    return "redirect:/account/edit";
}
```

### ⑤ OTP 인증 시간·횟수 제한

```java
// OTP 검증 시 유효기간 + 시도 횟수 제한
public boolean verifyOtp(String userId, String inputOtp) {
    OtpRecord record = otpDao.findLatest(userId);

    if (record == null || LocalDateTime.now().isAfter(record.getExpiresAt())) {
        throw new BusinessException("OTP가 만료되었습니다.");  // 3분 초과
    }

    if (record.getAttempts() >= 5) {
        throw new BusinessException("OTP 시도 횟수를 초과했습니다.");
    }

    if (!record.getOtpCode().equals(inputOtp)) {
        otpDao.incrementAttempts(record.getId());
        return false;
    }

    otpDao.markUsed(record.getId());
    return true;
}
```

## 보완방안

- CAPTCHA 추가: 일정 횟수 실패 후 CAPTCHA 표시로 자동화 공격 차단
- IP 기반 추가 차단: 동일 IP에서 다수 계정 실패 시 해당 IP 임시 차단
- 계정 잠금 발생 시 가입된 이메일/SMS로 사용자에게 알림 발송
- 로그인 시도 로그 기록 (userId, IP, 시간, 성공/실패) → 이상 탐지에 활용
