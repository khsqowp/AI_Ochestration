# 7-3. 서버 헤더정보 노출

> HTTP 응답 헤더의 `Server`, `X-Powered-By`, `X-AspNet-Version` 등에  
> 웹 서버 또는 WAS의 종류와 버전이 노출되어 공격자가 알려진 취약점을 타겟팅하는 취약점.

---

## 근본적인 원인

- 웹 서버 기본 설정에서 `Server` 헤더를 변경하지 않아 `Apache/2.4.41`, `nginx/1.18.0` 등 버전 정보 노출
- ASP.NET의 `X-Powered-By: ASP.NET`, `X-AspNet-Version: 4.0.30319` 등 기본값 미제거
- Tomcat의 `Server` 헤더에 버전 정보 포함

---

## 2차 피해 시나리오

- 서버 종류·버전 파악 → CVE 데이터베이스에서 해당 버전 취약점 검색 → 표적 공격
- 구버전 Apache/Tomcat/IIS 취약점을 이용한 RCE, 정보 노출 공격
- 프레임워크 버전 파악으로 특정 취약점(Log4Shell 등) 타겟팅

---

## 해결 및 대응방안

### ① Apache: ServerTokens / ServerSignature 설정

```apache
# httpd.conf 또는 httpd-default.conf

# Apache 2.2.x 이상: Include 여부 확인 후 적용
# Include conf/extra/httpd-default.conf 있으면 해당 파일에서 설정
ServerTokens Prod        # "Server: Apache"만 반환 (버전 제거)
ServerSignature Off      # 오류 페이지 하단 서버 정보 미표시
```

```apache
# mod_security 적용 시 추가 설정
SecRuleEngine on
ServerTokens Minimal
SecServerSignature "Custom-Server"  # 임의 값으로 변경
```

### ② Nginx: server_tokens 비활성화

```nginx
# nginx.conf (http, server, location 절 모두 설정 가능)
http {
    server_tokens off;  # 기본값: on (버전 노출)
    ...
}
```

### ③ Tomcat: server.xml에서 server 정보 변경

```xml
<!-- [Tomcat 설치 디렉터리]/conf/server.xml -->
<!-- server="" 로 하면 서버 정보가 노출 → 반드시 공백 포함 " " 사용 -->
<Connector port="8080" protocol="HTTP/1.1"
           server=" "
           ... />
<!-- server=" " (공백 포함) → blank로 표시됨 -->
<!-- server="Custom" → 임의 문자열로 표시 -->
```

### ④ IIS 5.x/6.x: UrlScan으로 Server 헤더 제거

```
1. UrlScan 3.1 설치 (https://technet.microsoft.com/en-us/security/cc242650.aspx)
2. IIS 관리자 → ISAPI 필터 → UrlScan 3.1 추가
3. UrlScan 설치 경로: C:\Windows\system32\inetsrv\urlscan
4. UrlScan.ini 파일 편집:
   RemoveServerHeader = 0  →  RemoveServerHeader = 1
   (헤더 정보 노출 방지)
```

### ⑤ IIS 7.x/8.x/10.x: web.config URL Rewrite로 헤더 제거

```xml
<!-- web.config -->
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <outboundRules>
        <!-- Server 헤더 제거 -->
        <rule name="RESPONSE_SERVER">
          <match serverVariable="RESPONSE_SERVER" pattern=".*" />
          <action type="Rewrite" />
        </rule>
        <!-- X-Powered-By 헤더 제거 -->
        <rule name="Remove X-Powered-By">
          <match serverVariable="RESPONSE_X-Powered-By" pattern=".*" />
          <action type="Rewrite" />
        </rule>
        <!-- X-AspNet-Version 헤더 제거 -->
        <rule name="Remove X-AspNet-Version">
          <match serverVariable="RESPONSE_X-AspNet-Version" pattern=".*" />
          <action type="Rewrite" />
        </rule>
      </outboundRules>
    </rewrite>
  </system.webServer>
</configuration>

<!-- URL Rewrite 모듈 필요:
  IIS 7.x/8.x: URL Rewrite 2.0
  IIS 10.x: URL Rewrite 2.1 -->
```

### ⑥ WebToB: ServerToken 설정

```
# http.m
*NODE
webmain ...
    ServerToken = "OFF"     # 서버 정보 미표시
    또는
    ServerToken = "임의의 값"  # 다른 서버인 것처럼 위장
```

### ⑦ iPlanet: magnus.conf 설정

```
# magnus.conf
ServerString "임의의 값"
또는
ServerString none
```

### ⑧ Spring Boot: 헤더 조작

```java
// WebServerFactoryCustomizer로 Tomcat Server 헤더 제거
@Bean
public WebServerFactoryCustomizer<TomcatServletWebServerFactory> serverCustomizer() {
    return factory -> factory.addConnectorCustomizers(
        connector -> connector.setAttribute("server", " ")
    );
}
```

```java
// 응답 헤더에서 X-Powered-By 등 제거
@Bean
public FilterRegistrationBean<OncePerRequestFilter> securityHeaderFilter() {
    FilterRegistrationBean<OncePerRequestFilter> bean = new FilterRegistrationBean<>();
    bean.setFilter(new OncePerRequestFilter() {
        @Override
        protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
                                         FilterChain chain) throws IOException, ServletException {
            res.setHeader("X-Powered-By", "");
            chain.doFilter(req, res);
        }
    });
    return bean;
}
```

## 보완방안

- 서버 헤더 변경과 함께 오류 페이지에서 서버 버전 정보 미포함 확인 (6-1 항목 연계)
- 서버 소프트웨어를 최신 보안 패치 버전으로 유지하여 버전 노출 자체의 위협 최소화
- 불필요한 확장 헤더(X-Frame-Options 미설정 등) 추가 보안 헤더도 함께 점검
