# 4-5. 일반계정 권한 상승 가능성

> 일반 사용자 계정으로 로그인한 상태에서 접근 제어 통제(ACL) 미흡으로  
> 관리자 페이지나 상위 권한 페이지에 접근하거나 타 그룹·파트너사 기능에 접근하는 취약점.

---

## 근본적인 원인

- 로그인(인증) 여부만 확인하고 권한(인가) 레벨을 별도 검증하지 않음
- URL 직접 입력으로 관리자 전용 기능 접근 가능
- 동일 권한 레벨이지만 그룹·팀·파트너사로 구분될 때 수평적 접근 제어 미적용
- 접근제어 통제(ACL) 정책이 수립되지 않거나 코드에 반영되지 않음

---

## 2차 피해 시나리오

- 일반 사용자가 관리자 기능(사용자 삭제, 권한 변경, 공지 등록 등) 실행
- 타 팀·파트너사의 데이터 열람·수정·삭제
- 권한 상승을 통한 추가 공격(악성 파일 업로드, 서비스 설정 변경 등)

---

## 해결 및 대응방안

### ① 접근제어 통제(ACL) 정책 수립 + 코드 반영

계정 인증과 연계하여 역할(Role) 기반 접근 제어를 정책적으로 수립하고 페이지·기능 단위로 적용.

```java
// Spring Security: 역할 기반 접근 제어
http.authorizeRequests()
    .antMatchers("/admin/**").hasRole("ADMIN")
    .antMatchers("/partner/**").hasAnyRole("ADMIN", "PARTNER")
    .antMatchers("/user/**").hasAnyRole("ADMIN", "USER")
    .anyRequest().authenticated();
```

```java
// 어노테이션 기반 선언적 권한 검증
@PreAuthorize("hasRole('ADMIN')")
@DeleteMapping("/admin/users/{id}")
public ResponseEntity<?> deleteUser(@PathVariable Long id) {
    userService.delete(id);
    return ResponseEntity.noContent().build();
}

@PreAuthorize("hasRole('ADMIN') or (hasRole('USER') and @accessPolicy.isOwner(#boardId, authentication))")
@PutMapping("/boards/{boardId}")
public ResponseEntity<?> updateBoard(@PathVariable Long boardId, @RequestBody BoardDto dto) {
    boardService.update(boardId, dto);
    return ResponseEntity.ok().build();
}
```

### ② 서비스 레이어에서 권한 재검증 (수평적 권한 상승 방지)

```java
// 같은 역할(USER)이더라도 자신의 데이터인지 검증
@Service
public class BoardService {
    public void update(Long boardId, BoardDto dto) {
        String sessionUserId = SecurityContextHolder.getContext()
                                   .getAuthentication().getName();
        Board board = boardDao.findById(boardId)
                              .orElseThrow(() -> new NotFoundException("Board not found"));

        if (!board.getOwnerId().equals(sessionUserId) && !isAdmin(sessionUserId)) {
            throw new AccessDeniedException("권한 없음");
        }
        boardDao.update(boardId, dto);
    }
}
```

### ③ 그룹·파트너사 수준의 데이터 격리

```java
// 파트너사 A 직원이 파트너사 B 데이터 접근 불가
@GetMapping("/partner/orders")
public List<OrderDto> getPartnerOrders(HttpSession session) {
    String partnerId = (String) session.getAttribute("partnerId");

    if (partnerId == null) {
        throw new AccessDeniedException("파트너 인증 필요");
    }

    return orderService.findByPartnerId(partnerId);  // 세션의 partnerId로만 조회
}
```

### ④ 공통 권한 검증 유틸리티

```java
// 공통 권한 체크 메서드
public class AccessPolicy {
    public boolean isOwner(Long resourceId, Authentication auth) {
        String userId = auth.getName();
        return resourceDao.findById(resourceId)
                          .map(r -> r.getOwnerId().equals(userId))
                          .orElse(false);
    }

    public boolean hasGroupAccess(String resourceGroupId, Authentication auth) {
        String sessionGroupId = ((UserPrincipal) auth.getPrincipal()).getGroupId();
        return resourceGroupId.equals(sessionGroupId);
    }
}
```

## 보완방안

- 가이드라인 참조: 샘플 소스는 4-1(쿠키 조작 가능성)의 샘플 소스 동일 적용
- 권한 매트릭스를 문서화하고 코드 리뷰 시 ACL 누락 여부 확인
- 정기적으로 불필요한 역할·권한 부여 여부 감사 (계정 권한 리뷰)
- 관리자 기능은 일반 사용자 API와 경로·인터페이스를 분리하여 혼재 방지
