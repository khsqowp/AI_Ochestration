# 5-1. 소스코드 내 주요정보 노출 여부

> 웹 페이지 소스코드 또는 설정 파일에 DB 접속 정보, FTP 인증 정보, API 키 등을  
> 하드코딩하여 비인가자가 해당 정보를 획득하고 악용할 수 있는 취약점.

---

## 근본적인 원인

- DB 커넥션 정보(URL, 계정, 패스워드), API 키, 암호화 키 등을 소스코드에 평문으로 하드코딩
- 사용하지 않는 인증 정보가 주석으로 소스코드에 남아 있음
- 설정 파일(web.config, application.properties 등)이 암호화 없이 평문 저장
- 소스코드가 공개 저장소(GitHub 등)에 업로드되거나 외부에서 접근 가능한 위치에 저장

---

## 2차 피해 시나리오

- DB 접속 정보 탈취 → 직접 DB 접속하여 전체 데이터 열람·수정·삭제
- FTP 인증 정보 탈취 → 서버 파일 시스템 접근
- API 키 탈취 → 외부 서비스 무단 사용 또는 과금 유발
- 암호화 키 노출 → 암호화된 데이터 복호화 가능

---

## 해결 및 대응방안

### ① 인증 정보를 소스코드에 하드코딩 금지 — 환경변수 또는 외부 설정 파일로 분리

```java
// 취약: 소스코드 직접 하드코딩
String dbUrl  = "jdbc:mysql://192.168.1.10:3306/mydb";
String dbUser = "admin";
String dbPass = "P@ssw0rd123";

// 안전: 환경변수 사용
String dbUrl  = System.getenv("DB_URL");
String dbUser = System.getenv("DB_USER");
String dbPass = System.getenv("DB_PASS");
```

```java
// Spring Boot: application.properties에서 외부 주입
// application.properties (소스 미포함, 서버에서 별도 관리)
// spring.datasource.url=${DB_URL}
// spring.datasource.username=${DB_USER}
// spring.datasource.password=${DB_PASS}
```

### ② 설정 파일 암호화 (ASP.NET: web.config 암호화)

```
# Cmd에서 aspnet_regiis.exe로 connectionStrings 섹션 암호화
# aspnet_regiis.exe 위치: C:\WINDOWS\Microsoft.NET\Framework\[닷넷버전]

암호화:
aspnet_regiis.exe -pef "connectionStrings" "D:\프로젝트_디렉터리"

복호화:
aspnet_regiis.exe -pd "connectionStrings" "D:\프로젝트_디렉터리"

※ 암호화 후 사이트가 안 뜰 때: 서비스 접근자 권한 추가 필요
aspnet_regiis -pa "NetFrameworkConfigurationKey" "NT Authority\Network Service"
```

```csharp
// 암호화된 설정에서 값 읽기 (ASP.NET)
var config  = new System.Configuration.AppSettingsReader();
string dbUser = (string)config.GetValue("DB_USER", typeof(string));
string dbPass = (string)config.GetValue("DB_PASS", typeof(string));

// 웹 루트 상위 경로의 복호화 키로 복호화 (웹 접근 불가 경로에 키 저장)
string keyFile = "/secure/decrypt/decrypt_key";
dbUser = Util.decrypt(dbUser, keyFile);
dbPass = Util.decrypt(dbPass, keyFile);
```

### ③ 중요 정보는 HSM·KMS 등 전용 인증 서버에서 관리

```java
// AWS Secrets Manager, HashiCorp Vault 등 활용
SecretsManagerClient client = SecretsManagerClient.builder()
    .region(Region.AP_NORTHEAST_2).build();
GetSecretValueRequest req = GetSecretValueRequest.builder()
    .secretId("prod/myapp/db")
    .build();
String secretJson = client.getSecretValue(req).secretString();
// JSON 파싱 후 DB 접속 정보 사용
```

### ④ 소스코드 내 주석의 인증 정보 제거

```java
// 취약: 사용하지 않는 인증 정보가 주석으로 잔존
// String dbPass = "OldPassword123";  ← 이런 주석 제거 필수
// String apiKey = "sk-xxx...";       ← 제거
```

### ⑤ 모든 인증은 인증 모듈 또는 서버에서 처리

- 인증 모듈은 Server Side에서만 동작하도록 설계
- 클라이언트(JavaScript) 소스에 인증 정보 포함 절대 금지

## 보완방안

- `.gitignore`에 설정 파일(`.env`, `application-prod.properties` 등) 추가하여 저장소 업로드 방지
- GitHub Secret Scanning, truffleHog 등으로 커밋 히스토리 내 인증 정보 탐지 자동화
- 인증 정보가 노출된 경우 즉시 키 교체(Rotate) 후 노출된 값 무효화
