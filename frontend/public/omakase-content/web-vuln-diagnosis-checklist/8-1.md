# 8-1. 취약점 진단 항목에 정의되지 않은 취약점

> 1~7 항목의 27개 정의된 취약점 외에, 새로운 Zero-Day 공격을 포함한  
> 기타 취약점이 발견될 경우를 다루는 항목.

---

## 주요 내용

사회·기술의 발전으로 새로운 취약점 및 공격 기법이 지속적으로 등장함.
정의된 27개 항목 외에도 진단 과정에서 발견되는 기타 취약점이 존재할 수 있음.

---

## 대응 원칙

발견된 취약점의 성격에 따라 대응 방안을 보고서에 별도 첨부하며, 자세한 내용은 진단 보고서를 참조.

---

## 보완방안 (일반 원칙)

### ① 주요 보안 취약점 정보 소스 모니터링

```
- CVE (Common Vulnerabilities and Exposures): https://cve.mitre.org
- NVD (National Vulnerability Database): https://nvd.nist.gov
- KISA 보안 공지: https://www.kisa.or.kr
- OWASP Top 10: https://owasp.org/www-project-top-ten/
```

### ② Zero-Day 취약점 대응 원칙

- 취약점 공개 즉시 임시 완화 조치(Workaround) 우선 적용
- 벤더사 공식 패치 출시 즉시 적용 (종속성 영향도 확인 후)
- 취약 컴포넌트를 사용하는 기능은 일시 비활성화 검토

### ③ 지속적 보안 점검 체계 유지

```java
// 의존성 취약점 자동 탐지 (CI/CD 파이프라인 통합)
// Maven: pom.xml
<build>
  <plugins>
    <plugin>
      <groupId>org.owasp</groupId>
      <artifactId>dependency-check-maven</artifactId>
      <version>8.4.0</version>
      <executions>
        <execution>
          <goals><goal>check</goal></goals>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
```

### ④ 발견된 취약점 분류 및 보고 프로세스

```
1. 취약점 식별: 진단 도구 또는 수동 점검
2. 영향도 평가: CVSS 점수 산정
3. 조치 방안 수립: 근본 원인 분석 → 대응 코드/설정 작성
4. 보고서 첨부: 취약점 설명, 재현 방법, 조치 방안 포함
5. 재점검: 조치 완료 후 동일 취약점 재발 여부 확인
```
