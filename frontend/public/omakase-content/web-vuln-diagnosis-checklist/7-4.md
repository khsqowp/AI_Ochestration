# 7-4. 취약한 보안설정

> 보안상 취약한 서버 설정, 패치 미적용 라이브러리·모듈·프레임워크,  
> SSL 인증서 관리 미흡 등으로 공격자가 시스템 권한·정보를 획득하거나 MITM 공격을 수행할 수 있는 취약점.

---

## 근본적인 원인

- 서버·WAS·라이브러리의 알려진 취약 버전(CVE)을 패치 없이 운영
- 불필요한 서비스·모듈·구성 요소가 활성화되어 공격 노출 면적 증가
- SSL/TLS 통신에서 자체 서명(Self-Signed) 인증서 또는 신뢰되지 않은 인증서 사용
- SSL/TLS 인증서 체인(Chain) 검증 부재 → MITM 가능
- 취약한 암호 알고리즘(DES, RC4, MD5, SHA-1 등) 사용

---

## 2차 피해 시나리오

- 알려진 CVE 취약점으로 원격 코드 실행(RCE), 서비스 거부(DoS)
- MITM으로 SSL 통신 스니핑 → 로그인 세션, 개인정보 탈취
- 자체 서명 인증서로 인한 인증서 위조 → 피싱 공격
- Log4Shell, Spring4Shell 등 프레임워크 취약점 악용

---

## 해결 및 대응방안

### ① 불필요한 서비스·구성 요소 최소화

```
- 사용하지 않는 웹 서버 모듈 비활성화 (mod_status, mod_info, mod_proxy 등)
- 불필요한 포트·서비스 방화벽으로 차단
- 개발·디버그 엔드포인트 운영 환경에서 완전 제거
```

```java
// Spring Boot Actuator: 운영 환경에서 민감 엔드포인트 비활성화
// application.properties
management.endpoints.web.exposure.include=health,info
management.endpoint.health.show-details=never
// heapdump, env, beans 등 민감 엔드포인트 비노출
```

### ② 라이브러리·프레임워크 취약 버전 패치

```xml
<!-- Maven: 의존성 최신 버전 유지 -->
<!-- 정기적으로 mvn dependency:check 또는 OWASP Dependency-Check 실행 -->
<dependency>
  <groupId>org.springframework</groupId>
  <artifactId>spring-webmvc</artifactId>
  <version>6.1.10</version>  <!-- 최신 보안 패치 버전 사용 -->
</dependency>
```

```bash
# OWASP Dependency Check (취약 라이브러리 탐지)
mvn org.owasp:dependency-check-maven:check

# npm (Node.js)
npm audit fix
```

> **주의**: 패치 시 종속성 및 서비스 영향도를 충분히 확인 후 적용.

### ③ SSL/TLS 안전한 설정

```java
// Spring Boot: TLS 설정 (application.properties)
server.ssl.enabled=true
server.ssl.protocol=TLS
server.ssl.enabled-protocols=TLSv1.2,TLSv1.3  // TLS 1.0, 1.1 사용 금지
server.ssl.ciphers=TLS_AES_256_GCM_SHA384,TLS_CHACHA20_POLY1305_SHA256
                  // 취약한 암호화 스위트(DES, RC4, 3DES 등) 제외
server.ssl.key-store=classpath:keystore.p12
server.ssl.key-store-type=PKCS12
server.ssl.key-store-password=${SSL_KEYSTORE_PASSWORD}
```

```apache
# Apache: 취약한 TLS 버전 비활성화
SSLProtocol all -SSLv2 -SSLv3 -TLSv1 -TLSv1.1
SSLCipherSuite HIGH:!aNULL:!MD5:!RC4:!DES:!3DES
SSLHonorCipherOrder On
```

### ④ 공인 인증기관(CA) 발급 인증서 사용

```
자체 서명(Self-Signed) 인증서 사용 금지
→ 공인 CA(DigiCert, Let's Encrypt, COMODO 등)에서 발급된 인증서 사용

인증서 체인(Chain) 검증 활성화:
  - 중간 CA 인증서까지 포함한 체인 인증서 설치
  - SSLCertificateChainFile (Apache) 또는 truststore 설정
```

```java
// HTTPS 클라이언트에서 인증서 검증 (Java)
// 자체 서명 인증서를 신뢰하는 코드 작성 금지
// TrustManager로 모든 인증서 허용하는 코드 금지:
// X509TrustManager { ... checkServerTrusted() {} } ← 절대 금지
```

### ⑤ 취약한 암호 알고리즘 사용 금지

```java
// 금지: MD5, SHA-1, DES, RC4 사용
// MessageDigest.getInstance("MD5")  ← 금지
// MessageDigest.getInstance("SHA-1") ← 단독 사용 금지

// 권고: SHA-256 이상
MessageDigest md = MessageDigest.getInstance("SHA-256");

// 패스워드 해시: BCrypt, Argon2, PBKDF2 사용
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(12);
```

### ⑥ 보안 설정 변경 전 영향도 검토

```
- 설정 변경 전 스테이징 환경에서 충분한 검증
- 단말기기·브라우저 호환성 확인 (TLS 1.3 미지원 구형 기기 존재 가능)
- 패치 적용 시 종속성 충돌 여부 사전 확인
```

## 보완방안

- 정기적인 취약점 스캔 (Nessus, OpenVAS, OWASP ZAP 등)으로 서버 설정 점검
- CVE 보안 공지 구독 및 패치 적시 적용 정책 수립
- SSL 인증서 만료일 모니터링 및 자동 갱신 (Let's Encrypt: Certbot 활용)
- 인프라 담당팀과 협의하여 보안 설정·패치 적용 — 개발팀 단독 처리 불가한 항목 포함
