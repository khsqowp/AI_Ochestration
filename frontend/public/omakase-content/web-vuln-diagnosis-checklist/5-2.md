# 5-2. 요청 및 응답 값 내 주요정보 포함여부 확인

> URL 파라미터, HTTP 요청/응답 바디에 디렉터리 경로, 개인정보, 결제정보 등이 평문으로 포함되어  
> 네트워크 스니핑, 로그 노출, 브라우저 기록 등을 통해 중요 정보가 탈취될 수 있는 취약점.

---

## 근본적인 원인

- URL 파라미터에 개인정보(이름, 전화번호, 주민번호), 사용자 식별값, 결제정보 등을 평문으로 전달
- HTTP(비암호화 통신)로 개인정보·결제정보 전송 → 네트워크 스니핑으로 탈취 가능
- 서버 응답 바디에 내부 경로, 파일 구조, DB 필드명 등 불필요한 정보 포함
- GET 파라미터로 인증 정보(아이디·비밀번호) 전송 → 서버 로그, 브라우저 히스토리에 기록

---

## 2차 피해 시나리오

- URL 파라미터의 개인정보가 서버 접근 로그에 평문 기록 → 로그 접근자에게 노출
- GET 파라미터 비밀번호가 Referer 헤더로 외부 사이트에 전달
- 네트워크 스니핑으로 신용카드번호, 주민번호 탈취
- 응답 데이터에 포함된 내부 경로·DB 스키마로 추가 공격 정보 수집

---

## 해결 및 대응방안

### ① URL 파라미터에 중요 정보 미포함 — POST + HTTPS 사용

```java
// 취약: GET 파라미터로 인증 정보 전달
// GET /auth/loginProcess?userId=admin&userPw=P@ssw0rd123
// → 브라우저 히스토리, 서버 로그, Referer 헤더에 비밀번호 노출

// 안전: POST 방식으로 전달 + HTTPS 적용
@PostMapping("/auth/loginProcess")
public String login(@RequestParam String userId,
                    @RequestParam String userPw,
                    HttpSession session) { ... }
```

### ② 파라미터에 중요 정보 불가피 시 암호화하거나 간접 값 사용

```java
// 직접적인 값 대신 간접적인 키 사용
// 취약: ?fileId=../../../etc/passwd  또는  ?userId=admin
// 안전: ?fileToken=e3b0c44298fc1c149a (서버에서 토큰 → 실제 값 매핑)

// 불가피하게 중요 값을 파라미터로 전달해야 하는 경우 암호화
String encrypted = AES256.encrypt(sensitiveValue, SECRET_KEY);
String urlParam = URLEncoder.encode(encrypted, StandardCharsets.UTF_8);
// URL: ?data=<암호화된값>
```

### ③ 통신 구간 암호화 — SSL/TLS(HTTPS) 적용

가이드라인 권고 암호 알고리즘 기준:
- 신용카드번호, 휴대폰번호 등 개인정보·인증정보 전송 시: **SEED 128bit 이상** 보안강도 알고리즘 또는 **SSL** 적용
- 전자서명, 키 공유, 메시지 암/복호화 시: **RSASSA-PSS 2048bit 이상**

```
# Spring Boot HTTPS 설정 (application.properties)
server.ssl.enabled=true
server.ssl.key-store=classpath:keystore.p12
server.ssl.key-store-type=PKCS12
server.ssl.key-store-password=${SSL_KEYSTORE_PASSWORD}
```

```java
// HTTP → HTTPS 강제 리다이렉트 (Spring Security)
http.requiresChannel()
    .anyRequest().requiresSecure();
```

### ④ 응답 데이터에서 불필요한 정보 제거

```java
// 응답 DTO에서 민감 필드 제외
@JsonIgnore
private String password;

@JsonIgnore
private String ssn;  // 주민번호

// 또는 마스킹 후 반환
public String getPhone() {
    return phone.replaceAll("(\\d{3})(\\d{4})(\\d{4})", "$1-****-$3");
}
```

### ⑤ 서버 로그에 민감 정보 기록 금지

```java
// 로그에 비밀번호 등 민감 정보 출력 금지
// log.debug("Login: userId={}, password={}", userId, password);  ← 금지
log.debug("Login attempt: userId={}", userId);  // 비밀번호 제외

// Spring Boot: application.properties
// logging.level.org.springframework.web=DEBUG  → 운영 환경에서 WARN/ERROR로
```

### ⑥ 개인정보 마스킹 처리 후 응답

```java
// 응답 시 개인정보 부분 마스킹
public UserResponse toResponse(User user) {
    return UserResponse.builder()
        .name(maskName(user.getName()))
        .phone(maskPhone(user.getPhone()))   // 010-****-5678
        .email(maskEmail(user.getEmail()))   // ex***@gmail.com
        .build();
}
```

## 보완방안

- Burp Suite로 요청·응답 전수 점검: URL 파라미터, 쿠키, 응답 바디에 평문 개인정보 포함 여부 확인
- HSTS(HTTP Strict Transport Security) 헤더 설정으로 HTTP 강제 차단
  ```java
  response.setHeader("Strict-Transport-Security", "max-age=31536000; includeSubDomains");
  ```
- 로그 수집 시스템에서 민감 필드 자동 마스킹(SIEM 필터 적용)
