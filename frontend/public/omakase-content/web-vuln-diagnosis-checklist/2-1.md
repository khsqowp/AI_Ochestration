# 2-1. 악성코드파일 업로드

> 웹 서버의 잘못된 설정이나 업로드 검증 부재를 이용하여 서버에서 실행 가능한  
> 스크립트 파일을 업로드하고 원격 명령을 실행하여 시스템 권한을 획득하는 취약점.

---

## 근본적인 원인

파일 업로드 기능에서 확장자·MIME 타입·파일 내용(매직 바이트)에 대한 서버 측 검증이 없거나 우회 가능할 때, 공격자가 웹쉘(asp, php, jsp 등)을 업로드하여 실행시킴.

**대표적인 우회 기법:**
- IIS 6.0: 세미콜론 트릭 — `test1.asp;test.jpg` → IIS가 `.asp`로 해석하여 실행
- IIS 7.5 이하: 에디터로 `1.asp` 이름의 디렉터리 생성 후 `webshell.jpg` 업로드 → `asp.dll` 버그로 해당 폴더 내 파일 실행 가능
- 이중 확장자: `file.jpg.jsp`, `file.php.jpg`
- 끝에 점 추가: `file.php.`
- 대소문자 변환: `file.PHP`, `file.Php`
- Content-Type 조작: `Content-Type: image/jpeg`로 변조해 필터 우회
- NULL 바이트: `file.php%00.jpg` → 구버전 파서가 `.php` 이후를 무시

> 직접 실행되지 않더라도 업로드된 악성 파일은 File Inclusion, Path Traversal 등 다른 취약점과 연계하여 실행 가능.

---

## 2차 피해 시나리오

- 웹쉘 실행 → 서버 OS 명령 원격 실행
- 데이터베이스 접속 정보·내부 파일 탈취
- 내부망 횡적 이동(Lateral Movement)
- 서버에 악성코드(랜섬웨어, 백도어) 설치
- 다른 취약점(File Inclusion 등)과 연계하여 간접 실행

---

## 해결 및 대응방안

### ① 화이트리스트 방식 확장자 검증 (서버 측)

허용할 확장자 목록을 명시하고, **대소문자 구분 없이** 비교:

```java
// JSP: 화이트리스트 확장자 검증
public String checkExt(String fileName) {
    String chkExt = "false";
    String exts = "jpg,gif,bmp,png,pdf,xlsx,docx,pptx"; // 허용 확장자

    // 특수문자 필터링 (가이드라인 [표] 11 기준: ../ ./ ..\ .\ % ;)
    if (fileName.indexOf("\0") > -1 || fileName.indexOf(";") > -1 ||
        fileName.indexOf("./") > -1 || fileName.indexOf(".\\") > -1 ||
        fileName.indexOf("..") > -1 || fileName.indexOf("%") > -1) {
        return "false";
    }

    // 확장자 추출 후 대소문자 구분 없이 비교
    String fileExt = fileName.substring(fileName.lastIndexOf('.') + 1);
    if (!exts.isEmpty()) {
        for (String allowed : exts.split(",")) {
            if (fileExt.equalsIgnoreCase(allowed)) {
                chkExt = "true";
                break;
            }
        }
    }
    return chkExt;
}
```

```csharp
// ASP.NET: 화이트리스트 확장자 검증
public bool checkUploadFile(string strFile) {
    bool bResult = false;
    string[] allowExt = new string[] { "jpg", "jpeg", "png", "gif", "pdf" };

    // 특수문자 필터링
    if (strFile.IndexOf("..") != -1 || strFile.IndexOf("./") != -1 ||
        strFile.IndexOf(".\\") != -1 || strFile.IndexOf("%") != -1 ||
        strFile.IndexOf(";") != -1  || strFile.IndexOf("\0") != -1) {
        return false;
    }

    // 마지막 점 이후 확장자 추출 → 소문자 변환 후 비교
    int tempPoint = strFile.LastIndexOf(".");
    if (tempPoint > -1) {
        string fileExt = strFile.Substring(tempPoint + 1);
        if (!string.IsNullOrWhiteSpace(fileExt)) {
            if (Array.IndexOf(allowExt, fileExt.ToLower()) != -1)
                bResult = true;
        }
    }
    return bResult;
}
```

```php
// PHP: 화이트리스트 + 특수문자 필터링
function checkext($filename) {
    $exts = "jpg,gif,bmp,png";
    $file_ext = strtolower(substr(strrchr($filename, '.'), 1));

    if (preg_match('/\x00|;|\.\.|\.\//i', $filename)) {
        return "error";
    }

    $ext_check = explode(",", $exts);
    foreach ($ext_check as $ext) {
        if ($file_ext === $ext) return "ok";
    }
    return "error";
}
```

### ② 이중 확장자·트릭 추가 차단

```java
// 이중 확장자 차단: 확장자 목록에 없는 중간 확장자 포함 여부 확인
String[] dangerous = {"jsp", "php", "asp", "aspx", "cgi", "sh", "exe", "pl", "py"};
String lower = fileName.toLowerCase();
for (String ext : dangerous) {
    if (lower.contains("." + ext)) {
        return "false";  // 위험 확장자가 파일명 어디에든 포함되면 거부
    }
}
```

### ③ 업로드 파일 저장 경로 분리

```
웹 루트(Document Root) 바깥의 별도 디렉터리에 저장:
  /var/app/webroot/ → 웹 루트
  /var/upload/files/ → 업로드 저장 (직접 URL 접근 불가)

부득이하게 웹 루트 하위에 저장 시:
  - 해당 폴더 내 모든 실행 권한 제거
  - 웹 서버에서 해당 경로의 스크립트 실행 차단
```

```apache
# Apache: 업로드 폴더 내 스크립트 실행 차단
<Directory /var/www/html/uploads>
    php_flag engine off
    Options -ExecCGI
    RemoveHandler .php .jsp .asp .aspx .cgi .pl .py
    AddType text/plain .php .jsp .asp .aspx
</Directory>
```

### ⑤ 파일 크기 제한

```java
// Spring Boot: 파일 크기 제한 (application.properties)
// spring.servlet.multipart.max-file-size=10MB
// spring.servlet.multipart.max-request-size=15MB

// 코드 레벨 검증
if (file.getSize() > 10 * 1024 * 1024) {  // 10MB
    throw new IllegalArgumentException("파일 크기 초과");
}
if (file.isEmpty()) {
    throw new IllegalArgumentException("빈 파일");
}
```

### ⑥ Apache 설정: AddLanguage / AddCharset 비활성화

```apache

```

## 보완방안

- 업로드 파일 MIME 타입 추가 검증 (Content-Type 헤더는 조작 가능 → 파일 매직 바이트 직접 확인)
  ```java
  // Apache Tika 또는 Files.probeContentType()으로 실제 타입 확인
  String detectedType = tika.detect(file.getInputStream());
  ```
- 에디터(CKEditor 등) 사용 시 서버 측 업로드 핸들러에도 동일한 확장자 검증 적용 (에디터 자체 클라이언트 검증 신뢰 금지)
- 에디터의 디렉터리 생성 기능은 불필요하면 비활성화
- IIS 사용 시 최신 버전으로 업그레이드 (IIS 6.0/7.5 세미콜론 트릭 패치 적용)
- 업로드 후 파일 다운로드 경로를 직접 노출하지 않고 서버에서 스트리밍으로 제공
