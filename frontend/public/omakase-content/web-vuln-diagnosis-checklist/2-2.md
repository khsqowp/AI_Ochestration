# 2-2. 중요 정보 파일 다운로드 가능성

> 파일 다운로드 기능에서 경로 파라미터를 검증하지 않아, 공격자가 Path Traversal 문자를 삽입하여  
> 서버 시스템 파일이나 중요 설정 파일을 다운로드할 수 있는 취약점.

---

## 근본적인 원인

파일 다운로드 기능이 외부 입력값(파라미터)으로 파일 경로를 직접 구성할 때, `../`, `%` 등의 특수문자를 통해 지정된 디렉터리 외부 경로로 이동하여 임의 파일을 읽을 수 있음.

또한 파일 읽기 함수들이 null byte(`\0`)를 파일 끝으로 인식하는 특성을 이용하여 확장자 필터를 우회하는 방식도 존재함.

```
취약한 요청 예:
http://victim.com/download.jsp?path=/upload/&filename=../../../etc/passwd
http://victim.com/download.jsp?path=/upload/&filename=config.properties%00.jpg
```

가이드라인 [표] 12 기준 path traversal 필터링 문자:
`../`, `./`, `..\`, `.\`, `%`, `;`

---

## 2차 피해 시나리오

- 서버 설정 파일(DB 접속정보, 비밀키) 탈취
- `/etc/passwd`, `/etc/shadow` 등 시스템 파일 열람
- 소스코드 파일 다운로드 → 추가 취약점 분석에 활용
- 웹 애플리케이션 `WEB-INF/web.xml`, `application.properties` 등 중요 설정 노출

## 해결 및 대응방안

### ① 경로 파라미터 대신 키 값(UUID/DB ID)으로 파일 식별 (근본 해결)

```java
// 취약: 경로를 파라미터로 직접 전달
// ?path=/upload/&filename=report.pdf

// 안전: UUID 또는 DB PK로 파일 식별
// ?fileId=231996be-6a32-48cb-abbc-6f3d35fcc901

@GetMapping("/download")
public ResponseEntity<Resource> download(@RequestParam String fileId,
                                          HttpServletRequest request) {
    FileInfo info = fileService.findById(fileId);     // DB에서 실제 경로 조회
    if (info == null) return ResponseEntity.notFound().build();

    // 세션 사용자 권한 검증
    String userId = (String) session.getAttribute("userId");
    if (!fileService.hasAccess(userId, fileId)) {
        return ResponseEntity.status(403).build();
    }

    Resource resource = new FileSystemResource(info.getFilePath());
    return ResponseEntity.ok()
        .header(HttpHeaders.CONTENT_DISPOSITION,
                "attachment; filename=\"" + info.getOriginalName() + "\"")
        .body(resource);
}
```

### ② Path Traversal 문자 필터링 (불가피하게 경로 파라미터 사용 시)

```java
// JSP: path traversal 문자 필터링
public String checkPath(String fileName) {
    if (fileName.indexOf("..") != -1 || fileName.indexOf("./") != -1 ||
        fileName.indexOf(".\\") != -1 || fileName.indexOf("../") != -1 ||
        fileName.indexOf("..\\") != -1 || fileName.indexOf("%") != -1) {
        return "false";
    }
    return "true";
}
```

```csharp
// ASP.NET: path traversal 필터링
public bool checkDownloadFile(string strFile) {
    if (strFile.IndexOf("..") != -1 || strFile.IndexOf("/") != -1 ||
        strFile.IndexOf("\\") != -1 || strFile.IndexOf("%") != -1 ||
        strFile.IndexOf(";") != -1) {
        return false;
    }
    return true;
}
```

```php
// PHP 5.3 이후: 정규식으로 path traversal 필터링
function check_Down($filename) {
    if (preg_match('/\.\.\/|\.\.\\\\|%/i', $filename)) {
        return "error";
    }
    return "ok";
}
```

### ③ Canonical Path 검증으로 이중 인코딩 우회 차단

```java
// 필터링 우회 방지: 정규화 후 기준 경로 이탈 여부 확인
String basePath = "/var/upload/files";
File file = new File(basePath, fileName);
String canonical = file.getCanonicalPath();

if (!canonical.startsWith(basePath + File.separator)) {
    response.sendError(403, "Forbidden");
    return;
}
```

### ④ 요청 사용자 권한·세션 검증

```java
// 다운로드 전 반드시 세션 유효성 및 파일 소유자 확인
if (session.getAttribute("userId") == null) {
    response.sendRedirect("/login");
    return;
}
String sessionUser = (String) session.getAttribute("userId");
String fileOwner   = fileDao.getOwnerId(fileId);
if (!sessionUser.equals(fileOwner) && !isAdmin(sessionUser)) {
    response.sendError(403, "Access denied");
    return;
}
```

### ⑤ 파일 정보 최소 노출

- 다운로드 URL에 실제 파일 경로·파일명 미포함 (UUID 또는 Base64 인코딩된 키 사용)
- `Content-Disposition` 헤더에서 실제 서버 저장 경로 노출 금지
- 오류 발생 시 파일 경로를 오류 메시지에 포함하지 않음

```
안전한 URL 예:
http://www.test.com/web/filedownload.cmd?fileId=231996be-6a32-48cb-abbc-6f3d35fcc901
http://www.test.com/Download.jspx?filePath=UlBcMjAxMFwwM&fileName=MjAwOeuFhCTshKD
(경로를 서버에서 Base64로 인코딩하여 전달, 수신 시 복호화 후 서버 내부에서만 경로 사용)
```

## 보완방안

- 파일 경로 매핑이 다양한 경우 서블릿 필터(Filter)를 활용하여 공통 처리
- 파일 저장 위치를 웹 루트(DocBase) 외부 또는 별도 드라이브로 분리 → URL 직접 접근 원천 차단
- 다운로드 이력 로깅 (사용자 ID, 파일 ID, 시각, IP)으로 이상 다운로드 탐지
- 동일 사용자가 단시간 내 대용량 파일을 다수 다운로드하는 경우 알림 처리
