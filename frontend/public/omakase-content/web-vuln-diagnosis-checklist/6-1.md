# 6-1. 오류페이지를 통한 정보 노출 여부

> 오류 발생 시 DB 에러 메시지, 스택 트레이스, 소스 파일 경로, 서버 버전 정보 등이  
> 사용자에게 그대로 노출되어 공격자가 잠재적 취약점을 파악하는 데 활용되는 취약점.

---

## 근본적인 원인

- 예외 처리 미흡: try-catch 없이 예외 발생 시 WAS의 기본 오류 페이지(스택 트레이스 포함) 노출
- DB 쿼리 오류 메시지를 그대로 응답에 포함 → SQL 문법, 테이블명, 컬럼명 노출
- WAS/웹 서버 기본 오류 페이지 미변경 → 서버 종류·버전·경로 노출
- 오류 메시지 통일성 없음 → "file not found" vs "access denied" 차이로 파일 존재 여부 노출

**설정이 필요한 HTTP Error Code:**
- 400: 요청 실패 (문법 오류)
- 401: 클라이언트 인증 실패
- 403: 액세스 금지
- 404: 찾을 수 없음
- 405: 메소드 허용 불가
- 500: 서버 내부 오류

---

## 2차 피해 시나리오

- SQL 에러 메시지로 DB 구조(테이블명, 컬럼명) 파악 → SQL Injection 공격 고도화
- 스택 트레이스로 소스코드 경로, 프레임워크 버전, 내부 구조 파악
- 서버 에러 페이지의 Tomcat/Apache 버전으로 알려진 취약점 타겟팅
- 오류 메시지 차이로 디렉터리 구조 및 파일 존재 여부 탐색

---

## 해결 및 대응방안

### ① 애플리케이션 코드에서 예외 처리 후 일반 메시지만 반환

```java
// 취약: 예외를 그대로 노출
// e.printStackTrace();  → 화면에 출력 금지

// 안전: 로그에만 기록, 사용자에게 일반 메시지 반환
try {
    ...
} catch (SQLException e) {
    log.error("DB 처리 오류: {}", e.getMessage(), e);  // 로그에 상세 기록
    throw new BusinessException("서버 오류가 발생했습니다.");  // 사용자에게 일반 메시지
}
```

### ② Spring Boot: 전역 예외 핸들러 + 커스텀 오류 페이지

```java
// 전역 예외 핸들러
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ModelAndView handleAll(Exception e, HttpServletRequest request) {
        log.error("Unhandled exception: URI={}", request.getRequestURI(), e);
        ModelAndView mav = new ModelAndView("error/500");
        mav.addObject("message", "서버 오류가 발생했습니다.");
        return mav;
    }

    @ExceptionHandler(NotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ModelAndView handleNotFound() {
        return new ModelAndView("error/404");
    }
}
```

```properties
# Spring Boot application.properties
server.error.include-message=never
server.error.include-stacktrace=never
server.error.include-binding-errors=never
server.error.whitelabel.enabled=false
```

### ③ Apache httpd.conf: 커스텀 오류 페이지 설정

```apache
# httpd.conf
ErrorDocument 400 /error/error.html
ErrorDocument 401 /error/error.html
ErrorDocument 403 /error/error.html
ErrorDocument 404 /error/error.html
ErrorDocument 405 /error/error.html
ErrorDocument 500 /error/error.html

# 에러 메시지 폴더를 Alias로 지정 후 에러 코드별 파일 연결
# ※ ErrorDocument 401은 외부 문서 참조 불가, 내부 문서만 지정 가능
```

### ④ Tomcat web.xml: 에러 코드별 오류 페이지 설정

```xml
<!-- WEB-INF/web.xml -->
<error-page>
  <error-code>400</error-code>
  <location>/error/error.jsp</location>
</error-page>
<error-page>
  <error-code>401</error-code>
  <location>/error/error.jsp</location>
</error-page>
<error-page>
  <error-code>403</error-code>
  <location>/error/error.jsp</location>
</error-page>
<error-page>
  <error-code>404</error-code>
  <location>/error/error.jsp</location>
</error-page>
<error-page>
  <error-code>405</error-code>
  <location>/error/error.jsp</location>
</error-page>
<error-page>
  <error-code>500</error-code>
  <location>/error/error.jsp</location>
</error-page>

<!-- 예외 클래스로도 지정 가능 -->
<error-page>
  <exception-type>java.lang.Exception</exception-type>
  <location>/error/error.jsp</location>
</error-page>
```

> **주의**: Tomcat에서 에러 페이지 파일이 512byte 이하이면 브라우저 기본 에러 페이지가 출력됨 → 512byte 초과하도록 작성.

### ⑦ JEUS WEBMain.xml: 브라우저로 에러 메시지 반환 비활성화

```xml
<!-- WEBMain.xml -->
<context-group>
  <group-name>MyGroup</group-name>
  <print-error-to-browser>false</print-error-to-browser>
</context-group>
```

### ⑧ WAS와 별도 웹 서버(Apache, IIS) 연동 시 양쪽 모두 설정

Apache + Tomcat 조합 시: Apache의 `httpd.conf`에도 ErrorDocument 설정 필요  
IIS + ASP.NET 조합 시: IIS 오류 페이지 + ASP.NET `.NET Error Page` 양쪽 모두 설정 적용

## 보완방안

- 오류 메시지를 통일하여 "file not found" / "access denied" 구분 없이 동일한 메시지 반환 (디렉터리 구조 노출 방지)
- fail-open 방지: 보안 점검 실패 시 기본적으로 접근 거부(deny) 처리 — 접근을 열어주는 방향으로 fall-through 금지
- 운영 환경에서 디버그 모드 비활성화 (`spring.profiles.active=prod`)
- WAS 서버 로그는 시스템 내부에만 보관, 오류 상세는 로그로만 기록하고 응답에는 포함 금지
