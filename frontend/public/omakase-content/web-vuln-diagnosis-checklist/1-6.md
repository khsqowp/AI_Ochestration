# 1-6. 입력 값 크기 및 무결성 검증 오류

> 웹 애플리케이션에 전달되는 입력값의 크기·형식·무결성을 검증하지 않아  
> 메모리 오염, 정보 노출, 비인가 접근, 원격 코드 실행 등이 발생하는 취약점 군.

---

## 1. Buffer Overflow (버퍼오버플로우)

### 근본적인 원인
사용자 입력값 크기에 대한 제한·검증이 없을 때, 할당된 저장 공간보다 더 큰 값이 입력되어 인접 메모리 영역을 덮어쓰면서 오류·정보 노출·비인가 접근이 발생함.

C 언어의 `strcpy`, `gets`, `sprintf` 등 경계 검사 없는 함수 사용이 주요 원인. 웹 애플리케이션에서는 파라미터 길이 제한 없이 수천 자를 수용하여 스택 트레이스가 노출되거나 서버 오류가 유발되는 형태로 나타남.

### 2차 피해 시나리오
- 스택 오버플로우 → 인접 메모리의 반환 주소 덮어쓰기 → 임의 코드 실행(RCE)
- 오류 메시지·스택 트레이스 노출 → 내부 경로, 소스코드 구조, DB 정보 노출
- 음수 크기 입력으로 메모리 할당 로직 우회 → Heap 손상
- 서비스 중단(Crash) → 가용성 침해

### 해결 및 대응방안

**① C: 안전한 함수로 교체 + 경계 검증**

```c
// 취약: strcpy는 경계 검사 없음
// strcpy(Target_Dest, User_Input_Data);

// 안전: strncpy로 크기 제한
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
#include <string.h>

int main() {
    char *User_Input_Data = "공격 Payload";
    char Target_Dest[100];

    memset(Target_Dest, '\0', sizeof(Target_Dest));
    strncpy(Target_Dest, User_Input_Data, sizeof(Target_Dest) - 1);
    printf("Copy Data : %s\n", Target_Dest);
    return 0;
}
// 위험 함수: strcpy → strncpy, gets → fgets, sprintf → snprintf
```

**② Java: 배열 크기 내로 입력 제한**

```java
import java.util.Scanner;

public class BufferOverflowPrevention {
    public static void main(String[] args) {
        int[] inputBuffer = new int[5];  // 크기 5로 명시적 제한
        Scanner scan = new Scanner(System.in);

        for (int i = 0; i < inputBuffer.length; i++) {
            System.out.print("User Data 입력: ");
            inputBuffer[i] = scan.nextInt();
        }
    }
}
```

**③ 웹 파라미터 크기 서버 측 검증**

```java
// 파라미터 최대 길이 서버에서 검증
String input = request.getParameter("title");
if (input != null && input.length() > 200) {
    response.sendError(400, "Input too long");
    return;
}
```

**④ 동적 메모리 할당 시 음수 입력 차단**

```java
int size = Integer.parseInt(request.getParameter("size"));
if (size <= 0) {
    response.sendError(400, "Invalid size");
    return;
}
byte[] buffer = new byte[size];
```

**⑤ 오류 발생 시 스택 트레이스 차단 (6-1 항목과 연계)**

```java
try {
    ...
} catch (Exception e) {
    log.error("처리 오류", e);               // 내부 로그에만 기록
    response.sendError(500, "서버 오류");    // 사용자에게 일반 메시지만 반환
}
```

### 보완방안
- 웹 서버 및 WAS 서버 안정성 검증된 최신 버전으로 유지
- 오버플로우 위험 함수(`strcpy`, `gets`, `sprintf`) 코드 감사 (정적 분석 도구 활용)

## 2. Format String (포맷 스트링)

### 근본적인 원인
C 언어 `printf` 계열 함수에서 포맷 문자열을 사용자 입력으로 직접 지정할 때, `%n`, `%x`, `%s` 등의 포맷 지시자로 메모리 내용 노출 및 변조가 가능함.

`%n`은 이전까지 출력된 바이트 수를 해당 변수 메모리에 저장하므로, 공격자가 원하는 값을 메모리에 임의로 기록할 수 있음.

```c
// 주요 포맷 지시자:
// %d: 정수(10진수)  %f: 실수  %c: 문자  %s: 문자열
// %x: 양의 정수(16진수)  %n: 지금까지 쓴 바이트 수 → 메모리 변조 가능
```

### 2차 피해 시나리오
- 스택 메모리 내용 노출 → 내부 변수, 반환 주소, 비밀 데이터 열람
- `%n` 지시자로 메모리 임의 변조 → 관리자 권한 획득
- 임의 코드 실행 (반환 주소 덮어쓰기)

### 해결 및 대응방안

**① 포맷 문자열을 사용자 입력으로 직접 사용 금지**

```c
// 취약: 사용자 입력이 포맷 문자열로 들어감
// printf(argv[1]);

// 안전: 포맷 문자열은 코드에 고정, 변수를 인자로 전달
printf("%s\n", argv[1]);
```

```java
// 취약
System.out.printf(userName);

// 안전: 포맷 문자열 고정
System.out.printf("Safe Code: %s", userName);
```

**② GCC 컴파일러 경고 옵션 활성화**

```bash
# 컴파일 시 포맷 문자열 불일치 경고
gcc -Wall -Wformat -Wformat-security -o output source.c
```

> 단, GCC 경고는 컴파일 타임만 검증 가능. 런타임 검증은 FuzzTesting으로 추가 검증 필요.

### 보완방안
- 정적 분석 도구(Coverity, Fortify 등)로 포맷 문자열 취약점 패턴 탐지
- 웹 서버 프로그램 보안 패치 최신 유지

## 3. Deserialization (역직렬화)

### 근본적인 원인
웹 애플리케이션이 사용자로부터 전달된 직렬화 데이터를 검증 없이 역직렬화할 때, 공격자가 악의적인 가젯 체인(Gadget Chain)을 포함한 직렬화 페이로드를 전송하면 서버에서 임의 코드가 실행됨.

> 직렬화(Serialization): 객체를 바이트 스트림으로 변환  
> 역직렬화(Deserialization): 수신한 바이트 스트림을 다시 객체로 변환

### 2차 피해 시나리오
- Apache Commons Collections 가젯 체인 등을 이용한 원격 코드 실행(RCE)
- 객체 내 중요 속성 변조 (권한, 역할, 금액 등)
- 서버 프로세스 장악 → 내부망 접근

### 해결 및 대응방안

**① 불필요한 역직렬화 자체 미사용 (근본 해결)**

역직렬화가 필요 없는 경우 해당 기능을 비활성화하거나 JSON/XML 등 대안 포맷 사용.

**② 화이트리스트 방식 역직렬화 필터 구현 (Java)**

```java
import java.io.*;
import java.util.logging.Logger;
import java.util.regex.Pattern;

public class DeserializationCheck extends ObjectInputStream {
    private static final Logger log = Logger.getGlobal();
    private boolean useWhiteList;

    // 화이트리스트: 허용할 클래스 패턴
    private static final Pattern[] WHITE_LIST = {
        Pattern.compile("java\\.lang\\.Boolean$"),
        Pattern.compile("java\\.util\\.Date$")
    };

    // 블랙리스트: 알려진 가젯 체인 클래스 차단
    private static final Pattern[] BLACK_LIST = {
        Pattern.compile("org\\.apache\\.commons\\.beanutils\\.BeanComparator$"),
        Pattern.compile("org\\.apache\\.commons\\.collections\\.Transformer$")
    };

    public DeserializationCheck(InputStream inputStream) throws IOException {
        this(inputStream, true);
    }

    public DeserializationCheck(InputStream inputStream, boolean useWhiteList)
            throws IOException {
        super(inputStream);
        this.useWhiteList = useWhiteList;
    }

    @Override
    protected Class<?> resolveClass(ObjectStreamClass desc)
            throws IOException, ClassNotFoundException {
        String className = desc.getName();

        // 블랙리스트 클래스 차단
        for (Pattern p : BLACK_LIST) {
            if (p.matcher(className).find()) {
                String msg = "역직렬화 거부(블랙리스트): " + className;
                log.severe(msg);
                throw new InvalidClassException(msg);
            }
        }

        // 화이트리스트 검증
        if (useWhiteList) {
            boolean allowed = false;
            for (Pattern p : WHITE_LIST) {
                if (p.matcher(className).find()) {
                    allowed = true;
                    break;
                }
            }
            if (!allowed) {
                String msg = "역직렬화 거부(화이트리스트 미포함): " + className;
                log.severe(msg);
                throw new InvalidClassException(msg);
            }
        }

        return super.resolveClass(desc);
    }
}
```

**③ 역직렬화 후 무결성 검증**

```java
// 역직렬화 후 객체 상태 검증
UserOrder order = (UserOrder) deserialize(data);
if (order.getAmount() <= 0 || order.getUserId() == null) {
    throw new SecurityException("Invalid deserialized object");
}
```

**④ 서드파티 라이브러리 최신 버전 유지**

Apache Commons Collections, Spring Framework 등 가젯 체인이 발견된 라이브러리는 취약 버전 사용 시 즉시 패치.

### 보완방안
- 외부에서 직렬화 데이터를 수신하는 API 엔드포인트 식별 후 전수 검토
- `serialVersionUID` 명시적 선언으로 버전 불일치 조기 감지
- Java 9 이상: `ObjectInputFilter` API로 역직렬화 필터 JVM 전역 적용 가능
