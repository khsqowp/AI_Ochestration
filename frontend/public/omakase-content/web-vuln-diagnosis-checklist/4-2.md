# 4-2. 인증(세션 및 토큰) 값 안전성 설정 여부

> 웹 애플리케이션에서 사용하는 인증값(세션 ID, 토큰)의 복잡도·만료시간·파기·사용횟수·중복 로그인 등  
> 안전성 설정이 미흡할 때 공격자가 이를 탈취·재사용하여 타인 계정으로 접근하는 취약점.

---

## 근본적인 원인 (취약점 유형별)

| 유형 | 원인 |
|------|------|
| 복잡도 미흡 | 세션 ID·토큰 생성 패턴이 단순·짧아 예측 가능 |
| 만료시간 미설정 | 비활성 상태에서도 세션이 유지되어 탈취 후 장시간 악용 |
| 미파기 | 로그아웃 후 서버에서 세션을 무효화하지 않아 재사용 가능 |
| 사용횟수 무제한 | 일회성 토큰(OTP, 결제 토큰)을 반복 사용 가능 |
| 동일 세션 ID 재사용 | 로그인마다 동일 세션 ID → 고정 세션 탈취 후 영구 사용 |
| 중복 로그인 허용 | 동일 계정으로 다른 IP에서 동시 접속 → 도용 계정 탐지 불가 |

---

## 2차 피해 시나리오

- 세션 ID 탈취 후 로그아웃 없이 장시간 타인 계정 사용
- 결제 토큰 반복 사용으로 무한 결제 시도
- 만료되지 않은 세션으로 로그아웃된 사용자의 기능 접근
- 동일 세션 ID 예측(순번 등)으로 타인 세션 탈취

---

## 해결 및 대응방안

### ① 복잡도: 예측 불가능한 세션 ID 생성

```java
// WAS 기본 제공 세션 사용 (안전한 무작위 ID 자동 생성)
// Tomcat, Spring 등은 SecureRandom 기반으로 세션 ID 생성 → 별도 구현 불필요

// JWT 토큰 사용 시: 안전한 서명 + 만료시간 포함
String token = Jwts.builder()
    .setSubject(userId)
    .setIssuedAt(new Date())
    .setExpiration(new Date(System.currentTimeMillis() + 30 * 60 * 1000)) // 30분
    .signWith(SignatureAlgorithm.HS256, SECRET_KEY)
    .compact();
```

### ② 만료시간 설정 (권고: 30분)

```xml
<!-- Tomcat/WAS web.xml -->
<session-config>
  <session-timeout>30</session-timeout>  <!-- 분 단위 -->
</session-config>
```

```xml
<!-- WebLogic weblogic.xml (초 단위) -->
<session-descriptor>
  <timeout-secs>1800</timeout-secs>
</session-descriptor>
```

```xml
<!-- JEUS WEB-INF/web.xml -->
<session-config>
  <session-timeout>30</session-timeout>
</session-config>
```

```java
// 코드 레벨: 세션 타임아웃 명시적 설정
session.setMaxInactiveInterval(30 * 60);  // 1800초 = 30분
```

### ③ 로그아웃 시 세션 즉시 파기

```java
// Spring MVC 로그아웃
@PostMapping("/logout")
public String logout(HttpSession session) {
    session.invalidate();  // 서버 측 세션 파기
    return "redirect:/login";
}
```

```java
// Spring Security 로그아웃 핸들러 설정
http.logout()
    .logoutUrl("/logout")
    .invalidateHttpSession(true)
    .deleteCookies("JSESSIONID")
    .logoutSuccessUrl("/login?logout");
```

### ④ 일회성 토큰 사용횟수 제한

```java
// 결제·인증 토큰: 사용 후 즉시 파기
public boolean validateAndConsumeToken(String tokenId) {
    Token token = tokenDao.findById(tokenId);
    if (token == null || token.isUsed() || token.isExpired()) {
        return false;
    }
    tokenDao.markUsed(tokenId);  // 사용 처리 → 재사용 불가
    return true;
}
```

### ⑤ 로그인 시 새로운 세션 ID 발급 (Session Fixation 방지)

```java
// Spring Security: 기본으로 Session Fixation 방어 (로그인 시 새 세션 ID 발급)
http.sessionManagement()
    .sessionFixation().migrateSession();  // 로그인 시 세션 ID 재발급
```

### ⑥ 중복 로그인 방지: 고유 키 세션에 포함하여 서버 검증

```java
// 고유 키 생성: Hash(TimeStamp | IP | UserID | Token)
String uniqueKey = DigestUtils.sha256Hex(
    System.currentTimeMillis() + loginIp + userId + UUID.randomUUID().toString()
);
session.setAttribute("sessionKey", uniqueKey);
session.setAttribute("loginIp",    loginIp);
sessionStore.put(userId, uniqueKey);  // 최신 세션 키 서버 저장

// 요청 시 검증
String storedKey = sessionStore.get(userId);
String requestKey = (String) session.getAttribute("sessionKey");
if (!storedKey.equals(requestKey)) {
    session.invalidate();
    response.sendError(403, "중복 로그인 감지");
    return;
}
```

```csharp
// ASP.NET: 로그인 IP 세션 저장 + 검증
Session["UserID"] = id;
Session["LoginIP"] = Request.UserHostAddress;

// 권한 필요 페이지 진입 시
if (Session["UserID"] == null) return Redirect("/Error?message=Need Login");
if (!Request.UserHostAddress.Equals(Session["LoginIP"].ToString()))
    return Redirect("/Error?message=Your session is duplicated");
```

```php
// PHP: IP 세션 저장 + 검증
@session_start();
$_SESSION["user_ip"] = $_SERVER["REMOTE_ADDR"];

if ($_SESSION["user_ip"] !== $_SERVER["REMOTE_ADDR"]) {
    echo "중복 세션";
    exit;
}
```

```java
// JSP: IP + UID 세션 저장 + 검증
String ip = request.getRemoteAddr();
session.setAttribute("ip", ip);
session.setAttribute("uid", userid);

// 이후 요청 시
String sessionIp  = (String) session.getAttribute("ip");
String sessionUid = (String) session.getAttribute("uid");
if (!ip.equals(sessionIp) || !userId.equals(sessionUid)) {
    out.println("중복 세션");
}
```

> **참고**: 외부서비스 인증 시 NAT IP로 인한 접속오류 발생 가능 — 서비스 영향도 확인 후 적용.

## 보완방안

- JWT 사용 시 `exp` 클레임 필수 포함, 서버에서 만료 검증
- 로그아웃 후 쿠키(`JSESSIONID`) 삭제 처리 → 클라이언트 측 세션 쿠키도 제거
- 세션 스토어를 Redis 등 중앙 저장소로 관리하여 중복 세션 제어
- 고위험 작업(결제, 비밀번호 변경) 전 세션 갱신 후 재인증
