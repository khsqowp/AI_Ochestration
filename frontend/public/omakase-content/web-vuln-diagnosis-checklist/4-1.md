# 4-1. 쿠키(Cookie) 및 웹 스토리지(Web Storage) 조작 가능성

> 클라이언트 측에 저장되는 쿠키 또는 웹 스토리지에 인증정보·권한 데이터를 저장하고  
> 해당 값만으로 인증을 처리할 경우, 값을 조작하여 다른 사용자나 관리자로 도용할 수 있는 취약점.

---

## 근본적인 원인

- 쿠키에 `role=admin`, `isAdmin=true` 등 권한 정보를 저장하고 서버에서 그대로 신뢰
- 인증·세션 값을 쿠키/웹 스토리지에 저장하면서 암호화 없이 평문으로 보관
- 쿠키에 `Secure` 옵션 미설정 → HTTP 평문 전송 시 패킷 캡처로 쿠키 탈취 가능
- XSS 취약점으로 JavaScript가 `document.cookie` 또는 `localStorage`에 접근하여 값 탈취

**웹 스토리지 특징:**
- HTTP 요청 시 서버에 자동 전달되지 않음 (쿠키와 차이)
- SOP(Same Origin Policy)로 기본 보호되나 JavaScript로 조작 가능
- Local Storage: 브라우저 종료 후에도 데이터 유지
- Session Storage: 탭/브라우저 종료 시 데이터 삭제

---

## 2차 피해 시나리오

- 쿠키 조작으로 권한 상승 (`role=user` → `role=admin`)
- XSS와 결합하여 쿠키 탈취 후 세션 하이재킹
- 네트워크 패킷 캡처로 평문 쿠키 탈취 → 세션 도용
- Local Storage에 저장된 인증 토큰 탈취 → XSS로 스크립트 실행 후 값 외부 전송

---

## 해결 및 대응방안

### ① Server Side Session 사용 (근본 해결)

```java
// 클라이언트에 권한 정보 저장 금지
// 취약: 쿠키에 권한 저장
// Cookie roleCookie = new Cookie("role", "admin");

// 안전: 서버 세션에만 저장
session.setAttribute("userId", userId);
session.setAttribute("role", "admin");

// 사용 시 항상 세션에서 조회
String role = (String) session.getAttribute("role");
```

### ② 불가피하게 쿠키에 중요 정보를 저장하는 경우: 암호화

```java
// AES256 암호화 후 쿠키 저장
String encryptedValue = AES256.encrypt(sensitiveValue, SECRET_KEY);
Cookie cookie = new Cookie("authData", encryptedValue);
cookie.setHttpOnly(true);
cookie.setSecure(true);
cookie.setPath("/");
response.addCookie(cookie);

// 사용 시 복호화 + 무결성 검증
String decrypted = AES256.decrypt(request.getCookies()["authData"], SECRET_KEY);
```

### ③ 쿠키 Secure 옵션 설정 (HTTPS에서만 전송)

```xml
<!-- Java web.xml -->
<session-config>
  <cookie-config>
    <secure>true</secure>
    <http-only>true</http-only>
  </cookie-config>
</session-config>
```

```ini
; PHP php.ini
session.cookie_secure = true
session.cookie_httponly = true
session.cookie_samesite = Strict
```

```java
// Spring Boot application.properties
// server.servlet.session.cookie.secure=true
// server.servlet.session.cookie.http-only=true
// server.servlet.session.cookie.same-site=strict

// 또는 수동 생성
ResponseCookie cookie = ResponseCookie.from("JSESSIONID", sessionId)
    .httpOnly(true)
    .secure(true)
    .sameSite("Strict")
    .path("/")
    .build();
response.addHeader(HttpHeaders.SET_COOKIE, cookie.toString());
```

### ④ 권한 검증을 서버에서 수행 (ASP.NET)

```csharp
// App_Start\FilterConfig.cs: 전역 AuthorizeAttribute 등록
public static void RegisterGlobalFilters(GlobalFilterCollection filters) {
    filters.Add(new System.Web.Http.AuthorizeAttribute());
}

// 특정 권한에게만 허용
[Authorize(Roles = "Admin")]
[HttpPost, ActionName("Delete")]
public ActionResult Delete(int id) {
    User user = db.Users.Find(id);
    db.Users.Remove(user);
    db.SaveChanges();
    return RedirectToAction("UserList");
}

// 비로그인 허용 페이지는 명시적으로 [AllowAnonymous]
[AllowAnonymous]
public ActionResult Index() { return View(); }
```

### ⑤ 세션 + IP 이중 검증 (ASP)

```vbscript
<%
UserGrade = "admin"  ' 이 페이지 접근에 필요한 권한 레벨

' 세션 권한 확인
If UserGrade <> Session("user_grade") Then
    Response.Write "<script>alert('접근 제한');history.go(-1);</script>"
    Response.End
Else
    If UserGrade = "admin" Then
        ' 관리자: IP + 로그인 여부 이중 확인
        If InStr(Request.ServerVariables("REMOTE_ADDR"), Session("access_ip")) Then
            If Session("logged_in") = "" Then
                Response.Write "<script>alert('로그인 필요');history.go(-1);</script>"
                Response.End
            End If
        Else
            Response.Write "<script>alert('IP 접근 제한');history.go(-1);</script>"
            Response.End
        End If
    ElseIf UserGrade = "user" Then
        If Session("user_id") = "" Then
            Response.Write "<script>alert('로그인 필요');history.go(-1);</script>"
            Response.End
        End If
    End If
End If
%>
```

### ⑥ 중요 프로세스에 2차 인증 적용

```java
// 결제·정보변경 등 중요 프로세스 진입 전 재인증
@GetMapping("/payment")
public String payment(HttpSession session, Model model) {
    if (session.getAttribute("passwordVerified") == null) {
        return "redirect:/auth/verify?returnUrl=/payment";
    }
    return "payment";
}
```

## 보완방안

- 불필요한 쿠키 정보(개인정보, 권한값) 저장 금지
- 웹 스토리지(localStorage)에 JWT·세션 토큰 저장 지양 → HttpOnly 쿠키로 대체
- XSS 취약점 해소 선행 (1-1 항목) — XSS가 있으면 HttpOnly 이외의 스토리지는 모두 탈취 가능
- 세션 ID는 예측 불가능한 무작위 값으로 생성 (프레임워크 기본 제공값 사용 권장)
