# 블랙박스 진단 훈련 v2 요구사항 명세서

상태: 구현 기준안  
작성일: 2026-09-13  
범위: `/dashboard/역량강화`의 블랙박스 사건형 훈련

## 1. 문제 정의

기존 사건형 훈련은 학습자의 자연어 행동을 실제 가상 대상의 상태 변화와 관측 결과로 연결하지 못한 경우가 있었다. 특히 다음 결함은 학습 목적을 훼손한다.

- 학습자가 URL 접근 또는 응답 헤더 확인을 요청해도, 대상 관측 대신 일반적 안내가 반환될 수 있다.
- 같은 세션 상태에서 같은 요청이 저장·복원 뒤 달라질 수 있다.
- 쿠폰 재사용, 주문 경계, 동시성, 할인 정책처럼 실무 진단에 필요한 업무 규칙 검증 사건이 없다.
- 종료 점수가 정답 판정과 관측 키 개수에 과도하게 의존한다. 근거의 정확성·과잉 단정·미확정 범위 구분을 평가하지 못한다.
- 고정된 답안 항목을 강요하면 실제로 확보하지 못한 내용을 채우게 된다.

## 2. 제품 목표와 비목표

### 목표

1. 학습자가 제공된 URL과 테스트 계정만으로 자연어 질문·요청을 수행한다.
2. 가상 대상은 세션 상태를 유일한 기준으로 하여 HTTP 응답, 화면상 데이터, 상태 변화를 반환한다.
3. 같은 초기 상태와 같은 행동은 항상 같은 관측을 반환한다. 저장 후 재개도 포함한다.
4. 코치는 정답·취약점 후보·숨은 상태를 공개하지 않고, 이미 관측된 사실에서 빠진 검증 축만 질문으로 넓힌다.
5. 종료 시 AI 평가는 자유 형식 결론을 읽고, 관측 사실·추론·확정 불가 범위를 분리해 종합 평가한다.
6. 역량 대시보드는 한 사건의 점수 대신 최근 사건들의 누적 증거로 갱신한다.

### 비목표

- 실제 외부 사이트에 요청하거나 실제 계정·쿠키·취약점을 대상으로 공격하지 않는다.
- 코드, 서버 로그, 데이터베이스, 숨은 정답을 학습자에게 제공하지 않는다.
- 답안에 고정된 섹션 수·문장 수·키워드를 강요하지 않는다.
- AI가 관측하지 않은 HTTP 응답·사용자 데이터·운영 사실을 창작하지 않는다.

## 3. 역할과 정보 경계

| 역할 | 책임 | 절대 제공하지 않는 것 |
| --- | --- | --- |
| 가상 대상 | 로그인, URL 요청, 상태 전이, HTTP/UI 관측 반환 | 원인, 취약점명, 숨은 데이터, 다음 정답 행동 |
| 명령 해석기 | 자연어를 허용된 대상 행동으로 변환 | 관측 결과 창작 |
| 코치 | 관측된 사실을 바탕으로 검증 축을 질문 형태로 제안 | 정답 후보, 확정 판정, 미관측 사실 |
| 평가기 | 종료 답안을 사건 관측과 대조해 근거 기반 평가 | 양식 위반만으로 감점, 없는 사실의 보충 |

가상 대상의 관측 결과가 유일한 사실 공급원이다. 코치와 평가기는 그 결과와 학습자가 쓴 내용만 해석한다.

## 4. 사용자 흐름

1. 사용자는 사건을 시작한다. 사건 개요에는 대상 주소, 테스트 계정, 공개된 기능과 제한만 표시한다.
2. 사용자는 자유롭게 질문하거나 행동을 적는다. 예: `A 계정으로 로그인 후 /orders/O-2008 조회`, `직전 302의 Location 값은?`.
3. 명령 해석기는 명확한 행동을 결정적으로 해석한다. 모호한 문장은 제한된 AI 해석을 사용하되, 해석 실패는 실행하지 않았음을 명확히 알린다.
4. 가상 대상은 상태에 따른 관측을 반환한다. 한 메시지에 로그인과 요청이 있으면 순서대로 두 결과를 반환한다.
5. 코치는 관측 뒤에만 선택적으로 한 개의 열린 질문을 보낸다. 코칭 실패는 대상 관측을 막지 않는다.
6. 사용자는 메모를 자유 형식으로 저장하거나, 충분하다고 판단하면 자유 형식 결론과 판정으로 종료한다.
7. 평가기는 대화, 관측, 메모, 결론을 종합한다. 재시도는 새 세션이며 이전 채팅을 가져오지 않는다.

## 5. 가상 대상 계약

### 5.1 결정성

- `target.execute(state, command)`은 외부 모델 호출, 현재 시간, 난수, DB 조회에 의존하지 않는다.
- 같은 `state`와 `command`는 `transcript`, `observationKey`, `nextState`가 모두 동일해야 한다.
- 런타임 상태는 다중 줄 HTTP 전문을 손실 없이 인코딩하여 DB 왕복 뒤 복원한다.
- 질문형 요청은 대상 상태를 바꾸지 않는다.

### 5.2 관측 계약

- 유효한 로그인, URL 접근, 헤더 조회, 상태 코드 조회, 재조회는 구체적 결과를 반환한다.
- 유효하지 않은 경로나 메서드는 실제 서비스와 같은 형태의 404/405/401 결과를 반환한다.
- 이전 응답의 `Location`, `Set-Cookie`, 상태 코드, 전체 헤더를 묻는 요청은 직전 관측에서 추출해 반환한다.
- 관측이 없는 상태에서는 사실을 만들지 않고 “아직 실행된 요청이 없다”고 반환한다.

### 5.3 쿠폰 업무 규칙 사건

사건은 소유권뿐 아니라 다음 축을 학습자가 스스로 확장할 수 있게 한다.

- 사용자·주문 경계: 한 사용자의 쿠폰이 다른 주문에도 다시 적용되는가.
- 사용 횟수: 사용자 단위 1회 제한이 실제 할인 결과에도 지켜지는가.
- 금액 조건: 최소 주문금액이 적용되는가.
- 적용 범위: 지정 상품·카테고리 조건이 지켜지는가.
- 주문 상태: 결제 완료·취소·환불 뒤 정책이 지켜지는가.
- 동시성: 동일 쿠폰에 대한 복수 요청의 응답과 실제 할인 상태가 일치하는가.

동시 요청의 `200 OK`만으로 레이스 컨디션을 확정하지 않는다. 두 주문의 실제 할인 금액, 쿠폰 사용 이력, 재조회 상태를 통해 경제적 효과가 중복됐는지 확인해야 한다.

## 6. 코치 응답 정책 및 프롬프트

코치는 자유 문장으로 답한다. 제목, 번호, 체크리스트, 정해진 답안 칸을 강요하지 않는다. 이미 사용자가 한 말을 반복하거나 숨은 사실을 추가하지 않는다.

시스템 프롬프트 초안:

```text
당신은 교육용 블랙박스 보안 진단의 코치다.

목적은 학습자가 스스로 관측하고 가설을 검증하도록 돕는 것이다. 답을 맞히게 하거나 보고서 양식을 강요하는 것이 목적이 아니다.

반드시 지킬 규칙:
- 제공된 사건 공개 정보, 대화 기록, 가상 대상이 실제로 반환한 관측만 사실로 취급한다.
- 관측하지 않은 HTTP 상태, 헤더, 쿠키, 데이터, 내부 구현, 취약점 원인을 만들거나 암시하지 않는다.
- 취약점 이름, 정답 후보, 정답 행동 목록을 먼저 제시하지 않는다.
- 학습자가 행동을 아직 수행하지 않았다면, 가능한 행동을 하나의 열린 질문으로 되묻는다.
- 행동 결과가 있다면, 그 결과가 확인한 것과 아직 확인하지 못한 것을 짧고 자연스러운 문장으로 구분한다.
- 필요한 경우에만 기존 관측과 다른 검증 축 하나를 질문한다. 예: 사용자 경계 다음에는 횟수, 시간, 주문 상태, 할인 적용 결과, 동시성 중 관련된 한 축.
- 답안 형식, 제목, 항목 수, 최소 분량을 요구하지 않는다. 학습자가 확보하지 않은 근거를 채우도록 유도하지 않는다.
- 학습자가 '모르겠다'고 하면 정답을 공개하지 않는다. 지금까지 관측한 사실 한 개와 그 사실만으로 확정할 수 없는 점 한 개를 짚고, 다음에 확인할 수 있는 질문 한 개만 한다.
- 코칭은 최대 5문장이다. 대상 관측 전문을 복사하지 않는다.
```

## 7. 종료 평가 정책

평가는 고정 양식 충족 여부가 아니라 아래 근거를 사용한다.

| 평가 축 | 100점 수준 | 80점 수준 | 60점 수준 |
| --- | --- | --- | --- |
| 관측 정확성 | 실제 관측과 모순 없음 | 핵심 관측은 맞으나 일부 누락 | 관측과 결론이 부분적으로 어긋남 |
| 인과 추론 | 관측과 결론의 연결이 명확하고 과잉 단정 없음 | 주된 연결은 타당하나 대안 설명이 부족 | 응답 코드만으로 원인을 확정하는 등 비약 존재 |
| 검증 범위 | 사건에 맞는 추가 상태·재조회·경계 검증 제시 | 하나 이상의 중요한 축 누락 | 소유권 또는 응답 성공 여부만 반복 |
| 불확실성 관리 | 확정 사실과 미확정 사실을 구분 | 일부 구분 | 근거 부족 상태를 확정으로 표현 |

점수는 모델의 숫자만 사용하지 않는다. 필수 관측의 충족 여부와 판정의 일치 여부를 기계적으로 반영하고, AI 평가는 서술 근거의 질만 보완한다. AI 실패 시 점수·피드백은 결정적 기본 평가로 생성한다.

## 8. 수용 기준

- [ ] `A 로그인 후 /orders/O-2008 조회`는 로그인 302와 주문 조회 200을 순서대로 반환한다.
- [ ] `리다이렉트 후 주소는?`, `세션 쿠키 값은?`, `직전 응답 헤더는?`는 직전 관측에서 일관되게 답한다.
- [ ] 동일 상태·동일 명령의 반복, 상태 직렬화·복원 뒤 반복 결과가 완전히 일치한다.
- [ ] 쿠폰 사건에서 다른 주문 재사용, 최소 금액 미달, 결제 완료 주문, 동시 요청, 재조회가 서로 다른 상태와 관측으로 작동한다.
- [ ] `200 OK` 다건 응답만으로 레이스 컨디션 확정 피드백을 반환하지 않는다.
- [ ] “모르겠다”는 메시지가 오류나 정답 공개가 아니라 열린 재검증 질문으로 이어진다.
- [ ] 종료 피드백은 답안 양식 부족을 요구하지 않으며, 관측·추론·미확정 범위 기준을 제시한다.
- [ ] 100·80·60 수준, 오답, 모름 응답이 회귀 테스트와 독립 검토에서 구분된다.

## 9. 알려진 제약

- 실제 API 키, 외부 브라우징, 실제 HTTP 대상은 이 훈련에 사용하지 않는다.
- 모델 호출은 지연·실패할 수 있다. 명령 실행과 가상 대상 결과는 모델 호출과 독립적으로 완료되어야 한다.
- 브라우저 인증 쿠키가 없으면 실제 API 엔드포인트 E2E는 수행할 수 없다. 이 경우 단위·서비스 계약 테스트는 실행하되, 인증된 UI E2E 공백을 명시한다.

## 10. 실행 계획과 완료 기준

| 순서 | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | 요구사항·정보 경계 확정 | 본 문서의 목표, 비목표, 수용 기준 검토 | 완료 |
| 2 | 쿠폰 업무 규칙 사건 추가 | 자연어 적용 요청, 주문 재조회, 이력 조회, 동시 두 주문 요청 지원 | 완료 |
| 3 | 상태 결정성 회귀 방어 | 동일 상태·명령, DB 직렬화 복원 뒤 결과 일치 테스트 | 완료 |
| 4 | 자유 대화 코치 추가 | 관측 후에만 작동, 모델 실패 시 안전한 열린 질문으로 대체 | 완료 |
| 5 | 자유 형식 결론 평가 | 양식 요구 없이 관측·실제 효과·미확정 범위를 평가 | 완료 |
| 6 | 자동 계약 테스트 | 기존 주문/세션 사건과 새 쿠폰 사건, 코치, 100·80·60 수준 평가 통과 | 완료 |
| 7 | 빌드·컨테이너 검증 | 프런트엔드 빌드, API 컨테이너 재빌드, 헬스 확인 | 진행 전 |
| 8 | 독립 시나리오 검증 | 세 명의 독립 검토자가 정답·부분 답·오답·모름·반복 요청을 검토 | 진행 전 |

### 검증용 답안 등급 시나리오

- 높은 수준: 두 주문의 재조회 결과와 쿠폰 이력 1건을 연결하고, 취소·환불 등 아직 검증하지 못한 범위를 명시한다.
- 중간 수준: 두 주문의 실제 할인 효과는 확인했으나 쿠폰 이력 또는 후속 상태를 누락한다.
- 낮은 수준: 동시 요청의 `200 OK`만으로 문제를 확정한다.
- 오답: 실제 두 주문 할인 관측이 있어도 정상 동작이라고 결론 낸다.
- 모름: 정답을 받지 않고, 현재 관측과 다음 한 번의 검증 행동을 받는다.
