## 2. 가장 중요한 경고

Claude 기록의 주 대상은 개인용 **AI 오케스트레이션·지식베이스·트레이딩 대시보드**였다. 현재 Git HEAD는 주문·랜딩·스마트 디코더 등 이후 변경이 누적된 상태다. 따라서 과거 기록에 등장하는 파일, 화면, 컨테이너, API가 현재 트리에 그대로 존재한다고 가정하면 안 된다.

앞으로 작업 전에는 반드시 다음 순서로 확인한다.

1. 현재 브랜치와 변경 파일을 확인한다.
2. 이 문서에서 과거 의도와 제약을 확인한다.
3. 실제 코드·DB·컨테이너가 해당 기능을 아직 보유하는지 확인한다.
4. 과거 기능 복구가 필요하면 사용자의 명시적 요청으로 처리한다.

## 3. 제품의 원래 목표

개인 연구실 형태의 시스템이다. PM이 사용자의 지시를 계획하고, 분야별 수집·검토·팀장·보관 역할이 작업을 분업하며, 결과는 파일과 지식베이스에 남긴다.

핵심 도메인은 다음이다.

- 보안: 신뢰 가능한 사이트의 보안 동향·학습 자료 수집과 한국어 정리.
- 경제: 한국·미국 시장, ETF, 테마, 배당, 비트코인 관련 조사와 분석 준비.
- 일반: 보안·경제 밖의 질문, 파일 기반 조사, 개인 아이디어 정리.
- 파일 지식베이스: `originals/`의 원본을 보존하고 `obsidian/`에 가공 Markdown을 보관.
- 2D 오피스: 실제 작업 단계와 담당자의 이동·말풍선·진행 경로를 표시.
- 트레이딩: 국장·미장 모의투자, 암호화폐 전략·백테스트·상태 대시보드. 실거래와 모의투자는 엄격히 구분.

## 4. 확정된 설계 원칙

### 4.1 에이전트 파이프라인

기본 흐름은 다음이다.

`수집(Gemini) → 검토 A(GPT) → 검토 B(GPT) → 분야 팀장(DeepSeek) → PM(DeepSeek) → Archive`

- PM은 움직이지 않고 회의실에 머문다.
- 직원 이동은 랜덤 배회가 아니라, 작업 완료 뒤 다음 담당자에게 보고하는 흐름이어야 한다.
- 아카이브 담당자는 최종 확인이 끝난 자료만 수령해 보관한다.
- 수집 실패·robots 차단·검색 거부 자료는 검토자·팀장·PM으로 올리지 않는다.
- 사용자 보고는 짧은 두괄식 요약과 파일 위치가 기본이다. 상세 설명 요청 시에만 확장한다.
- 해외 자료는 한국어로 정리한다. 통용 기술 용어만 영어를 병기한다.

### 4.2 아카이브 품질

- 화면 보고와 아카이브 노트는 목적이 다르다. 화면은 짧고, 노트는 학습 가능한 본문이어야 한다.
- 사용자 기준 SQL Injection 노트 약 2,475자를 기준으로, 아카이브 본문 최소 목표는 약 12,500자다.
- 메타 발언, 내부 판단, 모델 추론, 검토 과정, 확신도 나열, 시스템 로그를 노트 본문에 넣지 않는다.
- 노트는 개념 설명, 상세 내용, 예시·비교, 실무·학습 포인트, 핵심 정리 순으로 자연스럽게 구성한다.
- 같은 주제·동일 또는 높은 유사도의 자료는 파일을 늘리지 않는다. 기존 일자 노트에 병합하거나 추가 수집 섹션으로 통합한다.
- 뉴스 수집 결과는 소스별 파일 분할이 아니라 도메인별 하루 한 파일이 원칙이다. 예: `security/뉴스/YYYY-MM-DD.md`.
- 중복 정리 자동화는 삭제보다 `_archived/` 이동을 우선한다.

### 4.3 파일과 RAG

- 업로드와 로컬 감시 대상: `txt`, `md`, `pdf`, `docx`, `xlsx`, `pptx`, `hwp`, 이미지.
- 원본은 프로젝트 내부 `originals/`에 둔다. 가공 결과는 `obsidian/`에 둔다.
- Markdown·TXT·PDF는 화면 조회 대상이다. 그 밖의 원본은 기본적으로 다운로드 대상이다.
- Markdown은 원문 기호가 아니라 렌더링된 문서로 표시한다.
- 파일 탐색기는 주제 폴더 구조, 검색, Markdown 렌더링, AI 재가공, 그래프 뷰를 제공한다.
- RAG는 아카이브 노트에 있는 근거만 답변한다. 노트 밖 정보는 답변하지 않는다.
- RAG 대화 기록은 보관하되, 자동으로 별도 지식 파일을 만들지 않는다.

### 4.4 보안·인증

- API 키와 비밀값은 `.env`에서만 관리한다. UI, 로그, Git에 노출하지 않는다.
- 로그인 기반은 구현하되 개발 단계에서는 비활성화 가능해야 한다.
- 운영 모드의 인증은 JWT 기반이다.
- 관리자만 쓰기·설정·사용량·계정 관리·트레이딩 제어를 수행한다.
- 일반 사용자는 파일 아카이브, 수집 사이트 조회, 에이전트 조회, 보안 캘린더, 치트시트만 읽기 전용으로 본다.
- API 경로 단위 권한 검증, 세션 폐기, 예외 처리, 입력 검증, 레이트 리밋을 적용한다.
- robots.txt는 우회하지 않는다. 명시적 차단 사이트는 수집 실패로 기록하고 다음 단계로 전달하지 않는다.

### 4.5 UI·운영 원칙

- 모든 상태는 백엔드가 단일 진실 공급원으로 보유한다.
- UI는 폴링 또는 WebSocket으로 자동 갱신한다. 새로고침을 요구하지 않는다.
- 진행 작업마다 독립된 선·점·상태 메시지·진행표를 표시한다.
- 말풍선을 클릭하면 단계별 간트형 진행표를 연다.
- 하단바의 수집 결과 명칭은 `원본 N개 검토`가 아니라 `파일 아카이브`다.
- 모바일 대시보드는 별도 검증 대상이다. 데스크톱 CSS 축소만으로 완료 선언하지 않는다.

## 5. Claude Code에서 구현·검증했다고 기록된 기능

기록상 구현됐지만 현재 트리 존재 여부는 별도 점검이 필요하다.

1. Spring Boot, React, MySQL, Docker Compose, n8n 기반 오케스트레이션 스택.
2. Gemini 수집, GPT-4o mini 이중 검토, DeepSeek 팀장·PM 종합 파이프라인.
3. Web 수집기: 동일 호스트 링크 깊이 탐색, 리디렉션 재검증, SSRF 차단, robots 준수, 수집 원문 발췌를 후속 작업에 전달.
4. 파일 형식 추출: PDFBox, Apache POI, HWP 처리, 이미지 Gemini 분석을 비동기 워크플로에 배치.
5. 지식 아카이브: 중복 유사도, 일별 뉴스 병합, `_archived/` 보존, 주기적 전체 정리.
6. 큰 모달형 파일 탐색기, RAG 대화 기록, 보안 캘린더·사건 타임라인, AI 토론 화면.
7. JWT RBAC, 관리자·사용자 CRUD, API 경로 권한, 공개 엔드포인트 레이트 리밋.
8. 2D 픽셀 에이전트와 단계별 전달 이동.
9. 사용량·토큰 비용 화면. Gemini 검색 grounding, 캐시, 세금, 프로모션, 계약 할인은 토큰 추정치에서 제외.
10. 거래 상태 대시보드, 국장·미장·암호화폐 데이터 수집, 틱 아카이브, 백테스트, 수익 곡선 상호작용.

## 6. 트레이딩 관련 결정과 제약

트레이딩 기능은 오케스트레이션 앱과 별도 중첩 저장소 `trading/`에 있었다.

- 국장·미장은 KIS 모의투자를 우선한다. 주문 요청은 1초 이상 간격과 재시도 백오프가 필요하다.
- 암호화폐 펀딩비 차익은 연환산 펀딩이 음수로 전환될 때만 청산하도록 설계된 적이 있다. 장시간 보유가 곧 오류는 아니다.
- 앱 잔고와 대시보드 잔고 차이는 Spot·Futures 외 지갑을 제외한 계산으로 발생할 수 있다.
- 실거래 자금은 펀딩비 전략에서 분리하고, TRX와 모의 전략 상태를 혼동하지 않는다.
- 틱 데이터는 로컬 JSONL로 기록하고 NAS는 주기적 백업 대상으로 쓴다. NAS에 실시간 지속 쓰기를 하지 않는다.
- 데이터 디스크 정리 시 사용자가 명시적으로 보호한 진행 중 다운로드는 건드리지 않는다.
- 전략 백테스트 결과는 실거래 진입 근거가 아니다. 데이터 범위, 수수료, 슬리피지, 생존자 편향을 표시한다.

## 8. 작업 방식에 대한 사용자 피드백

반복적으로 확인된 요구다.

- 요청 범위를 넘는 구조 변경을 임의로 넣지 않는다.
- 작업 지시가 불명확하지 않은 이상 되묻지 말고 구현·검증한다.
- 변경은 빌드와 실제 실행 경로로 검증한 뒤 보고한다.
- 작업 결과는 한국어로 짧게, 결론부터 보고한다.
- 에이전트와 결과물이 사용자를 위한 문서인지 내부 작업 로그인지 분리한다.
- 자동 커밋·푸시는 Claude Code 기록에서 사용자가 허용했다. 현재 Codex 작업에서 외부 Git 변경은 별도 요청으로 취급한다.

## 9. 현재 인수인계 상태

이 문서는 과거 Claude Code 맥락을 현재 프로젝트에 가져오는 기준점이다. 과거 세션 전체를 원본 경로에 보존했고, 구현에 필요한 요구사항·결정·보안 제약·미완료 작업을 이 문서에 정리했다.

다음 변경 작업은 이 문서를 읽은 뒤 현재 소스와 차이를 확인하는 단계부터 시작한다.
